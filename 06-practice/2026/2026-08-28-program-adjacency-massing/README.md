## DESIGN QUESTION / INPUTS / CONSTRAINTS

Synthetic object: makerspace.

Question:
Can the plan/massing preserve these program relations even when room names and facade styling are removed?

Exercise inputs:
- Workshop = high-noise/dust zone;
- Loading should directly serve Workshop;
- Quiet Room should be separated from Workshop;
- Public Entry should first reach Shared Commons.

Adverse condition:
- delivery and public arrival occur at the same time while Workshop is operating at a high-noise condition.

Constraints:
- NTS;
- no area schedule;
- no acoustic rating;
- no egress/accessibility/code;
- no structure/cost/site authority.

These are `EXERCISE ASSUMPTIONS`, not universal room-planning rules.

## E-I-A-D

**EVIDENCE / EXERCISE PROGRAM INPUT**  
Workshop and Loading require a direct service relationship; Quiet/Public require a different relation; Commons is the shared connection.

**INFERENCE**  
A single formal shell subdivided only after form commitment can hide conflicting adjacency and crossing-flow relationships.

**ASSUMPTION / ATTACK**  
Delivery and public arrival can overlap in time; Workshop noise is active.

**DESIGN CONSEQUENCE**  
Separate noisy/service and quiet/public massing; keep Commons as a bounded hinge rather than making all programs share the same circulation carrier.

### A / REJECT — Sculptural Monolith
A continuous shell is committed first, then subdivided evenly. Public/delivery paths cross and Quiet is directly adjacent to Workshop.

### B / KEEP candidate — Two Bars + Commons Hinge
- noisy/service bar;
- quiet/public bar;
- bounded Commons hinge;
- Loading enters Workshop directly;
- public movement reaches Commons/Quiet without crossing loading.

### C / REVISE — Courtyard Ring
The courtyard produces a strong shared center, but service and public circulation both depend on the common ring. It becomes viable only if service circulation is independently separated.

## A/B / ATTACKS

1. `FACADE-OFF`
   Remove facade/form styling.
   - A loses its main justification.
   - B/C still expose their adjacency/circulation logic.

2. `LABEL-OFF`
   Remove room names.
   - B must still read as separated bars with a controlled hinge.
   - if every zone becomes interchangeable, program logic is not embodied.

3. `DELIVERY + PUBLIC ADVERSE`
   Test simultaneous service/public movement.
   - A/C create shared conflict carriers.
   - B keeps loading on the service edge.

4. `NOISE ATTACK`
   Workshop active/high-noise.
   - A leaves Quiet against Workshop.
   - B includes massing separation/buffer logic.
   - no acoustic rating is claimed.

5. `PROGRAM-RELATION DELETION`
   Remove the Workshop↔Loading direct requirement.
   - B's service edge is no longer mandatory and should be reconsidered.
   - this confirms the massing consequence is tied to the program relation rather than a stylistic preference.

6. `GRAY50`
   Option differences remain visible without color.
