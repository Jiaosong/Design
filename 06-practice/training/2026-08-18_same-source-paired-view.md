# 2026-08-18｜Story & Board Training｜Same-source Paired View

## Training question
How should an evidence-led story present `Landscape First → Relation Reveal` without replacing the project object with an abstract explanatory proxy?

## Project trigger
C04 W06 was previously `REJECT MAIN / REVISE_ASSET_BIND`: the layout could carry the narrative, but abstract proxies were being used where the main visual needed a real project/spatial asset. The training therefore targets asset-binding truth, not another generic hierarchy exercise.

## Reused existing capability
- `oleander-story-and-board`: existing mature-design/evidence-first rule, spatial authority preservation, one-primary-claim/visual.
- OLEANDER Artifact Review: compliance gate and professional design gate kept separate.
- Recent training on hierarchy, attention-state, pattern network, typography and decision-priority was treated as prior art and not repeated.

## Practice artifact
Editable vector: `06-practice/training/assets/2026-08-18_R06_landscape-first_relation-reveal.svg`.

The two frames use identical base vector geometry. Frame B only adds bounded reveal overlays. The artifact is explicitly NTS / provisional and is a training relation study, not a field-validated C04 drawing or final render.

## Design Crit
**Compliance / engineering closure:** KEEP FOR TRAINING.
- Base geometry is identical in both frames.
- Reveal layer is presentation-only.
- Does-not-prove boundary is explicit.
- No field dimensions, constructability or final geometry are claimed.

**Professional design gate:** KEEP FOR TRAINING / NOT MAIN C04 ASSET.
- First visual threshold: valley + river + crossing remain readable after labels are removed.
- Composition: paired panels are balanced and read left-to-right without dashboard dominance.
- Proportion: landscape occupies enough panel area to remain primary; title hierarchy does not overtake the object.
- Typography: clear three-level hierarchy; annotation type remains subordinate.
- Spatial truth: same geometry is preserved across the pair; no redraw occurs to make the reveal easier.
- Node readability: R06 reveal is localized and does not cover the whole field.
- Narrative: second frame adds one meaningful relation rather than re-explaining the whole scene.
- Professional finish: sufficient for method training; schematic geometry is intentionally not promoted as a project hero.

## Failure knowledge
- **Failure:** an abstract proxy can look compositionally clean while failing as a main project visual.
- **Failure:** a reveal frame can silently redraw the base object and create false continuity.
- **Failure:** labels can make an unreadable base image appear informative; removing labels exposes the weakness.
- **Invalid method:** adding more callouts to compensate for a weak first visual.
- **Correction:** bind the authoritative object first; reveal only a bounded relation; compare paired frames side by side.

## Skill delta
Modified existing `oleander-story-and-board`; no new Skill created.

Added a **Same-source paired-view gate**:
1. paired views derive from the same authoritative source/geometry;
2. first view must remain project-readable without explanatory labels;
3. second view reveals only decision-changing relations;
4. record `BASE_SOURCE / BASE_VERSION / PRESENTATION_ONLY_CHANGES / REVEAL_LAYER / DOES_NOT_PROVE`;
5. placeholders cannot receive `MAIN / KEEP` before authoritative binding and re-review;
6. paired-view QA now includes side-by-side geometry identity check.

Reason: the old Skill protected geometry in general, but did not explicitly prevent a story sequence from using two different geometries or promoting a placeholder/proxy as the first half of a reveal pair.

## Cross-project transfer
Applicable to:
- C04 landscape/node storytelling, route diagrams, section before/after or relation reveals;
- XJ01 product/CMF comparisons where the same product geometry must persist across material or configuration reveals;
- Baojiajie retail/packaging pages where locked logo/person/product assets must stay identical across explanation states;
- UI/web onboarding, overview→highlight, normal→degraded state comparisons when the underlying screen/object is intended to be the same.

Not sufficient for:
- genuinely different design alternatives;
- before/after conditions where geometry actually changes;
- measured technical drawings requiring field/CAD authority;
- renders whose camera/source geometry has not been verified.

## Promotion boundary
This training proves the paired-view presentation rule can be executed on a controlled vector study. It does not prove C04 field geometry, R06 dimensions, constructability, or that any current project render is MAIN-ready.
