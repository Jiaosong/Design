## New Decision Question

**Can the v0.12 relationship-driven freeform-surface method transfer to a materially different non-automotive freeform product domain without changing the core Relationship/Fairness Contract, while preserving editable Surface Source Authority, stable Machine QA, and repeatable Human Visual / Project judgment?**

## Why this is the correct re-entry question

The v0.12 Automotive E3 R3.3 result already establishes a valid in-domain application benchmark. The unresolved capability question is now transfer/generalization, not additional automotive styling refinement.

Therefore v0.13 changes the evidence domain while retaining the validated system principles.

## Retained from v0.12 Canonical Authority

These are inherited as locked method constraints, not reopened by default:

1. `Design Geometry Layer → Surface Construction Layer → Execution Mesh Layer`.
2. Relationship Graph is first-class evidence.
3. Primary Curves / low-frequency source structures precede dense execution topology.
4. Surface Source Authority remains editable and distinct from derived mesh.
5. Position PASS is not fairness PASS.
6. Smooth shading is not G1/G2 evidence.
7. Local patch repair cannot silently override an upstream relationship defect.
8. Machine / Visual / Project QA remain separate decisions.
9. Historical failed states remain immutable audit evidence.
10. PAP / Promotion boundaries remain human-owned.

## Materially different second-domain benchmark

Initial benchmark class: `NON-AUTOMOTIVE FREEFORM PRODUCT SHELL`.

The benchmark must not reproduce an automotive longitudinal body grammar. It should require at minimum:

- one dominant ergonomic or functional volume;
- one asymmetric or directionally biased freeform relation;
- at least one controlled opening / interface / inset relationship;
- at least one hard-to-soft transition;
- at least one termination not equivalent to front/rear vehicle closure;
- an explicit surface hierarchy with primary / secondary / detail separation;
- a sparse editable source structure capable of relationship revision without mesh-local sculpting.

This is a benchmark geometry grammar, not a production product or engineering claim.

## Candidate Entry Contract

v0.13 may move from `EXPLORE / WORKING_SOURCE` to `CANDIDATE` only when all of the following are true:

1. second-domain benchmark contract is explicit and machine-readable;
2. v0.12 core Relationship/Fairness Contract is retained or every deliberate change is separately justified;
3. source structures remain sparse and editable;
4. Machine QA = PASS under unchanged or stricter declared thresholds;
5. Human Visual QA = PASS;
6. Human Project QA = PASS;
7. relation edits can be traced to design-intent / relationship hypotheses rather than opaque mesh tuning;
8. at least one controlled revision demonstrates that a relationship error can be corrected upstream without topology-local patch debt;
9. authority/source identity is explicit;
10. no Canonical / Release / engineering / production claims are introduced by Candidate entry.
