## Current evidence｜2026-09-07

### C04 Web PR #465｜semantic source carrier failure

Real browser readback reached desktop/mobile target sizes and proved several runtime/layout behaviors while still failing because two claim-bearing image carriers depended on unstable Google Drive thumbnail delivery.

Observed separation:
- page structure / responsive layout / interaction state could execute;
- the browser could still fail the project because required semantic/source assets did not load;
- changing one remote URL for another remote URL does not solve delivery authority or browser stability by itself.

Bounded learning:

`SOURCE AUTHORITY ≠ DELIVERY CARRIER`

For claim-bearing source assets:
1. keep the source/master identity and provenance unchanged;
2. materialize or otherwise obtain controlled bytes when project authority allows;
3. preserve hash / derivative identity / crop role;
4. bind a browser-stable repo/deployment-controlled derivative;
5. test the actual target viewports/states in the real browser;
6. if the carrier fails, classify `ASSET DELIVERY FAIL` locally rather than calling the whole Web design invalid.

Preferred sequence:

`SOURCE AUTHORITY → EXACT BYTES / DERIVATIVE IDENTITY → CONTROLLED DELIVERY CARRIER → HTML/CSS/JS BINDING → REAL BROWSER → VIEWPORT / STATE READBACK`

Do not use:

`REMOTE THUMBNAIL FAIL → SWAP TO ANOTHER OPAQUE REMOTE URL → ASSUME FIXED`.

## Anti-pollution usage finding

The same PR also exposed that adding many files with `CURRENT/current` in their names without a valid Current identity creates governance failure even when the page itself renders.

Bounded rule:
- decide `Native Master / Current Derivative / Support / Evidence / Provenance / Temporary` role before using `CURRENT/current` naming;
- browser integration must not manufacture parallel Current identities merely because a file is locally convenient;
- Anti-Pollution PASS is separate from browser/render PASS and separate from Design KEEP.
