# OLEANDER Editorial Publication System Extension

Status: `CANDIDATE EXTENSION / STORY-AND-BOARD`

Use when a report, book, catalog, journal, zine, manual or other multi-page publication needs a coherent reading system across the full sequence rather than a set of independently styled pages. This is not a universal grid canon and does not replace typography, image art direction or print-production validation.

## Core contract

`CONTENT INVENTORY → PUBLICATION PURPOSE / READING CONTEXT → FLAT PLAN → PAGE / SPREAD ROLES → MASTER / GRID OPTIONS → TYPE / IMAGE / CAPTION / FOLIO SYSTEM → PACING → BINDING / TRIM / PRODUCTION CONDITIONS → FULL-SEQUENCE READBACK`.

The publication is a temporal reading system. A strong single spread does not prove the whole book works.

## Content-inventory gate

Before layout, inventory:
- section/chapter structure;
- text volume and hierarchy;
- image/evidence count, aspect and quality;
- captions/credits/source notes;
- tables/figures/sidebars/pull quotes or other recurring objects;
- cover/spine/back matter/TOC/index/appendix requirements;
- page-count/binding/print/digital constraints if known.

Do not invent filler spreads or duplicate imagery merely to make the flat plan look rhythmic.

## Flat-plan gate

Build a page-by-page or spread-by-spread map before high-fidelity styling. Record:
- page/spread role;
- primary claim/content object;
- expected density;
- image/text balance;
- continuity to previous/next spread;
- section transitions;
- production-critical special pages/inserts/folds when relevant.

The flat plan is a planning artifact. It may change after real content fit/readback, but changes should be traceable rather than accidental pagination drift.

## Page-role system

Define a limited family of roles such as:
- cover / front matter;
- section/chapter opener;
- primary narrative spread;
- image-led spread;
- evidence/data spread;
- technical/detail spread;
- transition/breather;
- appendix/reference/index.

Roles are project-specific. Do not force every publication to use the same set or the same density pattern.

## Grid / master gate

Use grids and masters as coordination systems, not aesthetic commandments.

For each recurring role, establish enough shared structure to control:
- alignment anchors;
- text measure and column behavior;
- image/caption/credit relation;
- folio/running head/section marker;
- repeated data/table/figure placement;
- safe adaptation for unusually long titles, bilingual text or exceptional imagery.

Test more than one grid/master logic when the content materially permits different readings. Breaking a grid can be valid when the break has a clear narrative/evidence role and does not create accidental inconsistency.

## Spread and single-page truth

Bound publications often produce spread relationships, but not every page is consumed as a fully open spread and not every publication is bound the same way. Review both:
- spread-level balance/sequence where the binding supports it;
- single-page integrity, especially for digital PDF, loose sheets, mobile extraction, right/left page starts, or partially opened bindings.

`SPREAD DESIGN ≠ LICENSE TO MAKE EACH PAGE DEPENDENT ON ITS NEIGHBOR`.

## Pacing and sequence

Review the publication as a sequence:
- dense → open transitions;
- image-led vs text-led cadence;
- repeated visual motifs/anchors;
- section entry/exit clarity;
- cumulative evidence load;
- whether page turns reveal, compare, pause or conclude intentionally.

Do not impose a fixed “no N dense spreads in a row” rule. Pacing is content- and purpose-dependent.

## Caption / folio / credit system

Treat captions, source notes, folios and running heads as operational navigation/evidence layers, not decoration.

Check:
- stable placement logic with allowed exceptions;
- clear image/figure ownership;
- source/credit proximity when required;
- hierarchy that remains visible but does not compete with primary content;
- continuity across bilingual or multi-script contexts;
- reference/index behavior when the publication is used non-linearly.

## Binding / trim / production awareness

Before final lock, record the actual or unresolved production conditions:
- trim/orientation;
- binding method;
- inside/outside page relation and crossover risk;
- creep/gutter/hinge behavior when applicable;
- bleed/slug/marks only according to current printer/process requirements;
- paper/ink/finishing constraints when they affect image, color, fold or page handling.

Do not import a universal bleed, gutter, margin or resolution value. Production values belong to the current printer/process authority and `PRINT_PRODUCTION_PREFLIGHT_EXTENSION.md`.

## Full-sequence readback

Inspect at minimum:
- cover → first content transition;
- representative dense spread;
- representative image-led spread;
- section transition;
- technical/data page if present;
- appendix/reference behavior;
- ending/back matter;
- thumbnail/contact-sheet view of the whole sequence;
- normal reading scale and detail scale.

Attack the system with longest titles, low/high image density, short/long captions and section-start edge cases. One polished hero spread cannot grant publication PASS.

## Cross-owner routing

- typography/script/longest-string behavior → `oleander-visual-design/TYPOGRAPHY_SYSTEM_EXTENSION.md`;
- image sequence/crop/source truth → `oleander-image-art-direction`;
- data tables/figures → `oleander-data-viz` and `DATA_TABLE_INFORMATION_DESIGN_EXTENSION.md` when applicable;
- final visual hierarchy → `oleander-visual-design`;
- print/PDF/X/preflight/proof → `oleander-delivery-qc/PRINT_PRODUCTION_PREFLIGHT_EXTENSION.md`;
- live presentation/deck logic → existing story-and-board presentation extensions rather than this publication route.

## Rejected external defaults

Do **not** promote as universal OLEANDER rules:
- every layout must use a visible/strict grid;
- margins can never be equal;
- one classical proportion/canon as preferred truth;
- fixed character-per-line range;
- fixed bleed or DPI;
- every publication must be designed only as spreads;
- Swiss/asymmetric composition as house style;
- fixed pacing formulas or density scores.

## Required output

Return content inventory, publication purpose/context, flat plan, page-role system, grid/master options, type/image/caption/folio rules, sequence/pacing rationale, production-condition ledger, full-sequence readback, repair log and unresolved content/rights/print holds.
