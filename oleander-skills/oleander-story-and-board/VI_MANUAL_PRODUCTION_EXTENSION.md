# OLEANDER VI Manual Production Extension

Status: CANDIDATE EXTENSION / EXISTING SKILL ONLY / NO NEW BRAND-IDENTITY OWNER

This extension adds executable **VI / Brand Identity Manual production** capability to `oleander-story-and-board` without changing the current authority model: Brand Identity remains a Notion knowledge METHOD and has no dedicated GitHub execution owner. `oleander-story-and-board` owns only the **presentation/manual composition layer** and must route specialist work to the Current Visual Communication, Color, Image Processing and Technical Drawing methods/tools.

## 1. Routing

Use this extension when the requested output is a visual identity manual, basic identity system, brand guideline, VI handbook, logo standards page, color/type system page, brand application guideline, or a Web chapter that must **visibly present** VI rules.

Resolve in this order:

`CURRENT BRAND IDENTITY METHOD → VISUAL COMMUNICATION CURRENT → COLOR CURRENT → T-VISUAL-IMAGE-OPS-001 when texture/image processing is needed → TECHNICAL DRAWING CURRENT when geometry/dimensions/construction are shown → PROJECT DESIGN DNA → VI MANUAL PRODUCTION → ACTUAL READBACK → ARTIFACT REVIEW`

Do not create a new brand-identity Skill merely because the native object has `NO_DEDICATED_OWNER`.

## 2. Core production rule: REPRESENT THE RULE

**Text describing a VI rule is not the same as showing the VI rule.**

For every rule that will be used by another designer, developer, fabricator or operator, the manual must include an actual visual specimen, drawing, matrix or measured example at the point where the rule is introduced.

Mandatory test:

`RULE EXISTS IN PROSE → RULE IS DRAWN / SHOWN → CONCRETE VALUE IS VISIBLE ON THE FIGURE → INVALID OR LIMIT CONDITION IS SHOWN WHEN RELEVANT → CAPTION EXPLAINS WHY`

A page that says “minimum size 120 px” in a paragraph but shows no 120 px specimen, dimension line, threshold or failure sample is **INCOMPLETE**.

A page that says “1X clearspace” but does not draw the 1X boundary, dimension arrows and exclusion area is **INCOMPLETE**.

A page that lists colors but does not show actual swatches / tonal relationships / role use is **INCOMPLETE**.

A page that names type families but does not show actual uppercase, lowercase, numerals, punctuation, CJK characters, weights and hierarchy is **INCOMPLETE**.

## 3. Required VI Manual modules

Do not treat the list below as a universal branding formula; include the modules that the current identity system actually owns. When they are relevant, they must be visually represented.

### A. Brand foundation
- Name / claim / actor / offer / architecture.
- Core verbal assets and bilingual hierarchy.
- Brand boundary: what the identity is / is not.
- Relationship between operator/master brand and experience/sub-brand when applicable.

### B. Mark / wordmark system
- Approved master family: Primary / Stacked / Wordmark / Mark-only / Reverse / Optical variant as applicable.
- Flat Geometry Authority versus Material / Display variants.
- Black master and reverse master.
- Construction logic / anatomy.
- Standard grid / coordinate construction.
- Clearspace / influence zone.
- Minimum size and optical decay.
- Background matrix.
- Greyscale / contrast attack.
- Co-brand / endorsement boundary when authority exists.
- Misuse examples using the real current logo, not generic placeholder icons.

### C. Color system
- Primary / support / accent / operational state colors as separate roles.
- Actual swatches.
- HEX / RGB for digital; CMYK or print values only when scope and color-management assumptions are declared.
- Spot/Pantone only when a real target and proof path exist; never invent a nearest Pantone as approved truth.
- Tonal scale when the system needs one.
- Text/background contrast matrix.
- Gradient / tonal modulation only when part of the identity grammar.
- Light / Dark translation.
- Digital / video / print / CMF translation boundary.

### D. Typography system
- Actual primary/fallback families and runtime availability.
- Weights that really exist in the runtime or licensed package.
- Uppercase / lowercase / numerals / punctuation / currency / technical symbols.
- Required Chinese characters or other language scripts.
- Case rules, tracking, leading and line measure.
- Bilingual hierarchy.
- Type scale for actual target media.
- Wordmark type must be separated from running text if the logo is outlined/customized.

### E. Graphic / image / material grammar
- Stable graphic relations, not just decorative motifs.
- Image crop / tonal / wash / mask behavior where applicable.
- Material / texture / grain layers follow `T-VISUAL-IMAGE-OPS-001` with effect-off baseline.
- Raster display effects never replace authoritative vector/text/geometry.

### F. Application and governance
- Real touchpoint specimens, not empty mockup placeholders.
- What remains stable versus what adapts.
- Version / owner / exception / legacy boundary.
- Production proof requirements.
- Rights/source note where applicable.

## 4. Technical Drawing subroutine for VI

When a VI page contains construction, dimensions, spacing, safe area, optical limits or production geometry, use Technical Drawing logic rather than ordinary infographic styling.

The figure itself must contain, as applicable:

- authoritative object geometry;
- reference datum / origin / baseline;
- dimension lines with arrowheads or clear terminal marks;
- extension lines;
- visible value and unit;
- `X` module only if it is derived from the actual object and needed;
- safe-area / exclusion boundary;
- maximum influence / no-object zone when relevant;
- minimum / recommended / maximum values clearly differentiated;
- pass and fail specimens around a threshold;
- `CURRENT RECOMMENDATION / PROOF HOLD` label for unverified physical thresholds;
- no invented dimensions merely to make the drawing look complete.

### Minimum-size representation gate

Do not write only “minimum 120 px”. Show the specific threshold with actual rendered variants, for example:

`Primary ≥ 120 px → Compact ≥ 88 px → Mark 48–95 px → Micro 24–32 px → Favicon 16 / 32 / 48 px`

The values above are an **example of representation syntax**, not universal OLEANDER defaults. Project values must come from the current identity asset and actual readback.

At least one below-threshold / failure specimen must be shown when the limit is intended to prevent misuse.

### Clearspace / influence representation gate

A clearspace figure is not complete unless the viewer can see:

`LOGO BOUNDS + CLEARSPACE BOUNDS + FOUR-SIDE DIMENSIONS + EXCLUSION / NO-OBJECT AREA + BASELINE / DATUM IF RELEVANT`

The manual must visually distinguish the logo's geometry bounds from the larger influence/safe-area bounds.

## 5. Traditional VI completeness, without style cloning

A reference VI manual may be used to audit **information completeness**—for example whether it visibly includes grid construction, black/reverse, minimum size, typography specimens, color swatches, greyscale, special applications and extended palettes.

Do not copy the reference brand's logo, palette, type, page chrome, Pantone values or stylistic trade dress. Extract the documentation function and rebuild it in the current project's own identity grammar.

`REFERENCE COMPLETENESS ≠ REFERENCE STYLE`

## 6. Visual quality rules

- The manual is a design artifact, not a compliance spreadsheet.
- One page/surface should have one dominant VI object or rule.
- Standard drawings must be large enough to read dimensions at the target viewport/print size.
- Do not shrink multiple required specs into decorative mini-panels merely to claim coverage.
- Use explanatory prose as support; prose must not substitute the drawing/specimen.
- Reuse the project's approved visual DNA for paper, color, typography, image treatment and spacing.
- A Total Web carrier may own chapter sequencing and navigation, but the Brand/VI system should remain the upstream visual reference when the project defines it that way.

## 7. Readback and attack tests

Required before declaring a VI manual module complete:

- actual desktop/print-scale readback;
- mobile/responsive readback when Web is a target;
- near-read crop for construction/dimension pages;
- FLAT / EFFECT-OFF for material identity;
- GRAYSCALE / MONO where logo/color resilience matters;
- TARGET_SIZE / BELOW_MINIMUM for minimum-size claims;
- light/dark background matrix for logo versions;
- compare prose against the figure: every stated threshold must be visible in the figure itself.

## 8. Artifact Review split

Run separate gates:

- **Evidence Gate**: source authority, rights, truth state, production facts, physical proof status.
- **2D Drawing Gate**: dimensions, line hierarchy, annotation collision, geometry preservation, units, exclusion zones.
- **Visual Communication Gate**: first visual, composition, scale, type hierarchy, whitespace, information rhythm, professional finish.
- **Production Gate**: editable masters, outlined logo assets, export integrity, file naming, hashes, reconstruction.

`Artifact existence ≠ Design quality.`
`Traceability ≠ Professional finish.`
`Text rule ≠ Visual specification.`

## 9. Failure triggers

REVISE / REJECT when any of the following occurs:

- VI rules exist only in explanatory text;
- dimensions are described but absent from the drawing;
- clearspace has no drawn influence/exclusion boundary;
- minimum size has no concrete threshold specimen;
- thresholds are shown without units;
- invalid examples are not shown where misuse is likely;
- a grid is decorative and not tied to current geometry;
- material/raster preview becomes geometry authority;
- color values are copied from a reference brand;
- Pantone/spot values are presented as approved without proof;
- runtime font weights are invented or unavailable;
- the manual becomes a different visual system from the brand it is documenting;
- engineering/export success is used to self-award Design PASS.

## 10. Required output contract

For a complete VI production task, return or persist:

- editable/source manual pages or Web fragments;
- authoritative logo/vector masters and optical variants used;
- standard drawing assets;
- color tokens and swatch assets;
- typography specimens and runtime metadata;
- application specimens;
- production/physical-proof OPEN items;
- versioned manifest and hashes for exported/native files;
- actual pixel readbacks;
- Artifact Review result with independent Design Quality verdict separate from execution evidence.
