## Material gaps found

### 1. Requirement coverage before implementation
A web artifact can look complete while silently omitting one requested asset, interaction or state. Existing OLEANDER handoff records are strong, but web work benefits from a compact requirement-to-evidence matrix before implementation.

Independent rule:
`REQUEST / SOURCE → TARGET REGION OR COMPONENT → REQUIRED STATE / BEHAVIOR → ACCEPTANCE EVIDENCE → STATUS`.

### 2. Asset-role pass before information architecture lock
Images and video should not be inserted after the page structure is already fixed. First classify source assets by role, resolution/usability, truth authority, crop tolerance and intended reading distance; then lock IA and layout density around the assets that actually carry proof.

Independent rule:
`SOURCE ASSET INVENTORY → ROLE / AUTHORITY / USABILITY → NARRATIVE DUTY → IA / LAYOUT`.

### 3. Reference decomposition before adaptation
“Reference-first” is too weak if it means copying colors or superficial styling. Before adaptation, record the source reference's structural grammar: section rhythm, dominant grid/alignment, typography roles, density, media behavior, image crop/scale, interaction states, motion ownership and continuity devices. After implementation, compare rendered output and name visible deltas.

Independent rule:
`REFERENCE → STRUCTURAL DECOMPOSITION → PROJECT-SPECIFIC TRANSLATION → RENDERED DELTA REVIEW`.

### 4. Low-content strategy
Sparse source content must not be padded with empty cards, fake metrics, icon walls or testimonials. Reduce module count; strengthen one real image/case/proof; use editorial whitespace, asymmetry and a clear next action.

Independent rule:
`LOW CONTENT ≠ FILLER; LOW CONTENT → FEWER STRONGER PROOF OBJECTS`.

### 5. Continuous page grammar
A long responsive page should read as one authored spatial/visual system rather than unrelated blocks stacked vertically. Continuity can come from recurring type/spacing grammar, shared background/material field, overlap, sticky media, crop rhythm, section bridges or repeated alignment anchors. Hard seams are allowed only when semantically intentional.

### 6. One dominant motion system
For a given page/story, choose one primary temporal grammar and use other motion only as supporting state feedback. Multiple unrelated hover/particle/glow/parallax systems create hierarchy noise and should fail review unless each has a distinct information role.

Independent rule:
`ONE PRIMARY TEMPORAL GRAMMAR + MINIMAL SUPPORTING FEEDBACK`.

### 7. Measurement is risk evidence, not aesthetic judgment
Browser geometry, overflow checks, computed styles, screenshots and automated measurements can prove execution facts and flag composition risks. They cannot automatically grant Design KEEP. Full-size rendered review remains separate.

### 8. Stable semantic editing/state identity
For editable HTML or dynamic interfaces, persist content/state by semantic IDs rather than DOM order. Reordering or deleting modules must not cause saved content or state to attach to the wrong object.
