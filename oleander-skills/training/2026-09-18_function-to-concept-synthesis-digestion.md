# Accepted mechanisms

## 1. Solution-neutral local design functions

Prefer:
`ALLOW CONTROLLED ROTATION`

not:
`HINGE`.

Function statements should avoid locking the first familiar embodiment.

## 2. Function dependency before morphological combination

Key rule:

`NUMBER OF FUNCTION ROWS ≠ NUMBER OF INDEPENDENT DESIGN DIMENSIONS`.

Relations may include:
- PRECEDES;
- ENABLES;
- CONSTRAINS;
- COUPLED;
- SHARES_MEANS;
- CONFLICTS;
- REDUNDANT_WITH;
- FAILURE_PROPAGATES_TO.

## 3. Principle / means pool

Store causal principles before brand/product/component examples.

## 4. Compatibility state

Each material means relation may be:
- COMPATIBLE;
- CONDITIONAL;
- INCOMPATIBLE;
- UNKNOWN.

Unknown never silently becomes compatible.

## 5. Coupled bundles

When attachment, load transfer and release/service are mutually dependent, treat them as one architecture block rather than independent rows.

## 6. Shared-means consequences

One means can satisfy several functions but may increase coupling/common-mode failure.

Part count reduction is not an automatic quality gain.

## 7. Contradiction ledger

Record:
`IMPROVE A → DAMAGES B → WHY → POSSIBLE PRINCIPLE MOVES → EVIDENCE NEEDED`.

No mandatory TRIZ catalog was imported.

## 8. Concept architecture

A coherent candidate requires:
- essential-function coverage;
- causal mechanism;
- function→means trace;
- interfaces;
- states/configurations;
- unresolved compatibility;
- trade-off;
- falsifier;
- specialist handoff.

A filled morphological table is not a concept.

## 9. Concept-family deduplication

Distinct family requires a meaningful difference in:
- causal mechanism;
- function allocation;
- topology;
- interface structure;
- support strategy;
- state model.

Material/color/fastener/small-dimension variation does not establish a new family.

## 10. Matched embodiment

Retained concept families must be compared at equivalent decision-relevant fidelity.

This prevents polished Current artifacts from defeating rough alternatives by presentation quality rather than architecture.

## 11. Selection firewall

The synthesis method generates and structures candidates.

Selection remains:
`HARD GATES → PARETO / DECISION CORRIDOR → UNCERTAINTY / SENSITIVITY → DISCRIMINATING TEST → HUMAN DESIGN JUDGMENT`.

- COMPATIBLE;
- CONDITIONAL;
- INCOMPATIBLE;
- UNKNOWN.

Examples:
- host-rail sleeve + independent floor support = incompatible support architectures;
- compliant band + rigid clamp = unknown until contact/deflection + structural attachment evidence exists.
