# OLEANDER Bio–Math Streamlined Form Extension

Status: **CANDIDATE EXTENSION / DESIGN-PROCESS OWNER / NO SILENT PROMOTION**

Canonical Notion owner: `KN-THEORY-BIO-MATH-STREAMLINED-FORM-001｜Bio–Mathematical Streamlined Form｜流线型—生物形态—数学生成`.

This extension is used when a design task materially involves streamlined/aerodynamic/hydrodynamic form, biomimicry/biomorphic visual language, biological growth or branching, topology, fields/PDEs, topology or shape optimization, minimal surfaces, Voronoi/Delaunay/skeleton systems, symmetry, allometry, or mathematical form generation.

It does not create a second biomimicry method, 3D modeling method, visual-design system, CFD authority, structural authority, or mathematics authority. `oleander-design-process` owns the design reasoning; specialist skills own execution and validation.

## 1. Four-authority split

Before form generation, classify every material claim as one or more of:

1. **FLOW / PHYSICAL PERFORMANCE** — fluid, velocity/regime, boundary layer, pressure, separation, drag/lift, structural or other physical performance;
2. **BIOLOGICAL MECHANISM** — growth, tissue mechanics, transport, branching, reaction–diffusion, adaptation, allometry or another sourced biological strategy;
3. **MATHEMATICAL / GEOMETRIC STRUCTURE** — topology, curvature, metric, graph, field, PDE, optimization, symmetry, skeleton, parameterization, stochastic rule;
4. **VISUAL / SEMANTIC FORM** — speed, softness, tension, life-like character, skeletal hierarchy, segmentation, pattern rhythm, controlled asymmetry.

Do not borrow authority across columns.

`BIOLOGICAL LOOK ≠ BIOMIMETIC FUNCTION ≠ STREAMLINED PERFORMANCE ≠ MATHEMATICAL OPTIMUM ≠ VISUAL QUALITY`.

## 2. Mathematics selection by problem

Choose mathematics by the design question, not by sophistication:

- local surface behavior / highlight flow → differential geometry;
- connected components / holes / genus / persistent features → mathematical topology;
- branching / hierarchy / route / redundancy → graph theory;
- density / distance / velocity / stress / orientation → scalar, vector or tensor fields;
- diffusion / reaction / flow / equilibrium → PDE / dynamical system;
- energy + boundary + constraint equilibrium → variational form-finding;
- material-domain performance search → shape/topology optimization;
- nearest-site partition / neighborhood → Voronoi/Delaunay;
- centerline / thickness organization → medial-axis/skeleton family;
- repeated invariance / transformation → symmetry/group grammar;
- scale-dependent family variation → allometry/morphometrics.

Hard distinction:

`MATHEMATICAL TOPOLOGY ≠ MESH TOPOLOGY ≠ CAD B-REP TOPOLOGY ≠ TOPOLOGY OPTIMIZATION`.

## 3. Streamlined-form gate

If the claim is only visual, use `STREAMLINED VISUAL LANGUAGE` and evaluate proportion, section progression, curvature distribution, reflection flow and semantic speed/tension.

If the claim includes low drag, flow efficiency, lift, cooling or fluid behavior, require:

`FLUID + SPEED/REGIME + SCALE + ORIENTATION + BASELINE + GEOMETRY VARIABLES + SOLVER/EXPERIMENT/REFERENCE + PRESSURE/WAKE/SEPARATION + PERFORMANCE READBACK`.

A teardrop-like silhouette, G2/G3 surface or clean highlight is not performance evidence.

## 4. Biomimicry gate

Co-route to Current `KN-METHOD-BIOMIMICRY-001`:

`DEFINE → BIOLOGIZE → DISCOVER → ABSTRACT → EMULATE → EVALUATE`.

Require a biological source when making a biological mechanism claim. A fish, leaf, shell, bone, cell or skin used only as a visual reference is `BIOMORPHIC / BIO-INSPIRED VISUAL`, not automatically biomimicry.

Translate source through:

`FUNCTION → BIOLOGICAL MECHANISM → MATHEMATICAL ABSTRACTION → DESIGN VARIABLES → NEW GEOMETRY / SYSTEM → FUNCTIONAL TEST`.

## 5. Topology gate

For mathematical topology, record the invariant/question first:

- components;
- cycles/holes/handles;
- cavities;
- genus or homology feature;
- persistence across threshold/scale if relevant.

Do not use topological sameness to claim geometric, aerodynamic, structural or visual sameness.

For mesh/CAD topology, route to 3D Modeling Essence/validity evidence instead.

For topology optimization, require design domain, loads/boundary conditions, material, objective, constraints, discretization/filter/length-scale and manufacturing boundary.

## 6. Field / morphogenesis gate

For field-driven form, record:

`FIELD TYPE → SOURCE/MEANING → DOMAIN → BOUNDARY/INITIAL CONDITIONS → OPERATOR/PDE/RULE → SAMPLING → GEOMETRY MAPPING → SENSITIVITY → READBACK`.

A decorative noise/vector visualization has no physical authority.

For biological morphogenesis, distinguish:

- sourced biological mechanism;
- mathematical model of a mechanism;
- procedural visual analogue.

`REACTION–DIFFUSION LOOK ≠ PROVEN TURING MECHANISM IN THE BIOLOGICAL SOURCE`.

## 7. Network / skeleton / Voronoi gate

Distinguish:

- graph connectivity from geometric embedding;
- medial axis from straight skeleton;
- Voronoi partition from Delaunay dual graph;
- biological transport network from a visually similar branching pattern;
- structural load path from a graphic skeleton.

Use these as relation generators only after the design role is named.

## 8. Symmetry and controlled asymmetry

Record transformation grammar rather than hand-copying motifs:

`GENERATOR → TRANSFORMATION GROUP → DOMAIN → INVARIANTS → BOUNDARY → VARIATION / DEFECT POLICY`.

If symmetry is broken, state which invariant is released and which functional/semantic purpose it serves.

No rule says more symmetry is more beautiful or more biological.

## 9. Allometry / shape-space gate

For family variation, separate size and shape. Do not scale all coordinates uniformly when thickness, ergonomics, radii, detail frequency, flow regime or structure should change with scale.

If PCA/shape-space analysis is used:

- define correspondence/landmarks/descriptors;
- define alignment and size treatment;
- retain real sample identity;
- treat principal modes as observed variance directions, not design ideals.

`AVERAGE SHAPE ≠ IDEAL SHAPE` and `PCA MODE ≠ DESIGN INTENT`.

## 10. Anti-pseudoscience gate

Reject as unsupported defaults:

- golden ratio/Fibonacci as universal beauty or nature law;
- one universal Murray exponent for all branching design;
- Voronoi as proof of biological cellular mechanism;
- fractal appearance as proof of natural efficiency;
- a topology-optimized render as automatic manufacturing/engineering proof;
- a smooth organic surface as automatic aerodynamic proof.

If one of these is useful as a formal generator, label it as a chosen generator and test it against the actual design goal.

## 11. Option-space construction

Generate alternatives by changing one causal layer at a time where possible:

- section-area distribution;
- curvature distribution / curvature gradient;
- topology/connectivity;
- graph hierarchy;
- field source or boundary condition;
- optimization objective/constraint;
- symmetry grammar;
- allometric rule;
- biological mechanism abstraction;
- visual-semantic translation.

Do not compare five simultaneous changes and then claim one mathematics choice caused the improvement.

## 12. Required specialist routing

- geometry/surface/native modeling → `oleander-3d-pipeline`;
- visual-semantic language and presentation → `oleander-visual-design`;
- biomimicry method → Current `KN-METHOD-BIOMIMICRY-001`;
- CFD / structural / engineering performance → actual specialist solver/evidence owner when available;
- final claims remain within the strongest actual evidence produced.

## 13. Minimum review carriers

Depending on the claim, retain the minimum causal evidence:

- streamlined form: orthographic silhouette + longitudinal/cross sections + curvature/reflection + flow/performance carrier when claimed;
- biomimicry: biological source + mechanism abstraction diagram + design translation + test;
- topology: component/hole/cavity/genus or persistence carrier;
- network: graph + embedding + junction/thickness readback;
- field: field visualization + boundary/source + geometry mapping;
- optimization: domain/load/constraint + iteration/result + reconstructed geometry + validation;
- shape-space: source set + correspondence + modes + selected design delta.

## 14. Maturity boundary

Tutorials, papers and mathematical correctness can improve the design route but do not prove a native model, CFD result, optimized part, biological mechanism, or final visual quality.

`THEORY M5 ≠ NATIVE PRACTICE M6 ≠ SPECIALIST PERFORMANCE PASS ≠ DESIGN KEEP`.
