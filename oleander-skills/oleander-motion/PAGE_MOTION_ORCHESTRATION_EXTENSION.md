# OLEANDER Page Motion Orchestration Extension

Status: `CANDIDATE EXTENSION`

Use for long-form websites, portfolio pages, project stories and browser presentations where several possible motion mechanisms compete for attention.

## Primary rule

Choose one dominant temporal grammar for the whole surface, then allow only small supporting interactions whose roles are distinct.

`ONE PRIMARY TEMPORAL GRAMMAR + MINIMUM SUPPORTING FEEDBACK`.

Examples of a primary grammar include scroll-linked reveal, shared-element/state continuity, editorial mask reveal, or scene-to-scene presentation transition. The mechanism is not the identity; the motion role and page narrative remain primary.

## Gate

Before adding a second major motion family, state:

- what information/state relationship the primary system owns;
- what new role the second system owns;
- why the primary system cannot carry that role;
- the no-motion and reduced-motion equivalents;
- the runtime cost and attention cost.

If the new motion exists only to make another section feel “more dynamic,” remove it.

## Anti-fragmentation review

Reject or revise when:

- scroll reveal, parallax, particles, magnetic buttons, floating cards and cursor effects all operate as unrelated attention systems;
- multiple sections use unrelated easing/rhythm without a narrative reason;
- decorative motion competes with reading or evidence inspection;
- a reference-driven page loses its original motion rhythm because generic effects were added;
- the same emphasis role is repeated by several concurrent effects.

## Relationship to core Motion

This extension does not replace the canonical OLEANDER Motion method. Each animation still requires state semantics, a motion role, no-motion baseline, reduced-motion equivalent, runtime attack and review. This extension only adds page-level orchestration so individually valid motions do not collectively create hierarchy noise.

## Candidate boundary

A coherent motion system does not prove usability, preference or accessibility conformance. Runtime readback and applicable human review remain required.
