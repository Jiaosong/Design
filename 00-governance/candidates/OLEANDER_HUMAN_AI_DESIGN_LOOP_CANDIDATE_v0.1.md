# OLEANDER 综合人机设计回路｜系统级候选 v0.1

**状态：CANDIDATE / 待真实跨域执行与独立设计评议；不变更 Notion Current 或 GitHub main。**
**范围：OLEANDER 全部设计域与综合项目。C01 是空间域验证样本之一，不是总方案的依赖或推广依据。**
**权威：Notion Current System Architecture Control Map v2.1、Design Intelligence Routing & Review、Project Control Plane；可执行接点为既有 `oleander-design-process`、Design Intelligence Packet、Design Review Receipt、Execution Receipt、原生制品及 Evolution Candidate Contract。**

## 1. 这次改动的设计问题

让 OLEANDER 在不要求人预先规定所有形式、风格和执行细节的情况下，自主完成问题解释、跨机制探索、原生制作、比较、批评和修复；让人的目的、否定、选择、混合与重开真正改变后续设计；把设计者能力成长与系统方法改进分别从真实反馈中产生。人保有设计判断和授权；系统不得因流程完备、模型打分或生成数量自授 Design KEEP。

面向空间、产品、界面、服务、视觉、系统及其交叉界面；各域在真实专业语义里交付等价深度的判断、假设、对比、可编辑对象、读回和必要专业验证，无统一图面模板或强制方案数量。

## 3. 一次设计回路的人机分工

1. **共同定题**：人可只说目的、担忧或指出“都不对”；系统解析当前权威，提出竞争性问题解释及最低必要未知。要经人的明确反对或新证据重开问题时，保留旧分支、反对理由和变化范围。
2. **机器自主展开**：先选改变功能分配、空间拓扑、构造、权限或交互因果机制的方向；对同族的参数/颜色变体去重。保留现状或不新增介入、强反例和有价值的意外方向。数量由真实权衡覆盖决定。
3. **制作与自我攻击**：在同一事实母体、同等约束下为可比较方向制作足以揭露关键失败的原生对象。记录来源和可逆假设，做删减、边界条件、故障状态及同对象跨视图回读。受限证据可以支持可逆探索，但对应不可逆、专业或真实性主张仍 HOLD。
4. **有意义的人介入**：展示可操作的差异、代价、最强反证与可编辑作品；人可选、改、混、否或重开，并可只说原因。系统把原因转为本轮约束、明确的开放变量和新反例，生成下一轮；无人的新判断不得伪造 steering event。
5. **独立决定**：现有 Design Review、Artifact Review、证据/真值及触发的专业和跨域整合各自读回。确认的只是适用范围内的判断；机器校验和方案票数不决定 KEEP。
6. **双向学习**：给设计者展示选择前后的权衡、失败的原因、一个针对性的挑战或反例，观察其下一轮独立判断；支持量可随该具体能力的表现减小，再观察误判是否增加。个人成长记录与项目设计结果分别评价。系统方法的改变仅从跨案例失败、修复和反例形成有界 EV 候选。

每轮的最小可追溯关系：
`DECISION OBJECT + CONTEXT → COMPETING FRAMES → DISTINCT CAUSAL BRANCHES → NATIVE ARTIFACT IDs → ACTUAL READBACK/CRIT → HUMAN STEERING (if occurred) → CHILD BRANCH → REVIEW/DISPOSITION → REOPEN TRIGGER`。
现有 Packet、Decision Record 和 receipts 只保存各自应有的信息；这是关联索引，不新造一个覆盖它们的总 receipt。

## 4. 跨域验证矩阵与首批执行

| 场景 | 原生工作对象 | 核心差异与人机检验 | 专有底线 |
| --- | --- | --- | --- |
| 数字界面 / 私有知识 Reader | 可运行 HTML/CSS/JS 或现有工程中的真实 UI 状态与交互，文字可编辑 | 比较阅读/编辑/审查与搜索的不同信息和权限机制；用户否定或混合后跑真实浏览器第二轮 | 真实登录/权限、可访问性、状态恢复、Notion 写回不由视觉原型宣称 PASS |
| 空间 / C01 或另一真实场地 | 同源可编辑二维底图、关系图/平剖与必要可编辑三维 | 比较保留、可逆介入、独立介入等机制；看人是否重开问题 | 来源/尺度/许可/结构/现场上限逐项标注，效果图不充作测量 |
| 物理产品 / 既有产品问题 | CAD/Blender 装配、功能/接触/维修关系图或实物样机 | 比较功能分配、操作和修理架构；人的取舍进入下一版构件 | 人体工学、承载、材料和制造由实测/专业主张限定 |
| 综合项目 / 服务、空间与界面耦合 | 互相引用同一对象 ID 的原生空间、界面、服务状态与接口 | 检验一处人机判断能否驱动各相关对象一致修订并保持域内责任 | 触发已有 Cross-Disciplinary Integration；局部 PASS 不等于集成 PASS |

首轮从**界面、空间、产品各至少一个真实决策对象**选材。原有 C01 三个用例只是空间边界回归输入；增补界面、产品和跨域协同用例后，才评估总方案。顺序按现成来源和原生执行条件调度，不以 C01 P01 完成为整个系统的启动门槛。

## 5. 验证与晋升条件

- 静态 golden 用例只验证预期行为描述；必须实际调用当前模型/工具，保存输出及失败，并做原生打开或运行读回。
- 在每个域比较现有流程与候选回路：问题是否更准确、机制差异是否真实、作品是否更好、事实边界是否诚实、人类理由是否改变第二轮、是否增加无效工序；评议使用现有专业镜头及独立 reviewer，不合成单一分数。
- 对一次错误的人机交互、一次全部方向被否定、一次跨域接口冲突做反例；记录失败归因、局部修复与重测。
- 只有跨域真实结果与反例支持可迁移规则，才向现有 `oleander-design-process` 和必要的 domain adapter 提交有界变更；Evolution Candidate 依原合同评估和人工晋升。
- 未具备真实模型执行、原生读回、独立设计评议和人类真实 steering 时，PR 保持 Draft / Candidate；CI 成功仅证明机器检查通过。

## 6. GPT 插件入口与下次执行

- **安装候选**：`plugins/oleander-design/plugin.json` 是 portable 插件清单；`skills/oleander-session/SKILL.md` 只实现会话入口；`.agents/plugins/marketplace.json` 提供仓库候选市场入口。当前只在 PR #705 的分支；没有声称已在 ChatGPT 安装或发布。插件不捆绑新的 MCP 服务，不获得单独的 Notion/GitHub 权限或写权。
- **首次进入**：检查已连接 Notion、GitHub 和目标域原生工具；读取 exact Current 与真实项目状态、现有 `oleander-design-process`、上一有效 Native Artifact 与 Receipt。输出 `task_id / decision_object_id / authority fingerprint / source revision / required_native_output / owner set / checkpoint / claim ceiling / next_allowed_action` 的现有承载视图，缺项写 UNRESOLVED。
- **续跑**：按最高已验证 checkpoint 恢复，核对 GitHub main 和 Notion 修订；若来源漂移，只重开受影响的分支。远端写入结果不确定时先核对后置条件，再决定是否重试。工具缺失时限定相应副作用，其他经授权的只读或可逆设计继续。
- **实跑验收**：本分支新增 package graph validator 进 AI Governance CI，检查 manifest、市场路径、Skill 引用及核心恢复字段；安装后另用数字、空间、产品真实对象和重开/混合/否定用例跑当前模型与工具，保留原生读回、人类实际理由及独立评审。静态 CI 成功不等于已可在 ChatGPT 移动端安装，也不等于设计方法专业 PASS。
- **停止与完成**：权限/身份冲突、不可逆无授权和事实越界按既有 Owner HOLD；任务完成须现有 Execution Receipt 的 `flow_completion.completion_gate = PASS` 且适用必需阶段无未完成项，插件不得单独宣称关闭。
