# OLEANDER Existing Mature Design First Policy v1.0

Status: ACTIVE CANDIDATE FOR GOVERNANCE MERGE  
Scope: ALL OLEANDER P0–P4 / Cases / Domains / Application Mappings / Design & Research Work  
Principle family: NO COMPRESSION / NO LOSS / RESTRUCTURE WITHOUT INFORMATION LOSS

## 1. Core rule

> **原始成熟设计必须完整看；Current Authority 决定它今天还能不能用；OLEANDER 用来审查、修正和深化，而不是替代原设计。**

Existing Mature Design / Design Source and Current Authority have different responsibilities:

- **Existing Mature Design / Design Source** = design origin, continuity, design DNA, already-solved problems and prior mature outcomes.
- **Current Authority** = whether that material is valid, writable, current, superseded, conditional, blocked or reusable today.

Authority-first must never become **source-blind**. Mature old work must never bypass Current Authority simply because it looks finished.

## 2. Global default

Unless the user explicitly requests a zero-base exploration, every new phase, restarted chat, model change, workstream change, medium change, redesign or deepening task MUST begin by locating, opening and reviewing existing mature design and effective prior outcomes.

`Restart / Reframe / Redesign / Deepen` MUST NOT be interpreted as `rebuild from zero` by default.

Default priority:

`USE EXISTING → EDIT / CURRENTIZE → RESTRUCTURE → DEEPEN → ADD ONLY THE GAP → REBUILD ONLY WITH EXPLICIT REASON`

## 3. Mandatory execution order

### 3.1 EXISTING-FIRST INVENTORY
Before production, locate and open relevant existing:

- boards / presentations;
- renderings / visualizations;
- drawings / CAD / diagrams;
- models / prototypes;
- product / physical / spatial concepts;
- app / Web / interaction prototypes;
- video / motion work;
- brand / identity / CMF systems;
- research findings;
- prior review failures that materially shaped the design.

A later summary, asset register, chat recap or derived technical sheet is NOT a substitute for looking at the original design artifact where the original artifact is available.

### 3.2 DESIGN-SOURCE READBACK
Review the existing artifact for its actual design DNA:

- central judgment;
- user relation / user job;
- spatial / product logic;
- visual hierarchy;
- composition and proportion;
- material / CMF language;
- interaction logic and rhythm;
- narrative sequence;
- professional completion level;
- already-solved design problems;
- known failure modes.

### 3.3 CURRENT-AUTHORITY REREAD
Then read Current Authority / Project State / Source Authority / Current Task and classify each existing outcome as one of:

`KEEP / CURRENTIZE / COMPETE / DEMOTE TO SUPPORT / DEMOTE TO PROCESS / HOLD / CUT`

Rules:

- Old does not mean invalid.
- New does not mean better.
- Mature does not mean current.
- Derived does not replace source authority.
- A high-fidelity old artifact cannot silently regain authority if current truth conflicts with it.

### 3.4 GAP-ONLY PRODUCTION
New production is allowed only when existing work cannot satisfy the current Goal, User, Evidence, Field, Quality, Function or Medium requirement.

Default actions before net-new creation:

- edit;
- correct;
- re-layout;
- re-sequence;
- add evidence;
- repair user logic;
- repair visual hierarchy;
- deepen construction / interaction;
- redraw only the failed part;
- add only the missing chapter / state / view / component.

Do not rebuild an already-solved system merely for visual uniformity, cleaner presentation or personal preference.

### 3.5 NO-LOSS RESTRUCTURE
Reordering, splitting, adding, regrouping, reweighting and redesign are allowed.

Independently valid design content must not disappear without an explicit design reason. This includes, when relevant:

- Audience Depth;
- Physical / Sensory;
- Product;
- Spatial;
- Digital / App;
- Memory / IP;
- Technical Proof;
- Service / Return;
- Evidence / Field;
- Operations / States;
- other project-specific independent chapters.

### 3.6 WHOLE-PROJECT READBACK
During prolonged local deepening, periodically reopen the original mature whole and the current whole-project structure.

This is a mandatory protection against local optimization.

A project must not degrade from an integrated design into only:

- a technical report;
- a method-card system;
- a status dashboard;
- an engineering detail package;
- a single-object project;
- an App-only explanation;
- a visual style exercise.

### 3.7 MATERIAL DELTA RULE
Every new artifact or revision must be able to state its material delta relative to the best existing mature outcome.

If the new artifact:

- adds no real design value;
- is only an equivalent redraw;
- loses information;
- weakens the original design hierarchy;
- replaces a mature spatial/product/user relationship with generic methodology;

then verdict = `REJECT / REVERT TO EXISTING / CURRENTIZE EXISTING` as appropriate.

### 3.8 QUALITY INDEPENDENCE
Existing-first is NOT a quality exemption.

These remain globally active:

- `Artifact existence ≠ Design quality`
- `Traceability ≠ Professional finish`
- `Evidence correctness ≠ Visual excellence`
- `Process PASS ≠ MAIN KEEP`
- `Machine PASS ≠ Design PASS`
- `Executed ≠ Validated`

Existing and new outputs pass through the same independent professional design gate.

### 3.9 PROVENANCE PRESERVATION
Replaced, demoted, held or rejected mature work remains provenance.

Do not overwrite, erase or rewrite the historical artifact merely because a newer Current version exists.

### 3.10 DEFAULT QUESTION BEFORE PRODUCTION
Before creating something new, answer:

> **已有的哪一个成果已经解决了这个问题？为什么不能直接用、修、深化或重组它？**

Net-new creation is allowed only when there is a concrete answer.

## 4. Legal reasons for zero-base rebuild

A rebuild from zero is legal only when one or more of the following is true:

1. Current Authority / Truth / Evidence materially conflicts with the old design.
2. The old outcome has been fully reviewed and fairly repaired/redrawn, but still cannot meet user, experience, spatial, product, visual or professional-quality requirements.
3. Goal, medium, audience or function has fundamentally changed and reuse would create misinformation, pollution or structural contradiction.
4. The user explicitly requests a genuinely new direction or zero-base exploration.

Even then:

- preserve original Design Source / provenance;
- record `REBUILD REASON`;
- record the material `DELTA` against the best existing outcome;
- do not present the rebuild as if no prior design existed.

## 5. Illegal reasons for rebuild

The following are NOT sufficient reasons:

- new chat;
- model changed;
- agent/workstream changed;
- page is long;
- want it simpler;
- want it cleaner;
- want it more unified;
- starting from zero feels clearer;
- old file is inconvenient to find;
- easier to regenerate than to inspect;
- previous artifact is not in current context window.

If the source is not in the current context, locate it. Do not silently reinvent it.

## 6. Runtime guard

Every execution should conceptually add this preflight:

`EXISTING DESIGN LOCATED? → ORIGINAL ARTIFACT OPENED? → DESIGN DNA READ? → CURRENT AUTHORITY REREAD? → MATERIAL DELTA IDENTIFIED? → THEN PRODUCE`

If any of the first four are false and existing mature work is reasonably likely to exist, production should be held until the missing read is completed, unless the user explicitly requests immediate exploratory work with that limitation acknowledged.

## 7. Relationship to other OLEANDER rules

This policy is cumulative with:

- `NO COMPRESSION / NO LOSS / RESTRUCTURE WITHOUT INFORMATION LOSS`;
- Artifact Review / Professional Design Gate;
- Current Authority / Source Authority / Project State;
- Evidence / Field / Rights / Engineering gates;
- provenance preservation.

This policy does **not** force every project to reuse old content blindly. It forces OLEANDER to **inspect and judge existing design before replacing it**.

## 8. Intended effect

OLEANDER is a cumulative design system.

The objective is to preserve and compound design capital across projects and iterations so that each new cycle begins from the strongest valid existing work, then becomes more accurate, more useful and more professionally resolved — instead of repeatedly resetting to generic zero-base output.
