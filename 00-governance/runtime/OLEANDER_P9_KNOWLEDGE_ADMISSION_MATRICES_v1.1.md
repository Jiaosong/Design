# OLEANDER P9 Knowledge Distillation / Admission Matrices v1.1

Status: **DRAFT COMPANION / PRIORITY P9 SECOND PASS**. Semantic owner remains `OLEANDER_G9_KNOWLEDGE_DISTILLATION_ADMISSION_CONTRACT_v1.0.*` plus `OLEANDER_KNOWLEDGE_CLASSIFICATION_CONTRACT_v1.1_DRAFT.md` and the Professional Knowledge Content & Research Standard.

## 1. Purpose

P9 second pass prevents project/runtime material from being promoted into Knowledge merely because it was useful, successful, repeated or well documented.

Core invariant:

`REUSE CANDIDATE → DEPROJECT → EVIDENCE/BOUNDARY → EXISTING-OWNER RESOLUTION → CLASSIFICATION → CONTENT/RESEARCH GATES → EXPLICIT PROMOTION`.

---

## 2. G9 Candidate Admission Matrix

Create a G9 candidate only when at least one material reusable pattern exists.

| Trigger | Candidate likely useful? | Minimum proof before Knowledge admission |
|---|---:|---|
| recurring failure repaired + retested | YES | root cause + repair + regression boundary |
| method/sequence improved outcome | YES | comparison/readback + conditions |
| cross-disciplinary interface pattern recurred | YES | multiple contexts or strong mechanism + boundaries |
| one project succeeded | MAYBE | only bounded Practice/Case unless broader support exists |
| one project failed | MAYBE | bounded anti-pattern/root-cause Case/Practice |
| task completed | NO by itself | no G9 candidate |
| new citation/source found | normally NO new object | patch existing Claim/Evidence owner first |
| tool/runtime receipt created | NO by itself | runtime provenance only |
| new reusable semantic responsibility discovered | YES | existing-owner check + atomicity test |

## 3. Existing-Owner Resolution Matrix

Before creating a Knowledge identity, compare with Current full body.

| Material delta | Default action |
|---|---|
| new evidence for existing Claim | `PATCH_EVIDENCE` |
| new contradiction/boundary/failure condition | `PATCH_BOUNDARY` |
| method step refinement | `PATCH_METHOD` |
| same responsibility, duplicate page | `MERGE_REDIRECT` |
| project-specific bounded application | `ADD_CASE_OR_PRACTICE_CHILD` |
| existing object mixes independent responsibilities | `SPLIT_RECLASSIFY` |
| genuinely new independent maintainable responsibility | `CREATE_NEW_L5` by default |
| cross-object integration owner passes L4 five-gate admission | `CREATE_OR_PROMOTE_L4` only after governance review |

Hard rule: `NEW LEARNING ≠ NEW PAGE`.

## 4. De-Project Matrix

### Strip from reusable human body unless mechanism depends on it
- project/workstream IDs;
- one-off coordinates/dimensions;
- local file paths;
- PR/commit/CI/hash/sync IDs;
- runtime receipt IDs;
- temporary tool state;
- client/person-confidential facts;
- local naming with no transferable meaning.

### Preserve as provenance/context
- source project/case ID;
- configuration/baseline;
- actual evidence/test/readback conditions;
- date/version;
- producer/reviewer;
- failed alternatives/negative evidence;
- supersession/lineage.

### Keep in reusable body only if semantically necessary
- a project condition that defines applicability;
- a dimension/range that is itself the transferable rule;
- a named tool/version when behavior is version-specific;
- a regulatory/locale condition required for correct use.

De-projecting is semantic separation, not anonymized deletion of evidence.

## 5. Generalization Strength Matrix

| Evidence pattern | Maximum default reusable form |
|---|---|
| one bounded project instance | `CASE` / `PRACTICE`, or bounded Claim in existing METHOD |
| repeated same-context instances | stronger Practice; still context-bounded |
| multiple materially different contexts with same mechanism | candidate Method/transfer rule |
| controlled comparison/benchmark + mechanism | stronger Method/Decision rule candidate |
| systematic/structured external research + project validation | broader Method/Theory candidate subject to R1/R2 |
| one anecdote/user quote | local evidence/context only |
| vendor/precedent repetition | contextual support, not universal performance proof |

No object Role/Level upgrade is inferred solely from count of projects.

---

## 6. Transfer Statement Completeness Matrix

A consequential reusable rule is `CLASSIFICATION_READY` only when it can state:

`WHEN` — applicability conditions/context;

`DO / EXPECT` — reusable action/mechanism;

`BECAUSE` — evidence/reasoning;

`NOT BEYOND` — failure/transfer boundary;

`REVALIDATE WHEN` — staleness/change trigger.

Missing `NOT BEYOND` or `REVALIDATE WHEN` blocks broad Method/Theory promotion where context sensitivity is material.

## 7. Counterexample Burden Matrix

| Candidate role | Counterexample/negative-evidence burden |
|---|---|
| `SOURCE` | source limitations/coverage; no fabricated counterexample requirement |
| `EVIDENCE` | contradiction/applicability/uncertainty |
| `CASE` | negative/failed aspects of the case where relevant |
| `PRACTICE` | failure conditions + context where practice did not work |
| `TOOL` | unsupported cases/version limits/failure modes |
| `METHOD` | counterexamples/alternative mechanisms/known failure conditions expected |
| `THEORY` | contradictory evidence/competing explanations expected |
| `INDEX` | coverage/gaps rather than theory-like counterexample burden |
| `L4 FRAMEWORK` | scope-out, owner boundaries, failure of integration model, alternative structures |

## 8. Classification Admission Matrix

Classification order after `Object Plane = KNOWLEDGE`:

1. `Subject Ownership`;
2. `Knowledge Level`;
3. `Primary Knowledge Role`;
4. `Framework Type` only if L4 admission passes;
5. `Typed Knowledge Relations`;
6. `Knowledge State`;
7. `Information Role`;
8. Application Mapping/Retrieval/Lifecycle metadata.

### L4 gate remains conjunctive
`BREADTH + INTEGRATION + DELEGATION + BOUNDARY + REUSE`.

If one fails → default to appropriate L5 owner/INDEX/other role; do not compensate with importance or page length.

## 9. Human Body vs Runtime/Provenance Matrix

| Content | Human Knowledge Body | Runtime/Provenance carrier |
|---|---:|---:|
| Core Question / Purpose / Definitions | YES | optional index only |
| Claims / Mechanism / Decision logic | YES | structured mirror optional |
| Procedure / Inputs / Outputs | YES | machine schema may mirror |
| Evidence basis / contradictions / limits | YES | Claim-Evidence ledger/provenance also |
| Scope / transfer boundary / revalidation trigger | YES | lifecycle metadata also |
| PR/commit/SHA/CI run | NO | YES |
| sync timestamp / D1 readback | NO | YES |
| migration batch / receipt history | NO | YES |
| current runtime gate state | NO | YES |
| historical project configuration | summarized only when essential | YES full provenance |

A knowledge page dominated by operational logs is `RESTRUCTURE`, even if all logs are correct.

## 10. Claim Unit Admission Matrix

Consequential Knowledge Claim minimum:
`claim_id + claim_type + EN/ZH text when formal bilingual + supports + contradicts + bounds + conditions + confidence + uncertainty + does_not_establish + validation_state + last_verified + supersession`.

Claim relations:
- `SUPPORTS_CLAIM`;
- `CONTRADICTS_CLAIM`;
- `BOUNDS_CLAIM`.

Page-level citation count cannot replace this for high-consequence Claims.

## 11. Gate Applicability Matrix

| Gate | Applies when |
|---|---|
| `R1 Research Conduct` | object makes research-derived claims where conduct/method validity matters |
| `R2 Reporting` | study/research reporting profile applies |
| `K1 Content` | all substantive Knowledge bodies |
| `K2 Object` | all canonical Knowledge objects |
| `K3 Graph` | all graph-managed canonical objects |
| `K4 Metadata/Provenance/Retrieval` | all canonical/retrievable objects |
| `K5 Lifecycle/Reuse/Staleness` | all mutable/reusable objects |
| `B1 Bilingual` | formal bilingual body required |
| `IR Independent Review` | high-impact/current promotion where specified |

Reference/Index/Redirect must not fabricate research protocols simply to fill fields; mark gates genuinely N/A where semantically inapplicable.

## 12. Knowledge State Separation Matrix

Reader/runtime must never collapse these:
- taxonomy: Level / Role / Framework Type;
- authority/retrieval: CURRENT / SUPPORT / PROVENANCE / EXCLUDED;
- governance;
- content state;
- research R1;
- research R2;
- evidence;
- trust;
- freshness;
- graph/relation state;
- bilingual state;
- lifecycle/reuse.

Forbidden inferences remain:
`CURRENT→TRUSTED`, `L4→MATURE`, `VERIFIED→HIGHER_LEVEL`, `POPULAR→FRAMEWORK`.

## 13. Promotion Decision Matrix

| Condition | Allowed outcome |
|---|---|
| reusable delta fits existing Current owner | patch/merge; no new identity |
| evidence bounded but research/content incomplete | SUPPORT/CANDIDATE/HOLD |
| single case only | CASE/PRACTICE; no universal Method/Theory claim |
| L4 gate incomplete | remain L5/other role |
| material contradiction unresolved | HOLD/REVISE; no Current promotion |
| mutable evidence stale | revalidate or lower retrieval/trust |
| bilingual parity incomplete where required | B1 REVISE/HOLD |
| all applicable gates pass + authority approves + readback confirms | CURRENT eligible |

Promotion is state change, not migration batch completion.

---

## 14. Dynamic Corpus Rule

The Knowledge corpus size is a dated census only.

Completion of a remediation/migration campaign is:
`enumeration closure + per-object full-body decision + readback + unresolved-object ledger`.

Never:
`fixed total count reached = knowledge system complete`.

New objects entering the corpus extend the denominator automatically.

## 15. Validator additions for P9 v1.1

- `P9/G9-M01`: task/project success alone cannot create reusable Knowledge identity.
- `P9/OWN-M01`: existing Current owner full body must be checked before new Knowledge identity.
- `P9/OWN-M02`: learning fitting existing responsibility routes to patch/merge, not parallel object.
- `P9/DEP-M01`: de-projecting strips runtime clutter while preserving provenance/context.
- `P9/GEN-M01`: single-case evidence cannot silently grant broad Method/Theory generalization.
- `P9/TRF-M01`: consequential reusable rule records WHEN/DO-BECAUSE/NOT-BEYOND/REVALIDATE-WHEN.
- `P9/L4-M01`: L4 requires all five admission gates; no importance/length substitution.
- `P9/BODY-M01`: operational audit logs cannot dominate canonical Human Knowledge Body.
- `P9/CLM-M01`: consequential Claim requires typed support/contradict/bound evidence.
- `P9/GATE-M01`: applicable gates remain independent; genuine N/A allowed but fabricated completion forbidden.
- `P9/STATE-M01`: taxonomy/retrieval/content/research/trust/freshness/bilingual/graph states cannot be collapsed.
- `P9/CORPUS-M01`: fixed census number cannot be encoded as migration completion constant.

## 16. P9 v1.1 closure test

P9 second pass is ready for validator compilation when test cases distinguish:
- reuse candidate from Knowledge object;
- patch/merge from create-new;
- Case/Practice from broad Method/Theory;
- de-projecting from provenance deletion;
- L4 integration owner from important L5 object;
- human professional body from runtime log;
- classification state from content/research/retrieval state;
- corpus snapshot from fixed system size.
