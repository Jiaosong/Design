# OLEANDER Current Architecture Map v2.0

**Status:** ACTIVE / CURRENT ARCHITECTURE CLASSIFICATION VIEW

**Effective:** 2026-09-15

**Scope:** OLEANDER system architecture, runtime layers, canonical contracts, professional processes, state families, reviews/gates and execution owners.
**Authority position:** subordinate to `00-governance/README.md`, Current Project / Source Authority and `00-governance/complex-project-master-runtime-v1.0.md`. This map classifies the current system; it does not create a second Master Runtime, Knowledge Architecture, Project Axis, professional stage system, Gate family or state namespace.

---

## 1｜Canonical counting rule

When OLEANDER is discussed at system level, use the following count and terminology exactly:

```text
OLEANDER DESIGN OPERATING SYSTEM
= 1 CURRENT SYSTEM ARCHITECTURE

orchestrated by
= 1 COMPLEX PROJECT MASTER RUNTIME

expanded operationally as
= 11 STABLE RUNTIME LAYERS (R-A ... R-K)

containing / invoking
= multiple canonical contracts, domain processes, reviews, gates,
  state families, schemas, Skills, capabilities, tools and artifacts.
```

Therefore:

- **OLEANDER currently has one Current system architecture.**
- `R-A ... R-K` are **11 Runtime Layers**, not eleven separate architectures.
- `DD-01 ... DD-12` are shared design-development **responsibility dimensions**, not architectures and not professional stages.
- Architecture `ADD-00 ... ADD-17` are one profession's authentic **professional stages**, not Runtime Layers and not a universal OLEANDER stage system.
- `KI*`, `OE*`, `DQ*`, interface maturity, evidence codes, Job State and Project/Design State are **state families**, not architectures.
- Artifact Review, PAP, High-Fidelity Built-Environment, statutory/technical/evidence checks and Post-Generation Review are **review/gate owners**, not architectures.
- Skills, capabilities and tools are **execution owners/resources**, not professional processes and not architectures.

If a future document uses “architecture” for a local subsystem, it must qualify the term, for example `Knowledge Architecture`, `Information Architecture`, `Software Architecture` or `Project-specific Spatial Architecture`. An unqualified question such as **“OLEANDER 有几个架构？”** refers to the single Current OLEANDER system architecture defined here.

## 8｜State-family map

State systems remain orthogonal. A label in one family cannot upgrade another family.

| State family | Current vocabulary / owner | Answers |
|---|---|---|
| Corpus / Retrieval | `CURRENT / SUPPORT / PROVENANCE / EXCLUDED` | where/how a knowledge object participates in retrieval/lifecycle |
| Content Remediation | Knowledge Content Review vocabulary | whether the full body is professionally adequate for its declared role/scope |
| Knowledge Integrity | `KI0 ... KI5` | whether identity/role/authority/evidence/graph/provenance integrity is resolved at scope |
| Operational Eligibility | `OE0 ... OE3` | whether a knowledge object may drive this task/claim at this ceiling |
| Design Quality Maturity | `DQ0 ... DQ5` | how mature the actual design system is |
| Professional Process State | domain-owned | whether authentic professional work has been executed/read back |
| Interface Maturity | `IDENTIFIED / DEFINED / COORDINATED / EXERCISED / VERIFIED` | how mature a cross-domain interface is |
| Interface Disposition | `OPEN / BLOCKED / CLOSED / OUTSIDE_CLAIM` | whether interface work remains |
| Project / Design State | `EXPLORE / CANDIDATE / REVISE / REJECTED / PROMOTED / LOCKED / SUPERSEDED` | project design lifecycle state |
| Job State | `CREATED / RESOLVED / QUEUED / RUNNING / SUCCEEDED / FAILED / CANCELLED / CACHED` | machine execution state |
| Authority State | `NONE / WORKING_SOURCE / CANDIDATE_AUTHORITY / CANONICAL_AUTHORITY / FROZEN_AUTHORITY` | authority maturity of a specific object |
| Evidence State | `E0 ... E4` plus applicable source/evidence contracts | evidence/verification level within its owner domain |

Hard separations:

```text
CURRENT ≠ CLEAN

OPERATIONALLY ELIGIBLE KNOWLEDGE ≠ DQ MATURITY
DQ MATURITY ≠ PROFESSIONAL STAGE COMPLETION
```

## 12｜Canonical answer formats

### 12.1 Short answer

> OLEANDER 当前是 **1 个总系统架构**，由 **1 个 Complex Project Master Runtime** 编排，并展开为 **11 个稳定 Runtime Layers（R-A～R-K）**。专业流程、DD、状态族、Gate、Skill 和 Tool 都是这个架构内的不同对象类型，不另计为顶层架构。

### 12.2 Professional-process answer

> OLEANDER 有 **1 个共享 Professional Domain Process Contract**；各专业保留自己的真实流程语义。目前 Architecture 已正式形成 `ADD-00 ... ADD-17` 的完整 reference process。Structural / MEP / Interior / Landscape / Lighting / HCD / Systems Engineering 等按同一 envelope 接入，但不得被假定为已经拥有与 Architecture 同样成熟的正式流程定义，除非对应 Current process owner 已实际建立并通过 readback。

### 12.3 Knowledge answer

> OLEANDER 仍只有一套 Current Knowledge Architecture（L0-L7 + independent Knowledge Role / typed relations）。正文补全、Knowledge Integrity、Operational Eligibility、DQ maturity 和 Professional Stage 是独立状态/运行层，不建立复制知识树。
