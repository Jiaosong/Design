## Real bounded question

How can **Return / Service remain continuously recoverable in the digital experience without making the phone dominate the landscape**, while preserving C04's current rules that Return outranks optional content, UNKNOWN fails closed, offline is not degraded, and digital-off still leaves route / safety / return outside the app?

This trial does **not** redesign the live C04 Web frontier and does not claim HCD Professional PASS. It creates a local candidate comparison surface because the current C04 HCD process exercise remains HOLD and the live Web object has a separate owner/frontier.

## Alternatives

- **A_RETURN_RAIL** — a persistent low-emphasis Return / Service rail; fastest recovery, highest persistent chrome cost.
- **B_CONTEXT_BEACON** — a small status-aware Return beacon that opens a service drawer; least visual occupation, higher discoverability risk.
- **C_RETURN_MODE** — an explicit Explore ↔ Return mode transition that collapses optional content and makes recovery the whole interface state; strongest state clarity, highest mode-switch cost.

All three are real editable HTML/CSS/JS prototypes sharing the same source-bound content and truth boundary. They are interaction mechanisms, not style variants.
