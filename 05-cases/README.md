# OLEANDER Cases｜案例入口

[← 返回 OLEANDER 首页](../README.md)

这里是 OLEANDER 的真实案例层。  
案例不是单纯用于展示“最后结果”，而是用于观察：

- 一个复杂问题如何被定义；
- 研究、设计判断、证据与开放问题如何区分；
- AI 在长期项目中承担了什么；
- 哪些关键决定仍由人类保留；
- 产物如何经过验证、复盘和版本演进。

> **Case ≠ Demo.**  
> 每个案例都保留其真实成熟度与证据边界。

# 如何读一个 Case

每个案例尽量按同一逻辑组织：

```text
Project Frame
→ Problem / Question
→ Current State
→ Design / Product Logic
→ Human–AI Collaboration
→ Artifact / Prototype
→ Evidence / Validation
→ Open Questions
→ Next Step
```

这意味着你不应该只看最终图或文件数量。

# 状态说明

## RESEARCH
项目仍以研究、证据整理和问题定义为主。

## PROPOSAL
存在设计提案，但提案不自动等于验证完成。

## PROTOTYPED
已经存在原型；不代表真实用户测试已经发生。

## VISUALIZED
概念已经形成可视化表达；不代表样品、工程或量产成立。

## TEST PLANNED / NOT RUN
测试方案已经存在，但真实测试尚未执行。

## FIELD NOT RUN
没有把远程资料或数字模拟冒充现场观察／实测。

## EVIDENCE REVIEW
证据仍在复核、补全或重新绑定设计判断。
