## 1｜项目是什么

「忘也 Daylily」是一项围绕 **品牌／IP、空间与体验关系** 展开的独立作品集项目。

项目已经形成设计逻辑、原型与视觉表达，但真实测试计划尚未执行，因此当前最重要的表达原则是：

> **原型存在，不等于效果已经被真实用户验证。**

---

## 2｜项目关注的问题

这个项目更关注：

- 品牌／IP 如何进入体验；
- 空间与触点如何共同构成体验；
- 视觉语言如何支撑而不是替代功能；
- 原型如何承载设计假设；
- 测试前应该明确哪些假设与风险。

它不是以“做完视觉稿”作为验证终点。

## 4｜项目命题：从“被安排的休息”转向“自主恢复路径”

现有项目展示把问题定义为：

> **当“休息”也需要被安排，体验应该提供什么？**

当前研究从行业、市场、竞品与目标人群切入，识别到的核心矛盾是：

> 都市人群需要短时恢复，但不希望被迫进入统一的仪式、审美或情绪脚本。

因此 Daylily 的设计命题不是制造一种“标准疗愈体验”，而是提供：

- 靠近；
- 停留；
- 感知；
- 自主选择；
- 带走；
- 下一次重新进入。

当前品牌命题写作：

> **让每一个都市人，都有一株属于自己的“忘忧草”。**

这里的“忘忧”是设计叙事，不是医疗或心理疗效声明。

---

## 5｜体验原则

现有作品将体验原则整理为四条：

1. **松开被规定的恢复方式**  
   不要求所有用户按同一种情绪脚本、仪式或动作完成体验。

2. **用自然材料降低感官负担**  
   通过低刺激材料、色彩与触感形成更安静的环境基调。

3. **让短暂停留也形成完整体验**  
   不要求长时间消费或完整流程才能获得体验价值。

4. **把空间记忆带回日常生活**  
   通过纸品、随身触点和可带走物，使体验不在离开空间时突然结束。

这些原则共同把项目从“视觉品牌”推向**品牌 + 空间 + 材料 + 触点**组成的体验系统。

---

## 6｜品牌与视觉系统

Daylily 当前的身份系统不是单独设计一个 Logo，而是从萱草的生长与舒展关系中抽取视觉生成语法。

现有设计记录包含：

- 花瓣；
- 放射；
- 生长节点；
- 开放边界；
- 标志构成与网格；
- 图形符号；
- 色彩系统。

这些元素被要求能够跨越：

~~~text
Identity
→ Editorial
→ Signage
→ Material
→ Spatial Touchpoint
~~~

也就是说，品牌识别不只出现在平面物料上，而要在不同媒介中保持同一种“关系语法”。

---

## 7｜CMF 与触点系统

当前材料／触点方向包括：

- 低饱和植物绿；
- 温暖纸色；
- 半透明层；
- 细微压印；
- tactile card；
- 折页／纸品；
- 空间标识；
- 可随身携带的触点。

其设计目的不是装饰，而是把“安静、停留、感知”转成可触摸、可翻阅、可带走的体验载体。

当前体验逻辑可以概括为：

~~~text
Environment slows the body
→ Information reduces choice pressure
→ Material creates tactile memory
→ Portable touchpoints extend the experience
~~~

这是项目目前最清楚的跨媒介设计关系。

---

## 8｜空间不是背景，而是体验媒介

现有展示明确把空间定义为：

> **恢复关系发生的媒介。**

空间、品牌和物料分别承担不同职责：

| Layer | 作用 |
|---|---|
| Environment | 帮助身体节奏慢下来 |
| Information | 降低选择压力 |
| Material | 建立触觉记忆 |
| Portable touchpoint | 把短暂体验延伸到日常 |

这使 Daylily 不只是“做一套品牌 VI”，而是一个把品牌识别、CMF、空间和用户路径组合起来的体验设计案例。

## 10｜下一阶段测试到底要验证什么

现有项目已经明确下一阶段希望补充真实场景测试，关注：

- 停留时长；
- 触点使用顺序；
- 情绪自评；
- 再次到访意愿。

这些目前只是**测试方向**，仓库没有支持把它们写成已经采集的结果。

真正执行时，需要进一步把它们转成：

~~~text
Design Hypothesis
→ Observable Behavior / Self-report
→ Test Task
→ Record
→ Failure / Deviation
→ Design Revision
~~~

但在真实测试发生之前，项目继续保持 `TEST PLANNED / NOT RUN`。

## 13｜证据边界

本项目不主张：

- 医疗效果；
- 心理治疗效果；
- 疗愈效果已经被验证；
- 用户行为改善已经被证明。

任何涉及用户心理、健康或疗效的表述，都必须建立在真实测试与可核验数据之上。

## 14｜Human–AI 协作价值

从 OLEANDER 角度，这个案例更适合验证：

它体现的能力包括：

- 假设与结果分离；
- 测试前边界管理；
- 品牌／体验／空间的跨对象协同；
- 避免把作品集表达包装成未经验证的商业成果。

## 16｜当前下一步

在有真实测试之前，合理的下一步不是继续增加“成功结论”，而是：

1. 明确目标用户与关键场景；
2. 明确需要验证的核心假设；
3. 定义测试任务与观察指标；
4. 执行真实测试；
5. 记录失败与偏差；
6. 再决定哪些设计继续 KEEP / REVISE / DROP。
