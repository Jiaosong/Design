## 01｜QJ-C06 Service / Accessibility / Recovery Contract v0.7

### Service hierarchy

`Safety / Return → Direction / Route → Recovery / Human Support → Observation → Explanation → Memory`

Service is part of the primary experience, not a back-office patch.

### Route certainty contract

Every route version must be able to answer:

- where the visitor is in the journey;
- main direction and return direction;
- whether the journey continues when a page is closed or skipped;
- whether shortening / retreat is possible;
- which service information requires human support or verified live data.

No pseudo-live timetable, weather, opening status, or remaining-time display is permitted without an official operating interface.

### Recovery contract

Recovery does not define a fixed interval and does not presume new furniture. It has three responsibilities:

1. allow bodily recovery;
2. not obstruct primary circulation;
3. return attention to real landscape / route after recovery.

The removable railing-leaning rest board remains `KEEP / HIGH PRIORITY SUPPORT / FIELD + ENGINEERING REQUIRED`, but no location is selected.

### Accessibility overlays

All of the following remain `G1F OPEN`: slope, steps, clear width, handrail / guardrail condition, stopping position, bypass / retreat, wet-surface risk, and bypass completeness after any physical intervention.

Before evidence closure, do not claim an accessible route, verified senior route, or verified low-load route.

### No-phone / weak-network contract

- Route / Return: physical wayfinding + human support are foundational.
- Observation: Landscape → one site prompt → paper → human → digital.
- Understanding: site diagram / paper / human first; digital reveal only where necessary.
- Memory: light recording on site; expand My Stone Book / photo / merchandise / sharing after departure.

### Environmental / capacity downgrade

- Fog: move to near-view / appearance-disappearance / sound / humidity; do not fake the missing distant view.
- Rain: downgrade content; prioritize Safety / Surface / Near-view.
- Strong light: reduce fine text and screen dependence; prioritize outline and direction.
- Peak crowd: remove Deep Read from bottlenecks and move depth to wider areas or post-visit.

## 02｜QJ-C07 Route × Service Failure Matrix v0.8

### Failure-tolerance principle

A complete experience is defined as the preservation of critical relationships, not fixed-node completion.

- Content / Companion Page failure must not break the route.
- Digital failure must not break Route / Return / Safety.
- Physical Hero must be bypassable.
- Service / Return / Safety uncertainty forces content downgrade.

### Failure levels

- `F1 Content Degradation`: content, digital, memory may fail; route remains complete.
- `F2 Experience Degradation`: some space / view / physical layer may fail; allow shortening or substitution while preserving Safety + Route + Return + at least one real observation relation.
- `F3 Journey Blocking`: Safety / Return / base circulation uncertain; do not present the journey as normal operation.

### Context responses

1. Page closed / skipped → continue route; no 13/13 penalty.
2. Fatigue / time shortage → Deep → Observe / Glance; allow shortening / retreat.
3. Weak network / no phone → physical + human + paper fallback.
4. Rain / wet surface → safety first; avoid forced dwell or active physical hero.
5. Fog → near-view / atmosphere fallback; no simulated clear-weather replacement.
6. Strong light → high-readability direction and outline.
7. Peak / group crowd → remove deep reading from bottlenecks.
8. Physical intervention unavailable → bypass; original route remains primary.
9. Return-window pressure → stop opening new deep-reading states; Return > Memory.
10. Narrow closure area unavailable → close truthfully; use only evidence-backed alternative closure / re-view position.

## 06｜QJ-C09 Recovery + Return Spatial Scenario Set v1.0

### Scenario method

Each scenario is defined as:

`Entry State → Spatial Relation → Primary Responsibility → Allowed Intervention → Exit State → Failure Fallback → Evidence Gate`

Every scenario must remain valid at `C0 / low-intervention`; stronger intervention is conditional only.

### S-C09-01 Continuous Walk → Micro Recovery

- Entry: continuous walking has produced fatigue or attention decline.
- Relation: `MOVE → slow down → short recovery → re-enter MOVE`.
- Primary: bodily recovery + route continuity.
- Allowed: C0, route/service micro-support, and conditionally the removable railing-leaning support.
- OFF: large rest Hero, strong branding, queued interaction.
- Fallback: if safe stopping is unavailable, do not force a Recovery node; downgrade content and use the next real service opportunity.
- Evidence: fatigue / dwell behavior, clear width, guardrail / substrate, view, bypass, wet condition, crowd.

### S-C09-02 Existing Pause / Viewpoint → Observe + Recover

- Entry: the route already forms a platform, viewpoint, or natural stop.
- Relation: `arrive → landscape first → optional support → leave`.
- Primary: real landscape first; recovery / explanation only if necessary.
- Allowed: C0, minimal prompt, railing support when justified, Print / 2D Reveal only when the real relation is visible but not understood.
- OFF: large Physical Hero plus main Science Reveal in the same first-reading position.
- Fallback: in crowd / strong light / rain / fog, Deep Read exits; Observe / Route / Safety remain.
- Evidence: view, dwell, congestion, readability, existing facility.

### S-C09-03 Single Recovery Competition Zone

This scenario only opens if A-line evidence proves that ordinary C0 / micro-support is insufficient.

Competition order:

`Existing condition → railing support → one larger rest OR one sensory candidate`

- Candidate A: mountain fluid rest installation.
- Candidate B: Qingfengyin.
- They do not stack and cannot both become Primary.
- If engineering, operation, noise, wind, maintenance, or landscape attack cannot be closed, fall back to the lower intervention level.
- Status: `CONDITIONAL / HOLD` pending candidate-specific Evidence Pack.

### S-C09-04 Pre-Closure → Design Withdrawal

- Entry: enough observation / reading has accumulated before a narrow-body closure such as 一线天.
- Relation: `content density down → body / rock / light / wind up → design withdraws`.
- Primary: natural body-space relation produces closure.
- Allowed: Safety / necessary Direction / operating notice.
- OFF: 步步生光, strong digital reveal, strong branding, IP, task, check-in Hero, forced recording.
- Fallback: if the real closure cannot be entered, use only a future evidence-backed alternative closure / re-view location and state truthfully that the original space was not entered.
- Evidence: actual circulation, clear width, wetness, crowd, closure rule, alternative route / view.

### S-C09-05 Return → Re-recognition

- Entry: main walking / reading experience is complete and the visitor is returning.
- Relation: `re-see → recognize relation → service certainty → leave`.
- Primary: make the second view different from the first through re-recognition, not new content density.
- Allowed: landscape / moving view, one light re-view prompt, Return / Service information, memory after departure.
- OFF: 13/13 completion, forced final task, new spatial Hero for closure.
- Fallback: as return pressure rises, close new content entries; Return > Memory.
- Evidence: real return sequence, visible relations, operating window, service data interface.

### S-C09-06 Shortened / Degraded Journey → Still Complete

- Entry: weather, fatigue, closure, time, or crowd reduces the full research journey.
- Relation: `reduce depth / distance → keep real relation → secure return → memory later`.
- Minimum contract: Route certainty + Safety / Return + at least one real Landscape / Body relation + one re-recognition opportunity when reality allows + no failure-completion state.
- Allowed: remove Reading / Companion / Digital / Physical layers.
- OFF: fake replacement experience, virtual equivalence claims, omission penalties.
- Evidence: actual shortening / retreat route, service node, closure logic, return method.

### Scenario synthesis

`MOVE → MICRO RECOVERY → OBSERVE / READ → [OPTIONAL SINGLE RECOVERY CANDIDATE] → DESIGN WITHDRAWAL → RETURN / RE-RECOGNITION → MEMORY LATER`

The non-substitutable core remains:

`Safety + Route + Return + Real Landscape / Body Relation`
