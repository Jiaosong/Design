## 1｜项目是什么

「清江石书」不是为红花峰林额外叠加一套独立游戏、角色宇宙或大型主题装置。

项目试图在成熟运营景区的真实地貌、地方文化、既有游线和运营条件之上，建立一套**低干预的山水阅读体验系统**。

> **山水为纸，岩层为字，行走成书。**

核心设计对象不是单一装置，而是：

- 游客；
- 真实地景；
- 地方解释；
- 路径；
- 数字信息；
- 身体行为；
- 服务与运营；
- 品牌识别；
- 记忆与文化产品；
- 返回与结束体验。

因此 C04 是 OLEANDER 中较适合观察“复杂多工作流长期协作”的案例。

# 4｜项目的设计因果链

当前专业内容架构采用：

```text
CONTEXT / EVIDENCE
→ PROBLEM
→ INSIGHT
→ PRINCIPLES
→ METHODS
→ MASTER SYSTEM
→ SUBSYSTEM DESIGN
→ SCENE APPLICATION
→ DETAIL DEVELOPMENT
→ TECHNICAL PROOF
→ PROFESSIONAL JUDGMENT
→ RETURN / CONCLUSION
```

游客第一阅读路径仍然重要：

```text
ENTER
→ ORIENT / CHOOSE
→ MOVE / OPEN
→ WALK / DISCOVER
→ STOP / OBSERVE / RECOVER
→ PASS
→ RETURN
→ REMEMBER
```

但游客 Journey 不是整个项目的唯一结构，不能为了“讲故事更顺”而压掉分析、方法、技术、品牌或设计深化。

# 6｜核心产品／体验系统

## Journey / Service
Arrival、BOAT、CABLE、WALK、分支／环线行走、纸质／人工／标识 fallback 与 Return 都属于项目。

BOAT / CABLE / WALK 描述的是体验尺度，不应被写成未经验证的既有运营事实。

## Thirteen Imprints
R01–R13 是内容／设计库。

它们可以被选择、重排和组合，不要求游客完成全部节点。

## App / Digital
App 是当前重要设计结果之一，稳定功能包括：

- TODAY
- ROUTE
- READ
- MY BOOK
- Service
- Return

同时保留：

- NORMAL / DEGRADED / CLOSED / UNKNOWN
- FULL / LIGHT / OFF
- Offline / no-phone fallback

数字体验不能成为现场体验成立的唯一条件。

## Physical / Body / Sensory
实体设计不等于“做大型装置”。

当前存在 KEEP、HOLD、COMPETE 等不同状态，具体对象需要分别经过来源、场地、人体、工程与设计质量判断。

## Brand / Visual Identity
品牌是独立设计系统，但不能获得路线、安全或景观权威。

Brand 的职责是：

> **整个项目如何被识别。**

## Memory / IP
Memory / IP 与 Brand 分开。

它回答的是：

> **游客离开之后，哪些内容继续被带走、记住和传播。**

# 7｜Human–AI 协作为什么在 C04 中重要

C04 的复杂度意味着 AI 如果只依赖聊天上下文，很容易出现：

- 把局部工作流当整个项目；
- 把旧版本当 Current；
- 把远程资料写成现场事实；
- 把 Web 合并成功写成 Design PASS；
- 把 3D 文件存在写成工程成立；
- 为了页面简洁压缩掉独立有效内容；
- 多个 Agent 同时工作时覆盖彼此对象。

因此 C04 实际上验证了 OLEANDER 的多个核心产品机制：

- Project State；
- Current Authority；
- typed Work Object；
- Owner / Next Owner；
- Human Decision Rights；
- Evidence / Claim Ceiling；
- Readback；
- Cross-workstream handoff；
- Anti-Pollution；
- No Compression / No Loss；
- Design Quality 与 Machine PASS 分离。

# 8｜当前五类工作流

当前 Project Control Card 将项目拆成五个主要 active workstreams。

## Active 1｜Narrative / Editorial
负责页面身份、内容结构、分析图、解释图与专业内容承载。

重点问题：

- 既有页面不能静默删除；
- source recovery 仍有开放项；
- 新页面必须建立在具体内容需要之上，而不是凑页数。

## Active 2｜Whole-project Visual / Motion
负责：

- Journey；
- App / Game Map；
- Physical；
- Brand；
- Memory / IP；
- Return；
- Analysis；
- Methods；
- Technical proof；
- Motion。

重点是形成 C04-specific visual language，而不是通用 dashboard / flowchart 视觉。

## Active 3｜Web
Web 是重要载体，但不是整个项目。

当前要求：

- 浏览器真实 readback；
- 多尺寸检查；
- finished-pixel review；
- governance / dependency PASS 与 Design PASS 分开。

## Active 4｜Physical / Product / Detail
包括：

- Physical P01–P09；
- body / use relation；
- plan / section / axon / node；
- CMF / material；
- maintenance；
- editable 3D when materially required。

3D 不是默认媒介。先判断需要表达的真实问题，再决定是否需要 Blender。

## Active 5｜Final Integration
持续把真正已经闭合的上游资产整合到：

- Web；
- PDF；
- boards；
- film。

它不是等所有工作流结束后才开始的“最后一步”。

# 9｜Evidence / Truth Boundary

这是 C04 当前最重要的边界之一。

仍未闭合的现场／专家证据包括：

- field-fact promotion；
- 精确实测几何；
- 安全／无障碍／容量批准；
- construction-ready；
- implementation-ready；
- approval claims；
- system promotion。

这些 HOLD：

> **不会阻止证据约束下的概念设计继续深化，  
> 但会阻止系统把设计候选写成现场事实、工程批准或实施结论。**

传统景观／风水相关内容只能作为文化解释，不作为工程或科学证据。

Wellbeing 仅用于休息、节奏、饮水／遮阴提示、安静观察、疲劳降级与 Return 支持，不主张未经验证的治疗或健康效果。

### Current Execution State
`ACTIVE / EXPLORE-G3 / FIELD OPEN / NO_PROMOTION`

这是当前项目执行层状态。

同时必须始终保留：

`FIELD OBSERVED=0 / FIELD MEASURED=0 / G1F HOLD`

因此：

> **进入 G3 探索 ≠ 现场验证通过**  
> **远程研究 ≠ Field Evidence**  
> **项目继续设计 ≠ 项目获得实施授权**

# 11｜页面与资产数量怎么理解

C04 曾出现大量页面、chapter、authoring units、Web surfaces 和资产。

当前规则是：

> **不使用固定页面数量作为设计目标。**

既有 52 个 Web PAGE identities 是 protected baseline inventory：

- 不是新架构；
- 不是上限；
- 不是必须压缩到的目标；
- 不能和 authoring unit 数量机械相加。

所有页面必须先做对象级映射，再决定：

- KEEP
- MOVE
- REWRITE
- REDRAW
- EXPAND
- PROCESS
- ARCHIVE CANDIDATE
- NEW

这体现了：

> **NO COMPRESSION / NO LOSS**

# 13｜如果你从产品经理视角阅读

C04 最值得看的不是“项目文件很多”，而是如何处理复杂度。

可以重点观察：

### Problem Decomposition
一个大项目如何拆成不同 Work Objects，而不是拆成互相失去联系的功能列表。

### Product State
如何防止旧文件、新文件、Web、3D、AI 对话同时声称自己是 Current。

### Multi-Agent / Multi-workstream Coordination
多个执行流如何通过 Owner、Next Owner、handoff 和 readback 避免冲突。

### Trust
为什么：

- file exists ≠ valid；
- CI PASS ≠ Design PASS；
- render complete ≠ professional approval；
- remote evidence ≠ field fact。

### Product Evolution
为什么系统优先修复和复用已有设计资产，而不是每轮重新生成。

- FIELD OBSERVED = 0；

- 已获得景区正式采用；
