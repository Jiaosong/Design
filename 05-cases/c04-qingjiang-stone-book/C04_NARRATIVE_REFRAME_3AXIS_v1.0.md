## 0｜Public logic

The public project is reorganized through three direct questions:

1. **清江有什么？** → 地域历史 / 文化故事 / 山水观 / 地方知识。
2. **游客怎么游？** → BOAT / CABLE / WALK / game-style map / service / App route.
3. **到了一个场景具体玩什么、得到什么？** → CULTURE / WISDOM / PLAY / WELLBEING × audience × existing physical/digital/memory design.

These three axes are an **editorial and experience structure** across existing assets. They do not delete the Thirteen Imprints, App, physical installations, memory products, IP, model or technical work.

Hero proposition:

> **先游清江，再读清江。**
>
> 从清江的地域文化、真实水陆空游程出发，把十三印、游戏地图、数字界面、实体互动、休息、记忆与文创重新编排到真正适合发生的场景。

## AXIS 1｜地域文化｜QINGJIANG CONTENT ENGINE

### Question
**清江到底有什么值得游客认识、参与和记住？**

### Content reservoir
Use the original `@恩施` package + current evidence/content library to organize:
- regional history / river and settlement / transport history;
- local stories and names: 廪君、盐水女神、峰名与地方叙事；
- craft / intangible culture: only where source-grounded and relevant to the experience;
- landscape knowledge: river, peak forest, fissure, plant, weather/season observation;
- traditional landscape view / 风水: treated as **cultural landscape interpretation**, never engineering/science proof;
- daily/local wisdom: route recognition, weather perception, observation and body pacing;
- memory language: page / line / mist / wind / personal mark.

### Existing designs activated by Axis 1
- **R01–R13 full content library**, especially R02/R04/R07/R09/R12 for culture/local story and R03/R06/R08/R10/R11 for observation/science questions;
- **READ / REVEAL** inside the App;
- **清江旅记 / 我的石书** for personal cultural memory;
- **红花峰崽** for child/family observation;
- **清江一线 / 清江雾气 / 清风吟** as selective memory translations;
- physical reading board F02 only where a scene genuinely needs a short on-site explanation.

### Design rule
Culture must change **what the visitor notices or does**, not become a long history chapter.

For each culture item, show:
`source / story → scene → visitor action → medium → audience depth → what changes in perception`.

Example:
- `盐水女神` → R09 scene → listen / compare landscape with story → optional audio/story page → adult/deep reader can continue, child/family gets image/voice cue → gain: understand local narrative without claiming the peak is the ancient event site.

### Public visual requirement
Axis 1 needs at least one strong **Culture Map / Content Constellation** and several actual scene applications. It must not be delivered as a taxonomy table alone.

## AXIS 2｜游玩线路与交通｜HOW TO PLAY QINGJIANG

### Question
**今天到底怎么游清江？**

### Core journey
`到达 → 确认路线/回程 → BOAT → CABLE → WALK → 场景选择 → 休息/互动/阅读 → RETURN → MEMORY`

The exact available transport sequence must follow current official/source authority; the design uses BOAT/CABLE/WALK as three experience scales, not as invented live-service promises.

### Three travel lenses

#### BOAT｜水上看清江
- long-distance landscape / river scale / sound / reflection;
- Culture can appear as short audio or map context;
- PLAY can be low-attention silhouette/sound observation;
- no screen-heavy interaction while the real river view is strong.

#### CABLE｜空中看清江
- transport first, then moving view;
- R01 / R05 may appear as light visual cues;
- App remains S0/S1 light; no mandatory trigger / long text / AR target;
- the game feeling comes from **moving across the world map**, not from forcing a task in the cabin.

#### WALK｜山中看清江
- body, terrain, branching path, rest, close observation;
- most Thirteen Imprints / physical interactions / family mechanics live here;
- route is a network; content can be discovered in different order.

### Game-style Qingjiang Map
The map should feel like a high-quality open-world exploration map while retaining tourism clarity.

Show layers:
1. river / banks / terrain regions;
2. BOAT / CABLE / WALK transport;
3. main paths + branches / loops;
4. service / rest / return;
5. Thirteen Imprints / stories / observation / sensory experiences;
6. CLOSED / UNKNOWN as fail-closed overlays;
7. personal visited/recorded traces, not completion percentage.

Allowed game language:
- map reveal;
- discovery markers;
- optional collection in My Book;
- scene icons;
- light puzzle/observation;
- family co-discovery;
- transport transition;
- personal route trace.

Not allowed:
- route locked by quests;
- 13/13 required completion;
- safety/return hidden behind game progress;
- battle/experience/coin/loot-box/rarity grammar;
- fake GPS/live operation.

### Existing designs activated by Axis 2
`J01–J06 + D01/D03/D04/D07/D08/D09 + M01/P09 + T01/C22 + T04 SEC-A + V01/V02/V05`.

### Front-end architecture
The App remains a primary designed outcome, with four public anchors:
- `TODAY｜今日清江`
- `ROUTE｜探索地图`
- `READ｜十三印 / 场景内容`
- `MY BOOK｜我的石书`

`SERVICE / Return` remains permanently accessible rather than buried as a fifth narrative chapter.

## AXIS 3｜场景游戏与不同人群｜WHAT HAPPENS HERE

### Question
**游客到了这里，具体能做什么；为什么值得做；不同人得到什么？**

Use four content modes as tags, not four equal chapters:

- `CULTURE` — story / name / history / intangible culture;
- `WISDOM` — observe → guess → compare → explain;
- `PLAY` — find / match / trace / listen / frame / step / collaborate / light puzzle;
- `WELLBEING` — rest / pace / shade-water prompt / quiet looking / recovery / fatigue downgrade / return.

`Wellbeing` is experience/service, not medical treatment or selenium-health marketing.

### Audience rule
Do not make separate decorative “child / adult / senior pages”. The same scene changes by action depth and support.

Current audience basis:
- A1 ordinary / first-time visitor;
- A2 family / learning;
- A3 deep reader / geology-culture-photo;
- A4 older / low-digital;
- A5 short-time / limited stamina;
- A6 local / returning.

### Interaction mechanics already in project
Use and refine the existing verbs rather than inventing a completely new game:
`LOOK / COMPARE / TRACE / LISTEN / WAIT / FRAME / STEP / REMEMBER`.

Map them to content modes:
- LOOK / FRAME → landscape + PLAY;
- COMPARE / TRACE → WISDOM;
- LISTEN / WAIT → CULTURE / WELLBEING;
- STEP → Physical / PLAY;
- REMEMBER → My Book / Journal / cultural product.

### Physical designs are scene mechanics, not decoration
- `步步生光` = strongest body-interaction candidate;
- rail leaning rest = service/recovery;
- mountain fluid rest = conditional landscape-rest interface;
- `清风吟` = low-intensity sensory interaction;
- F01–F03 = technical validation/support descendants, not the full design inventory.

## 4｜How the three axes become the public Web / portfolio

Page count is unrestricted. Use quality-driven editorial beats, not one asset = one page.

Recommended macro rhythm:

1. **Hero｜先游清江，再读清江** — one strong Qingjiang first read.
2. **What is Qingjiang?｜地域文化与山水内容源** — Culture Map, not research wall.
3. **How to play?｜游戏风格总地图** — BOAT/CABLE/WALK + route/service/return.
4. **The App｜清江十三印数字体验** — actual phone UI and interaction, not a small appendix.
5. **Thirteen Imprints｜十三印全体系** — show complete library, then demonstrate selected scenes in depth.
6. **Scene 01–n｜到这里具体怎么玩** — use R05 / step-light / R06 / culture nodes / Qingfengyin / R13 as differentiated scenes.
7. **Different people, same Qingjiang｜同一场景不同深度** — actual scene variants, not persona cards.
8. **Physical Design｜身体、休息与感官装置** — step-light / leaning rest / fluid rest / Qingfengyin; show body scale + material/use/field-open proof.
9. **Memory｜把这趟清江带走** — Journal + My Book + Line/Mist/Qingfengyin + Peak Cub with clear roles.
10. **Technical Proof｜为什么设计成立到这一步** — C22/C23 / SEC-A / R06 node / evidence boundaries.
11. **Return / Close** — real Qingjiang + personal memory; no completion score.

Do not force this into a fixed number of sections. A strong App interaction may need several screens; a weak technical matrix may be one appendix block.

## 5｜Quality consequence

The Public Quality Gate remains active, but now applies **after no-loss inventory**.

Decision vocabulary:
- `CONCEPT KEEP / PIXELS KEEP`
- `CONCEPT KEEP / PIXELS REDRAW`
- `CONCEPT COMPETE / SHOW PROCESS`
- `CONCEPT HOLD / FIELD OPEN`
- `CONCEPT DROP`

This prevents two opposite errors:
1. keeping bad old pixels only because an asset existed;
2. deleting valuable designs only because the latest minimal validation package did not show them.
