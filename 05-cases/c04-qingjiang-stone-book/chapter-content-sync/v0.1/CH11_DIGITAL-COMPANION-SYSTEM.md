# CH11｜数字陪伴系统 / App

- 章节角色：在真实路线与十三印已经独立成立的前提下，定义数字产品还能增加什么、何时出现、何时减弱、何时退出。
- 禁止：把本章压成6屏UI拼图、景区功能门户或游戏任务机。
- 核心身份：`DIGITAL COMPANION`，不是数字景区。

## CH11-P01｜数字陪伴系统到底是什么

# 手机不是进入清江的入口，只是在需要时出现的第二层。

App不是什么：
- 不是导航控制器。
- 不是十三印任务机；无3/13、下一任务、完成进度、签到。
- 不是游客后台仪表盘。
- 不是用HUD/抽象游戏地图覆盖真实清江的第二世界。

App承担五个角色：
1. ORIENT｜今天怎么游。
2. EXPLORE｜附近还有什么值得发现。
3. READ｜需要时进入十三印内容。
4. REMEMBER｜把真正想留下的经历带走。
5. RETURN｜任何时候重新获得方向与回程。

结构：`TODAY → ROUTE → READ/SCENE/EXPLORE → MY BOOK`；RETURN 与所有页面平行。

结论：**数字产品存在的价值，不是让游客更多地使用手机，而是帮助他更快重新把注意力交回清江。**

## CH11-P02｜TODAY｜进入清江前的第一次判断

# 今天的清江，先帮我判断“怎么游”。

TODAY回答：有哪些基本选择？哪种方式更适合时间/状态？有没有必要异常？怎样回来？

四层：
1. 今天的空间状态：游船/索道/步行/Return。
2. 推荐体验尺度：想看整体→BOAT；想理解两岸→CABLE；想进入山中→WALK；时间/体力有限→SHORT/RETURN-FIRST。
3. 必要状态：NORMAL / DEGRADED / CLOSED / UNKNOWN；UNKNOWN不得假装开放。
4. Return：稳定存在，不藏进更多菜单。

第一视觉仍是大幅真实清江，下部只保留 `水上看 / 空中看 / 山中走 / 先回来`。

结论：**TODAY不是告诉游客今天还能完成多少内容，而是帮助他决定以什么尺度进入清江。**

## CH11-P03｜ROUTE｜地图制造探索感，而不是任务感

# 地图告诉我“还能怎么走”，而不是“还有什么没完成”。

地图两层：
- **BASE ROUTE**：主路径、分支、回环、Return、服务关系；最强。
- **DISCOVERY**：附近十三印、景观观察、内容机会、记忆点；较弱。

游戏感来自：未完全揭开的地图、路线选择、附近可能内容、自己走过的路线形成轨迹，而不是闪烁任务点/积分/完成度。

探索显著性：当前位置最明显 → 真实可走关系 → Return稳定明显 → 附近可能内容轻提示 → 远处十三印可不显示。

状态：NORMAL正常；DEGRADED降低内容层；CLOSED明确不可进入；UNKNOWN不画成自由通过。

旁边必须并列 Paper Map / Signage / Human Service / Landscape Recognition，明确 `DIGITAL ROUTE ≠ ONLY ROUTE`。

## CH11-P04｜READ｜十三印数字阅读不是知识卡片

# 数字阅读不是把十三印搬进手机，而是控制内容出现的深度。

结构：`SCENE → CUE → RELATION → DEEP READ → WITHDRAW`。

第一屏先给当前景观/关系，不直接弹完整知识卡。
- CUE：极轻提示，如“两岸一样吗？”
- RELATION：用户主动进入后出现关系线/对照。
- EXPLANATION：再继续才进入地方故事、地名、科学解释、文化背景。
- SOURCE / DEEP READ：真正感兴趣者现场或旅后查看。

每一层都可继续或“回到清江”；Reveal用于内容进入，Withdraw用于退出。

结论：**数字深度可以无限扩展，但现场第一屏必须保持克制。**

## CH11-P05｜R06｜Landscape First → Relation Reveal

# R06不是打开一个页面，而是让一层关系短暂出现。

状态：
0. NO PHONE：完整河谷已成立。
1. LANDSCAPE：即使打开App，UI仍极弱。
2. QUESTION：轻问题，如“哪一边更高？”
3. RELATION REVEAL：出现简洁空间关系，不遮主体。
4. DEEPER READ：主动进入后才出现详细内容。
5. WITHDRAW：结束后撤退，回ROUTE或真实清江。

同一R06不同人：儿童停在Question/Compare；青年可Reveal/Explore；深读者进入Explanation；疲劳游客直接RECOVER/RETURN。

视觉：一张R06大图，数字层按时间短暂浮出，不做六台手机并列。

结论：**App没有替游客看见R06，它只帮助游客第二次看清刚才已经看见的东西。**

## CH11-P06｜R13｜身体优先时，数字必须真正关闭

# R13不是“轻量交互”，而是明确的数字退场场景。

- APPROACH：短提示前方高注意力通过段，然后逐渐退出。
- ENTER：只保留必要方向/出口/Return，甚至完全关闭。
- PASS：PLAY OFF / READ OFF / COLLECTION OFF / SOCIAL OFF。
- REOPEN：离开收束后内容才重新获得出现资格。
- LOOK BACK：可极轻提示回头看。

UNKNOWN/CLOSED时不得继续用“前往发现R13”等探索语言诱导。

结论：**数字产品成熟的证明，不是它能在每个地方工作，而是它知道哪里不应该工作。**

## CH11-P07｜MY BOOK｜个人旅程记忆，不是十三印完成册

# 留下的不是“我完成了多少”，而是“我经历了什么”。

禁止显示 `10/13 / 完成率 / 还差哪些印`。

记录：
- MY ROUTE：实际走过的路线。
- MY MOMENTS：真正停下来的地方。
- MY OBSERVATIONS：照片/文字/画/声音/一句话。
- MY READINGS：主动读过的内容，不等于完成。
- MY MEMORY：自己选最想留下的清江片段。

“我的石书”由游客自己生成，留下3页也完整；`MY BOOK IS PERSONAL / NOT COMPLETE`。

与实体《清江旅记》：数字记录路径/照片/阅读/声音；实体保留手写/盖印/折页/纸张/身体痕迹，二者不互相复制。

## CH11-P08｜SERVICE / RETURN / OFFLINE｜没有App也成立

# 一个可靠的数字陪伴系统，必须能够承认自己不是必需品。

- RETURN：任何主要页面可重入，不是菜单次级功能。
- OFFLINE：设计目标包括预载路线、核心地图、已保存内容、我的石书、Return信息；不宣称现场网络已验证。
- NO-PHONE：Paper Map / Signage / Human Service / Landscape 完成基本游程。

### 双状态系统
空间/服务状态：NORMAL / DEGRADED / CLOSED / UNKNOWN。
内容介入强度：FULL / LIGHT / OFF。
两者不得混为一套：如 NORMAL×OFF（R13正常开放但内容关闭）、DEGRADED×LIGHT、UNKNOWN×OFF。

三层图：真实清江/ROUTE/SERVICE（底层）→ PAPER/SIGNAGE/HUMAN（冗余支持）→ APP（可增加也可退出）。

核心：`APP OFF / JOURNEY STILL WORKS`。

## CH11-EXPANSION｜后续必须独立增加的专业数字页

以下内容不压进P01–P08；形成后应分配新的正式 PAGE-ID：
- Information Architecture：完整App信息架构。
- Cross-screen Journey：TODAY→ROUTE→READ→MY BOOK→RETURN。
- State Matrix：NORMAL/DEGRADED/CLOSED/UNKNOWN × FULL/LIGHT/OFF。
- Component System：地图、按钮、状态、Reveal、Return、字体、图标。
- Motion Grammar：Discover / Reveal / Withdraw / Return，而非统一Fade。
- Offline / Failure States：断网、未加载、状态未知、路线关闭、低电量等具体界面变化。

这些是新增页面候选，不使用与CH12旧顺序号冲突的临时“055A”等作为最终PAGE-ID。
