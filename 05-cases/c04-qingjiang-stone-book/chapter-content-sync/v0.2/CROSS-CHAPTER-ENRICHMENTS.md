## CH04-P07｜低数字熟悉度 / 无手机 / 陪同使用

Audience不能只按年龄分。增加一类**使用条件**：
- 无手机 / 低电量 / 无网；
- 不愿登录 / 不熟悉地图交互；
- 一台手机多人共读；
- 需要陪同或人工帮助。

设计后果：Paper + Signage + Human Service 必须构成完整旅程；Digital只增强，不成为准入条件。

## CH05-P05｜失败、绕行、求助与退出旅程

按 Journey Mapping Canonical，把理想旅程改为包含：
`PAUSE / WRONG TURN / FATIGUE / CLOSED / UNKNOWN / NO NETWORK / ASK FOR HELP / EARLY RETURN / EXIT`。

每个事件记录：`EVENT + CONDITION + CONSEQUENCE + ACTOR + OWNER + EVIDENCE`。

禁止无来源情绪曲线；优先画真实决策与责任。

## CH09-P06｜Service Blueprint｜游客看不见的后台怎样支撑Return

把前台旅程与后台能力并置：
- Frontstage：signage / staff / paper / digital / cable / boat / rest / route information；
- Backstage：运营排班、设备状态、信息更新、异常确认、人工接管；
- Support：数据、维护、票务 / 服务规则、供应商、应急接口；
- Failure：closed / unknown / network loss / fatigue / weather / missed transport；
- Recovery：inform / redirect / manual support / return / suspend optional content。

FIELD / operator data absent时只画责任接口，不伪造SLA。

## CH11-P09｜探索行为语法，不用特效代替状态

数字探索从 `fade / glow / reveal` 提升为行为关系：

`INTENT → SCOUT → COMMIT → REVEAL → RETREAT / RETURN`。

每一步必须有：
- persistent world / object；
- relationship change；
- reverse / recovery；
- reduced-motion equivalent。

特效只是机制，不能代替空间 / 任务 / 状态因果。

---

## CH11-P10｜交互状态与可见可恢复性

关键控件必须能区分：
`DEFAULT / HOVER / FOCUS / SELECTED / DISABLED`。

同时与 `NORMAL / DEGRADED / CLOSED / UNKNOWN` 分开：前者是交互状态，后者是运营 / 可信度状态。

截图可证明视觉区别，不能证明键盘顺序、辅助技术命名或完整可访问性。

## CH14-P10｜Brand Governance｜品牌不是交完VI就结束

每个应用记录：
`PROMISE → ACTOR → TOUCHPOINT → DELIVERY OWNER → EVIDENCE → FAILURE / RECOVERY`。

需要明确：
- Primary / Stacked / Small-size mark；
- FULL / LIGHT / TRACE / OFF；
- operational-status colors独立；
- bilingual hierarchy；
- photo / map / technical / motion role；
- exception / update owner。

视觉一致但服务失败，仍属于品牌体验失败。

这页只处理显示行为，不宣称商标 / operator approval。

## CH16-P08｜Dimension-to-object Binding｜尺寸必须指向真实测量区间

禁止“数字在旁边但不知道量什么”。

每个尺寸必须绑定：
`SOURCE VALUE → MEASURED OBJECT / INTERVAL → ATTACHMENT CARRIER → NEAR-READ DIMENSION → TRUTH BOUNDARY`。

重复 / 次要尺寸可移至近读rail，但关键身体与总尺度要直接贴合对象。

---

## CH17-P07｜Evidence-bound Figure Caption｜图注必须跟证明范围一起出现

每张关键图旁用紧凑图注绑定：
`FIGURE_ID + SOURCE CLASS + CLAIM + SUPPORT SCOPE + DOES NOT PROVE + FIELD STATE`。

禁止把元数据做成主视觉Dashboard，也禁止让图和证据边界分离到另一页。

---

## CH18-P07｜Mixed-media Evidence Role｜真实景观、模型、技术图、效果图各自证明什么

并置媒体时先声明：
- Landscape：证明真实视觉 / 场地来源范围；
- Model：证明关系 / 尺度 / 构造假设；
- Section / Node：证明几何 / 连接表达；
- Render / AI：证明概念体验或视觉方向；
- Prototype：证明交互 / runtime行为。

任何一种媒体都不能凭完成度越权替代另一种证据类型。
