## 0｜Why v2.0

The 2026-08-17 Web story-flow draft correctly identified repeated narrative ownership, but it predates Architecture v3.2, the independent CH14 Brand system, the strengthened CH02 evidence layer and the current PAGE-count contract.

Therefore the old story-flow remains editorial provenance only. v2.0 currentizes the narrative responsibilities without compressing the project.

## 1｜Two structures must coexist

### A. Professional project architecture
`CH00–CH19` is the authoritative professional chapter structure.

### B. Public Web reading rhythm
The Web may compose chapters into a more continuous public story, but every protected project system/page identity must remain traceable.

Hard rule:

> **Narrative acts may merge/split for pacing; canonical project content may not disappear.**

The Web must not turn 20 chapters into a false `page_count=20`, nor treat the 52 protected P001–P052 identities as the final page count. Exact PAGE REGISTER mapping remains a separate gate.

## 2｜Public Web narrative spine｜v2.0

The public carrier should answer, in order:

`WHAT IS QINGJIANG? → WHAT IS THE PROBLEM? → HOW DO YOU TRAVEL? → WHAT CAN YOU READ? → WHAT HAPPENS IN A SCENE? → HOW DOES THE BODY CHANGE THE DESIGN? → HOW IS THE SYSTEM RECOGNIZED? → HOW DOES IT ACTUALLY HOLD TOGETHER? → HOW DO YOU RETURN? → WHAT REMAINS AFTER LEAVING?`

This is a reading spine, not a fixed section count.

## 3｜Narrative acts and chapter ownership

### ACT 01｜PLACE / PROMISE
Primary chapter sources: `CH00 + selected CH02/CH03`.

First read:
- real Qingjiang landscape;
- project name `清江石书`;
- proposition `先游清江，再读清江`.

Purpose: establish the place and promise before systems.

Do not:
- start with App;
- start with diagrams;
- explain the entire route;
- explain all thirteen imprints;
- make Stone Seal/logo the first visual authority over Qingjiang.

### ACT 02｜EVIDENCE / PROBLEM / OPPORTUNITY
Primary chapter sources: `CH01 + CH02 + CH03 + CH04 + CH05`.

The Web must establish why the project is necessary:
- real guide evidence shows a branch/loop journey rather than a linear 13-stop route;
- water / bank / peak / valley / visibility / body condition change how much explanation is appropriate;
- different moving modes create different attention conditions;
- audience depth and physical stamina alter interaction demand.

CH02 GIS figures may appear as evidence/proof with their source/HOLD states visible. They must not be presented as survey or final engineering truth.

### ACT 03｜INSIGHT / DESIGN PRINCIPLES
Primary chapter sources: `CH06 + CH07 + CH08`.

This act converts evidence into the project logic:
- `REAL QINGJIANG FIRST`;
- `ROUTE ≠ CONTENT ORDER`;
- optional reading rather than task completion;
- `SERVICE / RETURN > ROUTE > OBSERVATION > EXPLANATION > MEMORY > SHARE`;
- `NORMAL / DEGRADED / CLOSED / UNKNOWN × FULL / LIGHT / OFF`;
- landscape/body attention controls how much design is visible.

Do not turn this act into a governance dashboard. Principles should be shown through a few decisive relations, not a wall of rules.

### ACT 04｜JOURNEY / ROUTE / SERVICE
Primary chapter owner: `CH09`; supporting evidence from `CH05`.

This is the **sole primary owner of “how the visitor travels.”**

Narrative:
`ENTER / ORIENT → BOAT or CABLE context → WALK NETWORK → OBSERVE / RECOVER / CHOOSE → RETURN`.

`ROUTE-03 = LOCKED CURRENT` is the geometry authority for current route representation.

Culture, Brand, App and Scene chapters may reference the route, but must not re-explain or redraw a competing route system.

### ACT 05｜READING SYSTEM / THIRTEEN IMPRINTS
Primary chapter owner: `CH10`; digital support from `CH11`.

Core explanation:
- the journey belongs to Route;
- the Thirteen Imprints belong to optional reading/content;
- there is no mandatory 13-stop route;
- there is no 13/13 completion gate;
- a visitor can keep moving, return, or ignore digital explanation.

The Web should make `ROUTE / PAGE / OPTIONAL READING` visually distinct.

### ACT 06｜DIGITAL COMPANION
Primary chapter owner: `CH11`.

App remains an independent canonical system, but Web only needs to explain its project role:
- TODAY / ROUTE / MY BOOK / SERVICE lineage;
- route child / reading relation;
- Return Guard / UNKNOWN fail-closed;
- FULL / LIGHT / OFF;
- no-phone continuity.

Web must not make App own the overall project narrative. Current App candidate status remains separate from Web quality.

### ACT 07｜KEY SCENE EXPERIENCE
Primary chapter owner: `CH12`.

This act owns the **full behavior of selected scenes**.

Recommended scene logic:
`CONTEXT → BODY/ACTION → OPTIONAL READING → PHYSICAL/DIGITAL SUPPORT → FALLBACK / RETURN`.

R06 and R13 should not be re-explained in every later chapter:
- R06 = open attention / recovery / optional reveal;
- R13 = compression / body passage / exit / Return; `PLAY OFF / READ OFF` during passage.

Scene is where the visitor experience becomes concrete.

### ACT 08｜AUDIENCE + BODY + PHYSICAL / SENSORY
Primary chapter sources: `CH04 + CH13` with scene references from CH12.

First show one shared real scene, then show how use depth changes:
- family / shared noticing;
- exploration / trace/frame;
- deep read;
- low-stamina / recover / return;
- low-digital / no-phone.

Then show physical/sensory support as responses to body need, not as a product catalogue:
- Step Light / transient feedback;
- short recovery support;
- Fluid Rest relation study;
- Qingfengyin / natural-wind-first sensory support.

Fixed read order:
`LANDSCAPE → BODY NEED → OBJECT RELATION → TECHNICAL SUPPORT → FIELD OPEN`.

### ACT 09｜BRAND / VISUAL IDENTITY
Primary chapter owner: `CH14`.

This is now an independent narrative act and cannot be hidden inside Motion or Memory.

Tell Brand through the logic of the whole project:
1. why the name is `清江石书`;
2. verbal proposition / language hierarchy;
3. Stone Seal / wordmark identity;
4. role-bound color and typography;
5. ROUTE-03-derived LINE / TRACE / PAGE grammar;
6. icon / legend / functional information family;
7. cross-media presence `FULL → LIGHT → TRACE → OFF`.

Critical semantic firewall:
- Brand does not own Route;
- Brand color does not encode operational state;
- Stone Seal does not become a map node;
- Return / Safety / Landscape may suppress Brand.

The narrative purpose is **recognition across carriers**, not a decorative VI gallery.

### ACT 10｜DETAIL + TECHNICAL PROOF + PROFESSIONAL JUDGMENT
Primary chapter sources: `CH16 + CH17 + CH18`.

Technical Proof remains independently visible and near-readable.

Use this act to show:
- general assembly / detail hierarchy;
- sections / model relation proof;
- material/interface/maintenance thinking;
- alternatives and rejected directions;
- what is source-grounded, what is design decision, what is still FIELD OPEN.

Technical proof clarifies finished experience; it does not reopen R06 or replace landscape first-read.

Do not make the project end on a technical sheet.

### ACT 11｜MOTION / SYNTHESIS
Primary source: `VISUAL / MOTION` system with CH05/CH12/CH19 relations.

Motion should synthesize already-understood spatial states rather than invent another content system.

Preferred temporal spine:
`ARRIVE → CROSS / MOVE → OPEN → OBSERVE / RECOVER → PASS → RETURN`.

Memory should not interrupt R13 passage. Brand presence should rise/fall according to attention rather than remain constant.

### ACT 12｜RETURN → MEMORY / TAKE AWAY
Primary chapter sources: `CH19 + CH15`.

This is the final closure and corrects the old `Memory → Technical → Motion → Return` order.

Final sequence:

`RETURN → RECOGNITION → RECORD → TAKE AWAY`

First prove the visitor can come back through:
- paper map;
- path markers;
- human service;
- landscape recognition;
- digital Return as a parallel helper, not sole dependency.

Only then close with Memory/IP:
- Qingjiang Journal / physical memory;
- My Book / digital memory;
- selective cultural products/IP extensions.

The final emotional frame should return to real Qingjiang / remembered journey, not a status chip, technical drawing, App screen or 13/13 completion state.
