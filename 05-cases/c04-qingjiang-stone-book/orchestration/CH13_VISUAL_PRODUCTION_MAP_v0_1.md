## S04｜CH13-P04｜步步生光 / STEP → RESPONSE → FADE

**Primary claim**  
`脚步经过，光只停留几秒。`

**First visual**  
A full-width dark path strip with the interaction itself running in the page. Avoid explanatory cards; the user should understand the behavior by triggering it once.

**Interaction state machine**
`IDLE → STEP → RESPONSE → FADE → IDLE`.

Inputs:
- pointer/touch press on a step zone;
- keyboard focus + Enter/Space equivalent;
- rapid repeated activation must not create an accumulating reward trail.

Motion role = **Feedback + Narrative**. The light must fade back to quiet. Reduced-motion keeps an instantaneous high-contrast response with no delayed animation lock.

**3D / model**  
No model. This is a temporal behavior problem; use native HTML/SVG/CSS/WAAPI first.

**Proof layer**  
After interaction, optional close-read reveals: daylight legibility / slip / drainage / power / maintenance / crowd-noise questions. No score, no completion logic.

**Image-consumption**  
Primary visual should be native vector/runtime, so it need not consume another major raster asset.

## Interaction grammar across CH13

- Default page is understandable without interaction.
- Scroll = continuity / reveal, not scroll-jacking.
- Pointer/touch = optional focus / comparison.
- Keyboard = same semantic state where interaction is essential.
- No interaction may create a task, score, completion requirement, reward loop, or route gate.
- Motion is added only after state is defined.
- Reduced motion preserves information.
- `RETURN / SERVICE / SAFETY` priority remains higher than optional interaction if this chapter is embedded in the live C04 Web/App carrier.
