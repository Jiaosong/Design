## 1｜Global visual rule

### Public reading arc

`BODY / EXPERIENCE → WHETHER / WHERE → SECTION RELATION → MATERIAL ROLE → CONNECTION / REVERSIBILITY → WEATHER / MAINTENANCE → OPEN ITEMS / RETURN TO WHOLE`

CH16 must not read as seven repeated technical boards. Every page gets a different dominant carrier and a different visual action.

### Resource hierarchy

`REAL QINGJIANG / BODY CONTEXT → REGISTERED DRAWING / RELATION → SAME-SOURCE DETAIL → MATERIAL / JOINT / MAINTENANCE PROOF → TEXT`.

- One dominant resource per page; target first-read visual mass `~65–80%`, not an equal-card contact sheet.
- Authoritative/current resource frames use `contain`; no crop / cover-fit replacement.
- If a page needs more than one full resource, use sequential full-frame / carousel / step-through; recoverability is mandatory.
- Interaction acts on the resource: reveal, focus, compare, state switch, parent→child, return-to-whole. Do not add a dashboard over the resource.
- One page = one strong interaction; secondary controls remain peripheral.
- Brand presence in CH16 = `LIGHT / TRACE`; Cinnabar is an editorial/detail accent, not an operational state colour.
- AI-generated images are not a default production input. Existing/current C04 assets are inspected and reused/currentized first.
- `ODB-02 / 可拆卸倚靠休息板.png` is prohibited from every CH16 visible role: MAIN, support, thumbnail, crop, zoom, carousel, source/evolution or appendix.
- The derived `P02_railing_lean_rest_v1_2.svg` is a technical/currentization carrier only; it does not replace upstream source authority and is not automatic MAIN KEEP.

## CH16-P02｜平面与定位：先证明为什么需要落位

### Page claim
**落位首先是一个“是否介入”的判断，而不是先画一个点。**

### First visual
A large **RELATIONAL PLAN / DECISION FIELD**, explicitly `NOT SITE SURVEY / LOCATION OPEN`.

It shows only the relations needed to decide intervention: `PATH / VIEW / SHORT-RECOVERY ZONE / EXISTING FACILITY / MAINTENANCE ACCESS / RETURN FLOW / NO-INTERVENTION OPTION`.

### Visual composition
- One dominant relational plan, not a mapped exact site plan.
- Route/landscape context may appear only as a small locked-reference strip; no new pin or coordinates.
- Three state overlays use the same base geometry:
  1. `NO INTERVENTION` — existing condition sufficient / view and flow remain untouched.
  2. `SHORT SUPPORT` — limited body-support envelope without blocking path/view/return.
  3. `CONFLICT` — maintenance, passage, view or Return conflict makes the intervention invalid.
- Evidence-state tags remain attached to the geometry: `SOURCE-GROUNDED / INFERRED / ASSUMPTION / FIELD OPEN`.

### Interaction
One three-state switch: `NO INTERVENTION ↔ SHORT SUPPORT ↔ CONFLICT`.

The base plan never changes identity; only the decision overlay changes.

### Required content
- What body/service problem occurs here?
- Are existing facilities already enough?
- Is no intervention better?
- Does it block view, path, maintenance or Return?
- What is the location-evidence level?

### Forbidden
- precise coordinates / survey geometry / invented topography.
- locating P02 at R06 by implication.
- equal checklist cards replacing the plan.
- reopening R06 experience design.

## CH16-P05｜连接与可逆性：从母图进入注册节点

### Page claim
**连接必须能被顺序读懂，也必须能回到母图。**

### First visual
`PARENT → REGISTERED D01 CHILD → STATE SEQUENCE`.

The parent is the P03 registered section/elevation relation. The child keeps stable anchors, orientation, sidedness and component order.

### Visual composition
- Start with parent and D01 callout.
- Enter a full-frame child detail; do not crop it into an isolated “pretty node”.
- Then step through conceptual state-changing actions with stable part IDs:
  1. `ALIGN` — contact/replacement component aligned to interface.
  2. `ISOLATE / SEAT` — buffer / isolation layer established.
  3. `CLAMP / LOCK` — reversible clamp/fastener relation shown conceptually.
  4. `CHECK / RELEASE` — inspection and removal path shown.
- `1200 / 975` may appear only in the appropriate elevation relation; `160` only in side view. All remain `DESIGNER ESTIMATE / NTS / FIELD OPEN`.

### Interaction
Step-through sequence; each state has one dominant action. `RETURN TO PARENT` is always available.

### Required content
- component IDs.
- joint / reveal / setback / termination.
- buffer/isolation.
- reversible clamp / fastener.
- replaceable component.
- escalation note: drilling / welding / permanent foundation / chemical anchors = `FIELD + ENGINEERING OPEN` unless later verified.

### Forbidden
- all parts exploded simultaneously as the only explanation.
- changing camera/orientation between states without registration.
- torque / anchor / load certainty not supported by evidence.
- child detail that silently changes parent geometry.

## 4｜Page-level review attacks before any KEEP request

Every produced page must survive:
- `FIRST-READ`: can the dominant claim be understood before reading notes?
- `RESOURCE-DOMINANCE`: is the current C04 resource visually authoritative, or flattened into equal cards?
- `THUMBNAIL`: does the dominant resource/relationship remain legible at distance?
- `NEAR-READ`: are dimensions, component IDs and notes readable without crowding?
- `CROP-ATTACK`: does any focus/crop become a replacement resource?
- `RETURN-TO-WHOLE`: can the viewer recover the complete source/drawing after interaction?
- `REGISTRATION`: can every child/detail return to an exact parent position/orientation?
- `BODY-ACTION`: do human figures carry action/interface/flow/maintenance information?
- `TRUTH-BOUNDARY`: are FIELD/engineering uncertainties visible without becoming the headline?
- `NO-DASHBOARD`: would the page still work if all cards/pills/status chrome were removed?

Producer may record `EXECUTED / SELF-CHECKED / REVIEW PENDING / REVISE / REJECT`. Producer does not assign `PIXEL KEEP / MAIN KEEP / PROFESSIONAL FINISH PASS`.
