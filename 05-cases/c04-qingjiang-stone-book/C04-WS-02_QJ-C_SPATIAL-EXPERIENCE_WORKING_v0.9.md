## 01｜QJ-C06 Service / Accessibility / Recovery Contract v0.7

### Service hierarchy

`Safety / Return → Direction / Route → Recovery / Human Support → Observation → Explanation → Memory`

Service is part of the primary experience, not a back-office patch.

### Route certainty contract

Every route version must be able to answer:

- where the visitor is in the journey;
- main direction and return direction;
- whether the journey continues when a page is closed or skipped;
- whether shortening / retreat is possible;
- which service information requires human support or verified live data.

No pseudo-live timetable, weather, opening status, or remaining-time display is permitted without an official operating interface.

### Recovery contract

Recovery does not define a fixed interval and does not presume new furniture. It has three responsibilities:

1. allow bodily recovery;
2. not obstruct primary circulation;
3. return attention to real landscape / route after recovery.

The removable railing-leaning rest board remains `KEEP / HIGH PRIORITY SUPPORT / FIELD + ENGINEERING REQUIRED`, but no location is selected.

### Accessibility overlays

All of the following remain `G1F OPEN`: slope, steps, clear width, handrail / guardrail condition, stopping position, bypass / retreat, wet-surface risk, and bypass completeness after any physical intervention.

Before evidence closure, do not claim an accessible route, verified senior route, or verified low-load route.

### No-phone / weak-network contract

- Route / Return: physical wayfinding + human support are foundational.
- Observation: Landscape → one site prompt → paper → human → digital.
- Understanding: site diagram / paper / human first; digital reveal only where necessary.
- Memory: light recording on site; expand My Stone Book / photo / merchandise / sharing after departure.

### Environmental / capacity downgrade

- Fog: move to near-view / appearance-disappearance / sound / humidity; do not fake the missing distant view.
- Rain: downgrade content; prioritize Safety / Surface / Near-view.
- Strong light: reduce fine text and screen dependence; prioritize outline and direction.
- Peak crowd: remove Deep Read from bottlenecks and move depth to wider areas or post-visit.

## 02｜QJ-C07 Route × Service Failure Matrix v0.8

### Failure-tolerance principle

A complete experience is defined as the preservation of critical relationships, not fixed-node completion.

- Content / Companion Page failure must not break the route.
- Digital failure must not break Route / Return / Safety.
- Physical Hero must be bypassable.
- Service / Return / Safety uncertainty forces content downgrade.

### Failure levels

- `F1 Content Degradation`: content, digital, memory may fail; route remains complete.
- `F2 Experience Degradation`: some space / view / physical layer may fail; allow shortening or substitution while preserving Safety + Route + Return + at least one real observation relation.
- `F3 Journey Blocking`: Safety / Return / base circulation uncertain; do not present the journey as normal operation.

### Context responses

1. Page closed / skipped → continue route; no 13/13 penalty.
2. Fatigue / time shortage → Deep → Observe / Glance; allow shortening / retreat.
3. Weak network / no phone → physical + human + paper fallback.
4. Rain / wet surface → safety first; avoid forced dwell or active physical hero.
5. Fog → near-view / atmosphere fallback; no simulated clear-weather replacement.
6. Strong light → high-readability direction and outline.
7. Peak / group crowd → remove deep reading from bottlenecks.
8. Physical intervention unavailable → bypass; original route remains primary.
9. Return-window pressure → stop opening new deep-reading states; Return > Memory.
10. Narrow closure area unavailable → close truthfully; use only evidence-backed alternative closure / re-view position.
