## 0｜Why v1.9 exists

v1.8 corrected the old abstract eight-anchor story, but it still read too much like a catalogue of project systems: Culture / Journey / Game / Audience / Physical / Digital / Memory.

The public project must now answer a different question:

> **What design decision changes the visitor's actual Qingjiang journey at this moment?**

Therefore:

- public storytelling is organized by **one real journey**, not by department/system taxonomy;
- the former N1/N2/N3 three axes remain useful as **content indexing and editorial checks**, but no longer define public chapter order;
- governance, FIELD/G1F, versioning and evidence labels remain truth boundaries, not public headlines;
- Technical Proof follows a design decision; it does not lead the story;
- 52 Web semantic surfaces remain a no-loss inventory/carrier, not 52 equal public pages and not 13 equal chapters.

Hard editorial test for every public surface:

> **“这个设计决定是什么？”**

If a surface only proves the project is rigorous, it moves to `SUPPORT / TECHNICAL / PROCESS / APPENDIX`.

## 1｜Public project definition

### Main statement

**《清江石书》把一次真实的清江游程，设计成一套可以自由进入、随时退出、无需完成任务的山水探索体验。**

游客先在水上、空中和山中建立对清江的整体认识；沿途需要时，再打开一页地方故事、自然观察、身体互动或个人记忆。地图、数字界面、纸图和实体设施都服务于游程，不取代真实景观，也不把十三印变成十三个任务站。

### Hero

> **先游清江，再读清江。**
>
> **水上看，空中看，山中走；需要时，再打开一页清江。**

Public first read must be real Qingjiang / journey / body, not governance, matrix, technical proof or App dashboard.

## 2｜The public story is one journey

Public sequence is no longer `Culture → Journey → Audience → Product...`.

It becomes:

`ENTER QINGJIANG → CHOOSE HOW TO MOVE → CROSS / OPEN THE LANDSCAPE → WALK / DISCOVER → STOP / OBSERVE / RECOVER → PASS / WITHDRAW → RETURN → REMEMBER`

This is an editorial spine, not a mandatory visitor route. Real route authority remains the current locked route/spatial source.

### Current journey binding

- `ROUTE-03` = current locked Route object for downstream public binding.
- `JOURNEY-04` = provenance / non-current for public route authority.
- BOAT / CABLE / WALK describe three **experience scales**; they must not be written as invented live service promises.
- Return / retreat / no-phone fallback remains accessible throughout the journey.

## 3｜Eight public design decisions

These are the public design decisions. They are not eight mandatory pages; one decision may occupy several surfaces and several decisions may coexist in one scene if hierarchy remains clear.

### D01｜先让清江成为主角

**Decision:** Real Qingjiang is the first visual and spatial read. Interpretation arrives only after the landscape/body relation is understood.

Public consequence:
- Hero, R06 and major journey moments begin with landscape or body-in-landscape;
- maps, diagrams, UI and text are subordinate until they materially help orientation or understanding;
- model/technical graphics never replace real Qingjiang as project identity.

### D02｜把游程设计成三种尺度的切换

**Decision:** BOAT / CABLE / WALK are not three content chapters; they are three ways of seeing the same Qingjiang.

- `BOAT` — river scale / long view / sound / reflection;
- `CABLE` — transport first / moving cross-river view / whole-valley orientation;
- `WALK` — body scale / branching path / close observation / rest.

The route/game map makes these relations legible without turning navigation into a quest chain.

### D03｜十三印沿途出现，但不定义路线

**Decision:** R01–R13 remain the complete optional reading/content library, but they do not own route order and do not require 13/13 completion.

Public consequence:
- visitors may `LOOK / COMPARE / TRACE / LISTEN / WAIT / FRAME / STEP / REMEMBER`;
- a scene can be entered, read lightly, read deeply or skipped;
- content markers never gate safety, service or Return;
- R01 moving-view moments stay light; R13 high-attention play stays OFF.

### D04｜不同场景使用不同注意力

**Decision:** The project does not apply the same interaction density everywhere.

Use three scene intensities:

1. `LANDSCAPE FIRST` — view dominates; intervention is minimal;
2. `READ / RECOVER` — the visitor may stop, compare, rest or open a deeper layer;
3. `PASS / RETURN FIRST` — body, route and safety dominate; new tasks withdraw.

Examples:
- `R06` = Landscape First → optional spatial/science reading → short recovery; R06 is finished/frozen and is not reopened for new design content.
- `R13` = passage first → exit view → Return; memory happens after exit, not inside the constricted passage.
- `R01` = transport/moving view first; no forced UI or long explanation.

### D05｜数字体验是一名隐性助手，不是第二个景区

**Decision:** App/Digital helps visitors orient, choose, read and remember, then withdraws when the real landscape is stronger.

Stable public functions:
- `TODAY｜今日清江` — current visit/service orientation without pseudo-live certainty;
- `ROUTE｜探索地图` — route/world relation, optional discovery, Return always visible;
- `READ｜十三印 / 场景内容` — layered reading only when the visitor asks for it;
- `MY BOOK｜我的石书` — personal route/scene/memory, not completion score;
- Service / Return remains always accessible;
- Offline/no-phone route, paper and human service remain complete in parallel.

Do not narrate NORMAL/DEGRADED/CLOSED/UNKNOWN or FULL/LIGHT/OFF as public chapters. They are behavioral constraints inside the product.

### D06｜实体设计只在身体真正需要时出现

**Decision:** Physical intervention is not a collection of installations. It appears only where the body needs to lean, pause, recover, sense or understand a relation that landscape alone cannot provide.

Current selection discipline:
- railing / removable leaning-rest lineage = `KEEP / HIGH-PRIORITY SUPPORT / NOT LOCATED`;
- `PHY-01 步步生光` = `KEEP CONCEPT / HOLD SELECTION / PROCESS-SUPPORT`;
- Mountain Fluid Rest = `HOLD / SINGLE-SITE COMPETITION`;
- `清风吟` = `HOLD / WIND-SENSORY CANDIDATE`;
- C23/Model details are proof for selected objects, not proof that every physical concept is selected.

Public storytelling may show HOLD/DROP decisions as professional design judgment in Process, but must not visually promote them to built/current MAIN objects.

### D07｜同一场景，为不同人提供不同深度

**Decision:** Audience design changes action depth and support inside the same Qingjiang scene; it does not create separate persona products.

Examples:
- family/child: discover together, compare shapes/sounds, low text;
- explorer/youth: route reading, spatial comparison, light challenge;
- adult/deep reader: culture/landscape explanation on demand;
- older/low-stamina: route certainty, large clear information, rest and Return first.

Audience logic must be shown through **what changes in the scene/action**, not persona cards or matrices.

### D08｜用回程完成故事，用记忆带走清江

**Decision:** The experience closes through route re-recognition and personal memory, not a 13/13 score.

Current memory hierarchy:
- `清江旅记` = physical Memory MAIN candidate;
- `我的石书` = digital memory hero;
- `清江一线 / 清江雾气 / 清风吟 memory extension / 红花峰崽` = selective support/extensions subject to their own current pixel/form authority.

Return is a designed final layer:
`recognize the way back → reduce interaction → recover landscape → record selected moments → leave with a personal version of Qingjiang`.

## 4｜Where Culture goes now

Culture remains essential, but **Culture is no longer a standalone explanatory block that precedes the journey**.

Use culture only where it changes what the visitor notices or does:

- place name / local story → the visitor compares a name/story with the landscape;
- landscape knowledge → the visitor observes/compares before explanation;
- traditional landscape view → presented as cultural interpretation, never scientific causation;
- craft/intangible culture → enters only when a scene/medium/action is materially connected;
- wellbeing/local wisdom → pacing/rest/quiet observation/return support, never medical or selenium-health claims.

Internal indexing may continue to use:
`HISTORY / LOCAL STORY / CRAFT / LANDSCAPE KNOWLEDGE / TRADITIONAL LANDSCAPE VIEW / DAILY WISDOM`.

Public page titles should describe the **scene or decision**, not the taxonomy.

## 5｜Scene examples become the proof of the story

### R06｜先看完整河谷，再选择是否读深

Design decision:
> Keep the valley as the primary experience; add explanation and short recovery only after the landscape is legible.

Public order:
`LANDSCAPE → BODY/PATH RELATION → OPTIONAL READ → RECOVER → CONTINUE / RETURN`

Technical section/model appears after the experiential decision and proves only relative spatial/assembly logic within its evidence boundary.

### R13｜通过本身就是体验

Design decision:
> In a constricted/high-attention passage, stop adding tasks. Let body, light, exit view and Return carry the experience.

Public order:
`BEFORE → PASS → EXIT → BACK-LOOK / RETURN`

No chase/search/AR mission/long reading inside the passage.

### Return｜最后重新认出清江

Design decision:
> The final experience is not “completion”; it is re-recognition of route, landscape and selected personal traces.

Public order:
`RETURN CERTAINTY → LANDSCAPE AGAIN → JOURNAL / MY BOOK → OPTIONAL MEMORY OBJECT`

## 6｜Web / portfolio editorial rule

The current Web lineage contains **52 visible semantic surfaces**. v1.9 does not delete that inventory and does not impose a new target count.

For every surface assign exactly one primary editorial role:

- `MAIN_DECISION` — shows a visitor-facing design decision through actual scene/product/spatial effect;
- `SUPPORT_EVIDENCE` — proves a MAIN decision with source, comparison or secondary system;
- `PROCESS_JUDGMENT` — shows why a concept was kept, revised, held or dropped;
- `TECHNICAL_PROOF` — plan/section/detail/model/behavior proof after the design decision;
- `ARCHIVE` — provenance only.

### MAIN surface rule

A MAIN surface must answer:

1. **What changed for the visitor?**
2. **What is the visible design decision?**
3. **Which actual current object/scene proves it?**

If the answer is primarily “we researched / validated / governed / created a framework”, it is not MAIN.

### Public headline rule

Do not use these as MAIN headlines:
- FIELD / G1F / Authority / Evidence Gate / State Machine / Governance / Version / Receipt;
- generic taxonomy labels such as “Audience Matrix”, “Physical System”, “Technical System” without a visitor-facing decision.

These remain visible where required, but subordinate.

## 7｜Process / Design Exploration

Process is not a graveyard. It should show **professional selection**.

Useful Process material includes, when source assets exist:
- `步步生光` — concept retained, current selection HOLD;
- Fluid Rest variants — site-fit competition / HOLD;
- `清风吟` — sensory candidate / HOLD until one useful scene and mechanism are selected;
- older completion-score / 13/13 / task-route App states — dropped because they damage route freedom and Return priority;
- old board-in-Web / dashboard-like / governance-led presentation — replaced because it explained the project more than it showed the design;
- old model/axon views — support only when weaker than landscape/linework.

A HOLD/DROP page is valid when it clearly states **what design judgment was made and why**, not merely that a gate failed.

## 8｜Technical proof rule

Technical Proof is necessary but never the project identity.

Order:
`DESIGN DECISION → EXPERIENCE / BODY EFFECT → TECHNICAL PROOF → OPEN FIELD ITEMS`

Current principles:
- C22/C23 route/plan/section/details retain their own object authority;
- model is selective proof; real Qingjiang > grey model;
- R06 technical work does not reopen the frozen R06 experience design;
- exact geometry, safety, accessibility, capacity, mounting/foundation and construction claims remain within their owner/evidence state.

## 9｜Cross-media binding

All media use the same journey-led narrative, with different depth.

### Web
Use 52 semantic surfaces as an editable inventory. Reweight, merge in reading flow, expand, or demote by role; do not destroy underlying design objects to make the site shorter.

### Boards / PDF
Lead with Qingjiang + journey + selected scene decisions. Technical/evidence proof follows; governance moves to small boundary fields / appendix.

### Film
Motion should feel like a journey:
`ENTER → MOVE → OPEN → WALK/STOP → PASS → RETURN → REMEMBER`.
Do not revert to abstract relation/reveal/withdrawal slides or a contact-sheet montage.

### App
Show product behavior inside the journey, not as an isolated product-spec chapter.

### Process
Show meaningful alternatives, HOLD/DROP decisions and iteration only when they explain design judgment.

## 10｜Truth boundary

The public story becomes more experiential; the truth boundary does not loosen.

Still locked:
- `FIELD OBSERVED=0`
- `FIELD MEASURED=0`
- `G1F HOLD`
- `NO_PROMOTION`
- `NTS / NOT FOR CONSTRUCTION` where applicable
- UNKNOWN never shown as OPEN/NORMAL
- no invented live operations / GPS / safety approval / exact survey / construction certainty
- local legend ≠ historical-site proof
- traditional landscape view ≠ scientific causation
- wellbeing ≠ medical/health-effect claim
- AI/concept visualization ≠ site photo / field proof

These constraints appear as captions, proof notes, technical boundary fields or appendix — **not as the main public story**.
