02 / INFORMATION & WAYFINDING

图标构造

24px 是最低动作识别压力测试；轮廓和关节负空间优先。

READ 24×24 / 2px strokeBOUNDARY 小尺寸可读性具有否决权。
03 / INFORMATION & WAYFINDING

核心图标库

12 个基础语义覆盖 Return、Route、Service、Observation、Reading。

READ 12 editable SVG pictogramsBOUNDARY 图标存在不证明现场服务存在。
04 / INFORMATION & WAYFINDING

方向箭头

箭头形式可统一，但具体方向必须由真实节点 / Source Authority 赋值。

READ Direction = actionBOUNDARY 品牌手册不虚构现场方向。
05 / INFORMATION & WAYFINDING

节点分类

路线节点、关键锚点、可选阅读和 Return 决策分开编码。

READ Role before icon identityBOUNDARY R01–R13 不自动等于 13 个地图节点。
06 / INFORMATION & WAYFINDING

图例系统

线、点、状态、服务先按类别建立关系，再读名字。

READ Redundant encodingBOUNDARY 颜色不是唯一信息通道。
07 / INFORMATION & WAYFINDING

运营状态

NORMAL / DEGRADED / CLOSED / UNKNOWN 使用形状 + 文本 + 色彩冗余。

READ UNKNOWN never looks normalBOUNDARY 状态色不等于品牌综合色。
08 / INFORMATION & WAYFINDING

导视决策

移动中的第一眼只能有一个最高优先动作；Return / Service 压过可选解释。

READ Decision priority → graphic priorityBOUNDARY 示例不声明真实现场方向。
09 / INFORMATION & WAYFINDING

服务矩阵

服务项由图标、名称、动作、状态与 Source Owner 五层共同定义。

READ Semantic + action + state + sourceBOUNDARY 未绑定来源的服务保持 UNKNOWN。
10 / INFORMATION & WAYFINDING

纸图

纸图必须在无手机、无 GPS 情况下独立完成定向与 Return。

READ Offline-first paper mapBOUNDARY 不是 App 截屏的打印版。

App 信息判读

App 与纸图共享语义对象，但允许交互、局部展开和状态入口不同。

READ Shared semantics / different layoutBOUNDARY 此页不替换当前 App Authority。
