# C04｜Design Invariants｜PERMANENT

Project: `PRJ-C04-QINGJIANG-SHISHU`  
Scope: **ALL C04 subtasks / all lanes / all media / all future currentization**  
Status: `PERMANENT DESIGN INVARIANTS`  
Change rule: these invariants may only be changed by an explicit later user decision that names the invariant being changed. A subtask, PR, technical package, visual revision, Web/F edit, feature freeze, or temporary working scope cannot silently override them.

---

## 0｜Inheritance contract

Every C04 subtask must carry all five blocks below simultaneously:

1. `PROJECT IDENTITY`
2. `DESIGN SOURCE`
3. `DESIGN DNA`
4. `FULL DESIGN UNIVERSE`
5. `CURRENT DELTA`

A subtask may edit only a small delta, but it still inherits the complete C04 project universe.

> **`CURRENT DELTA ≠ PROJECT SCOPE`**  
> **`NOT EDITED THIS ROUND ≠ DOES NOT EXIST`**  
> **`NOT SHOWN IN THIS ARTIFACT ≠ REMOVED FROM C04`**  
> **`VALIDATION SUBSET ≠ WHOLE PROJECT`**

If a subtask says `CURRENT DELTA = App only`, this means only the App is being edited in that round. Landscape, Journey, Thirteen Imprints, Scene Interaction, Audience, Physical/Sensory, Memory/IP, Technical, Narrative, Visual/Motion and Return all continue to exist and remain part of C04.

## 2｜DESIGN SOURCE

The primary **design source / design motherboard** is:

> **the original C04 presentation boards and their mature design outcomes.**

Later technical, evidence, validation, App-prototype, Web, Model, C22/C23, F or governance files may:

- currentize;
- redraw;

They may **not** silently redefine the project by omission or replace the mature original design source merely because they are newer or more structured.

Working order:

→ `LATEST AUTHORITY / EVIDENCE / FIELD BOUNDARY`

## 3｜DESIGN DNA

The following characteristics must remain recognizable across every C04 medium and subtask:

### 3.1｜真实清江优先 / REAL QINGJIANG FIRST
Real Qingjiang landscape, route, body experience and verifiable local context outrank invented scenery, generic tourism graphics, grey models, AI atmosphere and abstract explanation.

### 3.2｜Landscape First
The visitor first encounters landscape / route / bodily situation. Explanation, digital overlays and content appear only when they add value.

### 3.3｜纸 / 墨 / 线 / 印
Paper / ink / line / seal form the project’s editorial and visual grammar. They should be currentized professionally rather than turned into decorative pseudo-traditional styling.

### 3.4｜实体与数字互补
Physical and digital systems complement each other. Digital can appear, reduce or disappear by context; the route, safety, service and Return must still work without a phone.

### 3.5｜十三印是内容系统
R01–R13 are a complete optional content / reading / interpretation system. They are not a mandatory linear route, 13-stop task chain, completion score, or route authority.

### 3.6｜身体与空间真实成立
Body posture, movement, rest, view, passage, scale, maintenance and spatial relationships must be credible in real space. Text, diagrams, UI and technical evidence cannot substitute for a body-space relationship that does not actually work.

### 3.7｜Return闭环
Return is an independent design layer and part of the experience closure. Route/service/recognition must remain available throughout the journey.

### 3.8｜Memory / IP 作为旅行余韵
Memory/IP extends selected real journey variables after the visit. It is not a compulsory souvenir checklist or a generic merchandise layer.

Current closure logic:

`RETURN → RECOGNITION → RECORD → TAKE AWAY`

## 5｜CURRENT DELTA

Every C04 subtask must explicitly state what it is changing **this round only**.

Required form:

```text
CURRENT DELTA:
- EDITING NOW: <object / system / question>
- NOT EDITING THIS ROUND: <other systems remain inherited, not removed>
- DOES NOT CHANGE: PROJECT IDENTITY / DESIGN SOURCE / DESIGN DNA / FULL DESIGN UNIVERSE
```

Example:

```text
CURRENT DELTA:
- EDITING NOW: App / Game Map currentization only.
- NOT EDITING THIS ROUND: Landscape, Journey, 13 Imprints, Scene Interaction, Audience,
  Physical/Sensory, Memory/IP, Technical, Narrative, Visual/Motion and Return remain current C04 systems.
- DOES NOT CHANGE: PROJECT IDENTITY / DESIGN SOURCE / DESIGN DNA / FULL DESIGN UNIVERSE.
```

A subtask must not infer that an unedited system is absent, obsolete, demoted or deleted.

## 6｜Removal / demotion rule

If any existing C04 design is genuinely removed or reduced, that action must be explicit and separate from `CURRENT DELTA`.

Allowed actions only:
- `DEMOTE TO SUPPORT`
- `DEMOTE TO PROCESS`
- `HOLD / FIELD OPEN`
- `CUT`

Each action must name a concrete design reason, such as:
- genuine redundancy;
- conflict with experience;
- generic / non-Qingjiang specificity;
- visually insufficient after fair redraw/currentization;
- evidence / truth conflict;
- harmful to visitor experience;
- materially / spatially / technically infeasible at the current stage;
- replaced by a demonstrably stronger object while provenance is retained.

The following are **not valid reasons by themselves**:
- page too long;
- website too long;
- board does not fit;
- want it cleaner;
- want fewer chapters;
- minimalism;
- this round is focused on something else.

## 7｜Quality rules remain simultaneous

These invariants preserve the complete project, but they do **not** force weak pixels into MAIN.

Always keep the separate quality rules:

> **`Artifact existence ≠ Design quality`**  
> **`Traceability ≠ Professional finish`**  
> **`Evidence correctness ≠ Visual excellence`**  
> **`Process PASS ≠ MAIN KEEP`**

And:

> **`CONCEPT KEEP ≠ PIXEL KEEP`**  
> **`PIXEL FAIL ≠ DESIGN DELETE`**

Therefore an original design can remain part of the full design universe while its current presentation is `REDRAW`, `SUPPORT` or `HOLD`.
