# CH10 v0.4｜Method Bindings

## Why this reorganization exists
The previous flat R01–R13 table was too close to a complete checklist. Current project knowledge instead requires a hierarchy of evidence, attention, bodily state and recoverability.

## Bound methods
1. **CH03 — Content selection**
   `CONTENT SOURCE → QINGJIANG RELEVANCE → PERCEIVABLE NOW → CHANGES LOOK/ACTION → SCENE FIT → IMPRINT`
2. **CH04 — Use-state**
   `CONDITION → NEED → DESIGN RESPONSE`; same scene, variable depth/support, same Return.
3. **CH05 — Journey / attention**
   `JOURNEY PHASE × BODY × ATTENTION × ACTION = DESIGN NEED`.
4. **CH06 — Design principles**
   `LANDSCAPE → RELATION → OPTIONAL EXPLANATION → MEMORY`;
   `SERVICE/RETURN > ROUTE > OBSERVATION > EXPLANATION > MEMORY > SHARE`.
5. **CH07 — Generation chain**
   `PROBLEM → EXISTING CONDITION → NO DESIGN → REUSE → MINIMUM SUFFICIENT CARRIER → NEW OBJECT IF NEEDED → ATTACK TEST`.
6. **CH08 — Master strategy**
   `PRIMARY ENCOUNTER BEFORE CONTEXT`;
   `SPATIAL ORDER ≠ FORCED SEQUENCE`;
   `CORRECT ABSENCE`;
   `ENCOUNTER → ORIENT → CHOOSE → OBSERVE → OPTIONAL REVEAL → RECOVER/CONTINUE → WITHDRAW/RETURN → RECOGNIZE → RECORD`.
7. **Earned Attention**
   current task and Return outrank supporting chrome/content.
8. **Same-source Paired View**
   Reveal uses the same authoritative base; add only bounded relation, never redraw evidence.
9. **Prompt ↔ Media Semantic Binding**
   demanded objects/relations/actions must be visible or explicitly unknown.
10. **Service Design / Failure & Recovery**
   every ideal interaction must also define skip/closed/unknown/fatigue/recovery behavior.
11. **CH13 ownership boundary**
   CH10 may specify a body need but does not own physical object design. Physical escalation is a separate owner decision.
