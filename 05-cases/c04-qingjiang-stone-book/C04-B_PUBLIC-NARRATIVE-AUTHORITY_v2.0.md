## 0｜Correction

The project must not be reduced to a single portfolio story.

`先游清江，再读清江` remains the strongest first-read proposition, but a professional design project must also make visible:

- why the design exists;
- what was analysed;
- what principles were derived;
- what design methods were used;
- how different users were considered;
- how the route, scenes, digital, physical and memory systems work;
- how key designs were developed in plan / section / model / interface / material / state;
- why some alternatives were selected, held or dropped;
- what remains open because field evidence is absent.

Therefore the narrative is now **layered, not compressed**.

Hard rule:

> **First-read clarity does not justify information loss.**  
> **Analysis is not governance.**  
> **Design reasoning, user analysis and design detail may be MAIN content when they materially explain the design.**

FIELD / G1F / Authority / Receipt / CI / versioning remain subordinate truth-boundary information. They are not the same thing as site analysis, audience analysis, design principles, design methods or technical design development.

### L2｜CONTEXT + ANALYSIS｜背景与分析

Analysis is allowed to be visually prominent when it changes a design decision.

Required analysis families, using existing evidence where available and clearly marking open items:

1. **Regional / landscape context**
   - river / valley / peak-forest relation;
   - north-south bank relation;
   - arrival / transport / walking network;
   - real multi-branch / loop route character;
   - scenic sequence and spatial compression / opening.

2. **Culture / content analysis**
   - regional history;
   - local stories and place names;
   - intangible culture / craft;
   - landscape knowledge;
   - traditional landscape view as cultural interpretation;
   - daily wisdom / wellbeing as experience, not medical claim;
   - content-source → scene-fit analysis.

3. **Journey / mobility / service analysis**
   - arrival;
   - BOAT / CABLE / WALK experience differences;
   - route choice;
   - service / rest / retreat / Return;
   - no-phone fallback;
   - route states and closure logic where relevant.

4. **Audience / people analysis**
   - children / family;
   - youth / explorer;
   - adult / deep-read;
   - older / low-stamina;
   - body condition, attention, cognitive load, reading depth, interaction difficulty and Return priority;
   - same-scene differences rather than decorative persona cards.

5. **Behavior / interaction analysis**
   - LOOK / COMPARE / TRACE / LISTEN / WAIT / FRAME / STEP / REMEMBER;
   - where attention can increase;
   - where interaction must reduce;
   - where body / route / safety takes priority.

6. **Environmental / operational analysis**
   - seasonal / weather / visibility where supported;
   - route state NORMAL / DEGRADED / CLOSED / UNKNOWN;
   - FULL / LIGHT / OFF behavior;
   - risk / recovery / accessibility / capacity / maintenance as scenario or open-field analysis where evidence permits;
   - never convert remote analysis into field certainty.

A useful analysis page may remain MAIN if it clearly changes the project design. A purely evidentiary or governance page remains SUPPORT / TECHNICAL / APPENDIX.

### L3｜DESIGN PRINCIPLES + METHODS｜设计原理与设计方法

The project must explicitly show **how design decisions were generated**, not only the outcomes.

#### Current design principles

1. **Real Qingjiang First** — landscape and body relation before explanation.
2. **Service / Return before content completion** — route certainty and recovery outrank game progress.
3. **Three scales of experience** — BOAT / CABLE / WALK read the same Qingjiang at different scales.
4. **Optional content, not mandatory stations** — Thirteen Imprints are openable content, not route authority.
5. **Scene-specific attention density** — not every scene gets the same amount of UI, text, play or intervention.
6. **Digital retreatability** — digital appears when useful and withdraws when landscape / body / Return is stronger.
7. **Minimum necessary physical intervention** — physical design appears where body, recovery, reading or Return genuinely needs support.
8. **Same scene, different depth** — audience differences are handled through depth and support, not duplicated products.
9. **Landscape → relation → explanation** — especially in R06, the whole landscape precedes interpretive proof.
10. **Return + memory, not completion score** — the project closes through re-recognition and memory rather than 13/13 completion.

#### Current design methods

Methods may be shown as independent design-method pages when they are visually and intellectually useful:

- `Evidence → Spatial Finding → Design Consequence`;
- `Visitor Situation → Action → Content / Interaction Mode → Carrier → Value → Fallback`;
- `Landscape First → Relation Reveal`;
- `Scene × Attention Density × Audience Depth`;
- `Concept State ≠ Pixel State` for design selection;
- `Existing / Minimal Intervention / Hero Intervention` comparison where relevant;
- `NORMAL / DEGRADED / CLOSED / UNKNOWN × FULL / LIGHT / OFF` as behavior method, not public dashboard;
- `Physical + Digital + Paper + Human Service` redundancy / retreatability method;
- `Design Decision → Experience / Body Effect → Detail / Technical Proof → FIELD OPEN`.

Design methods must be concrete and tied to actual C04 examples. Generic methodology diagrams without project consequence should not occupy MAIN.

## 3｜Page / surface rules by content type

The v1.9 universal rule `every MAIN page answers only “这个设计决定是什么？”` is too narrow and is replaced.

Different page types answer different professional questions:

### STORY / EXPERIENCE page
- What does the visitor experience here?
- What design decision shapes it?

### ANALYSIS page
- What did we learn?
- Why does it matter spatially / behaviorally / culturally / operationally?
- What design consequence follows?

### PRINCIPLE / METHOD page
- What principle or method is being used?
- Which C04 decisions demonstrate it?
- What does it prevent or enable?

### SYSTEM page
- What does this design system do?
- How does it interact with route / scene / user / other carriers?

### AUDIENCE page
- What changes for different people in the same real scene?
- What changes in action, depth, support and Return priority?

### DETAIL page
- How does the design actually work?
- What are its body / spatial / interface / material / construction relations?

### TECHNICAL page
- What part of the design does this prove?
- What remains open?

### PROCESS page
- What alternative was considered?
- Why was it selected / held / dropped?
- What professional judgment did that create?

No page is promoted merely because it is rigorous. No page is demoted merely because it is analytical.
