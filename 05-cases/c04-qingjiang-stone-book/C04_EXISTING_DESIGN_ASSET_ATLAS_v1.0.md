## 0｜Why this atlas exists

This atlas corrects a loss-of-design error in later integration work. The late-stage evidence / validation / minimum-service subsets are **not** the complete project.

Hard rule:

> **`CONCEPT KEEP ≠ PIXEL KEEP` and `PIXEL FAIL ≠ DESIGN DELETE`.**

A legacy/current image may fail the Public Quality Gate and require redraw, while the underlying design concept remains part of C04. A technical validation subset (for example C23 F01/F02/F03) may deepen a few objects without replacing the wider existing design universe.

Before any Web / F / D edit, all existing design objects below must be classified separately by:
- `CONCEPT STATE`: KEEP / CURRENTIZE / REVISE / COMPETE / HOLD / DROP;
- `PRESENTATION STATE`: MAIN / SUPPORT / PROCESS / REDRAW / NOT-YET-SHOWN;
- `TRUTH STATE`: source-grounded / design candidate / field-open / provenance.

No asset is removed from the project simply because an old image, UI, board or implementation assumption is outdated.

## 4｜NO-LOSS execution rule

Before deleting, demoting or rebuilding any asset in Web / boards / film:

1. identify its `asset_id` in this atlas;
2. judge `CONCEPT STATE` separately from `PRESENTATION STATE`;
3. if pixels/UI/board are stale but concept is valuable, use `CONCEPT KEEP / PIXELS REDRAW`;
4. only use `CONCEPT DROP` when an actual design review finds the concept redundant, harmful, generic, or incompatible with the journey — never because later governance/validation happened to omit it;
5. any successor Web/F package must visibly represent all major systems: `Journey + 13 Imprints + App + Physical + Memory/IP + Audience + Technical Proof`, with different weights, not equal page counts.
