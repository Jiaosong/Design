## 1. Why the experiment changed

The first A/B/C round assumed that a lecture-style card could function as the practical baseline. That is not sufficient once current public evidence is considered.

A 2024 Quzhou College of Technology institutional report states that Guangdu already had route markers, signs, a guide map, repaired stone paving and other tourism-infrastructure work. The same report states that an earlier innovation-station team had distributed 350 questionnaires and conducted focused interviews with more than 50 villagers, and that nine universities had entered Guangdu for research/planning through the 2023 provincial rural-revitalization competition.

These are **source claims**, not OLEANDER field measurements. They nevertheless reject the idea that C01 is entering an empty site with no interpretation system or previous research.

Therefore the valid question becomes:

> Can OLEANDER add a distinct evidence / comparison / question / interpretation-right mechanism on top of an existing tourism and research layer, rather than making another guide system or repeating prior research?

## 2. A is now A0 + A1

### A0 — Existing Interpretation Baseline

Capture what is actually present in 2026:

- route marker;
- directional sign;
- guide map;
- node interpretation panel;
- QR/digital layer;
- first-reading unit;
- visible source/date/responsibility;
- current physical condition;
- actual wording and media hierarchy.

A0 must not be designed by OLEANDER and must not be assumed to be weak.

### A1 — Controlled Lecture Card

A1 is retained only as a controlled comparison using the same object, minimum fact set and approximate exposure time as B/C. It tests `complete answer first` versus `evidence/question first` without intentionally making A1 poor.

The earlier symbol-heavy A card is downgraded to `METHOD DEMO / NOT REAL BASELINE`.

## 3. C is now C1 + C2

Current 2025 local reporting describes three related historical archways at Shangmashi, Baguting and Dapandi, with one described as a zhenxiao archway and two as jiexiao archways. The Jiangshan cultural-market inspection list independently confirms Guangdu jiexiao and zhenxiao archways as inspected heritage objects, but does not close all object-level identity, coordinates or access conditions.

### C1 — Single-object deep reading

`one exact object → one visible clue → autonomous question → next person/archive/node`

C1 remains the lower-risk route.

### C2 — Comparative route

`two or more exact objects → same/different → person / institution / location / evidence difference → why different? → continue verification`

The first-reading unit is no longer `the archway form` but:

> Why are objects within the same broad commemorative type not the same?

C2 is the current lead candidate because it may turn type-symbol recognition into a relational comparison mechanism. It is still `NOT RUN`.

## 4. Adversarial rejection conditions

C2 must be revised or rejected if any of the following occurs:

1. road, traffic, heritage or stopping conditions make a multi-object route unsafe;
2. the existing guide system already performs equivalent comparison/evidence separation well;
3. participants only perform visual spot-the-difference without generating a historical/institutional question;
4. local narrators judge that the comparison creates false equivalence or flattens individual histories;
5. the route requires excessive explanatory text to work;
6. current heritage/site conditions should not encourage additional visitor stopping.

## 5. Reality Gate 2 evidence package

Only raw evidence enters the Gate 2 folder before interpretation:

- exact object identity + source record;
- current signage / guide-map photographs;
- `approach / front / pass-or-leave` capture for each tested object;
- road / traffic / stopping / drainage / protection-boundary notes;
- A0 / A1 / B / C1 / C2 anonymous raw behavior records;
- local narrator / village collective / professional correction or objection;
- raw JSON exports from the v0.2 field pack.

No `PASS / APPROVED / VERIFIED` is available at data-capture stage.
