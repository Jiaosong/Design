## 1. Existing-practice upgrade

The existing C01 learning practice already separated one topic into three prototype modes:

1. lecture / complete answer;
2. question-led observation;
3. practice / comparison / recording / collaboration.

Round 01 maps those modes to the OLEANDER T0–T4 translation framework and one real C01 node: `榜｜N03 牌坊礼序路径`.

## 2. Shared invariants

All three routes must preserve the same constraints:

- no drilling, adhesive, hanging or irreversible intervention on the heritage body;
- do not convert historical `节孝 / 贞孝` discourse into an automatic present-day value endorsement;
- do not use unsupported promotional claims as historical evidence;
- visibly separate observation, source claim, design inference and unknown;
- same low-fi task-duration basis: **6–8 minutes is an exercise assumption, not project data**;
- each participant/task must leave a comparable output rather than only a like/dislike response.

## 3. A — Symbol / Lecture Control

**Translation depth:** T0 dominant.  
**Decision role:** negative/control condition, not the preferred design route.

First-reading unit:

`榜 / archway / ritual-order explanation`

Prototype:

1. Show one compact explanation card using an archway silhouette, a short `礼序` label and minimal background text.
2. Ask: `这座牌坊代表什么？`
3. Require a one-sentence retelling.

Output:

`one-sentence retelling`

### Remove-the-symbol test

Remove the archway silhouette, pseudo-historical framing, seal-like marks and the `榜` label. If the learning structure collapses, the route remains T0.

### Round-01 result

`REJECT AS PRIMARY / KEEP AS CONTROL`

Reason: it is easy to compress differentiated historical objects into a generic symbol and to confuse accurate retelling with relational understanding.

## 4. B — Evidence / Material Reading

**Translation depth:** T1 → T2 candidate.  
**Decision role:** keep and revise.

First-reading unit:

`physical evidence → confirmed / sourced / inferred / unknown`

Prototype:

1. Do not begin with a full story.
2. Observe only visible evidence such as inscription, couplet, relief, stone surface/weathering and spatial position when that evidence is actually available.
3. Classify each statement into:
   - `I can directly observe`
   - `a source states`
   - `I infer`
   - `I do not know`
4. Read a minimal verified context note.
5. Record: `Which evidence changed my first judgment?`

Output:

`four-column evidence card + one revised judgment`

### Remove-the-symbol test

If the exercise continues to work after removing historic-style graphics and the `榜` label, the mechanism may reach T2.

### Round-01 result

`KEEP / REVISE`

Revision requirement: material observation cannot become antiquarian appreciation detached from people, institutions and present-day interpretation rights.

## 5. C — Relation / Behavior Translation

**Translation depth:** T2 → T3 candidate.  
**Decision role:** current lead candidate; site/human validation required.

First-reading unit:

`approach → observe → ask → compare → carry a question forward`

Prototype:

1. Record the first thing noticed while approaching the selected archway, without touching the heritage body.
2. Select only one real visible clue.
3. Ask two questions:
   - `这个对象当时要求谁遵守什么？`
   - `今天谁有权解释它？`
4. Create one question that cannot be fully answered at this node.
5. Carry the question to the subsequent `八股厅 / 书香研学室`, archive, local narrator or another responsible evidence source.

Output:

`observed evidence → autonomous question → next node/source → who must answer/verify`

### Remove-the-symbol test

If the behavior chain still works with no archway icon, calligraphic texture or pseudo-historical palette, the relational mechanism survives symbol removal.

### Round-01 result

`KEEP AS LEAD CANDIDATE / SITE + HUMAN TEST REQUIRED`

## 6. Reality Gate 1 — executed

Reality Gate 1 uses the current C01 Evidence Register plus current public reality checks. It is a constraint test, not a substitute for fieldwork.

### Finding 01 — `牌坊` cannot remain one abstract object

Current public records distinguish multiple Guangdu archways rather than one interchangeable `牌坊`. Therefore implementation must either:

- lock one exact archway with its own identity, location, protection/rights and evidence chain; or
- explicitly design a multi-archway comparison path where differences are part of the learning mechanism.

A generic unified archway icon cannot carry all historical claims.

### Finding 02 — heritage protection precedes interpretation hardware

Current C01 evidence can support the existence/regulatory background of relevant objects but does not close ownership, current opening conditions, protection boundary, safe stopping position or permission to install media.

Therefore the next prototype remains:

`hand-held / independent movable / digital / non-contact`

until project-specific permissions and site conditions are verified.

### Finding 03 — path conditions require a fresh survey

A 2026 Guangdu village road-hardening project is public evidence that local circulation conditions may be changing. It does not prove direct overlap with N03; it is a trigger to re-check road width, pedestrian/vehicle conflict, drainage, accessibility, stopping space and construction-period routing before fixing a visitor path.

## 8. Assumptions rejected in Round 01

1. `one traditional object = one unified symbol/story` → rejected.
2. `complete explanation = learning completed` → rejected.
3. `more traditional visual signs = deeper cultural translation` → rejected.
4. `C is logically stronger, therefore it can be adopted immediately` → rejected.

## 9. Reality Gate 2 — NOT RUN

### Site gate

Required evidence:

- exact archway identity and coordinates;
- approach direction and sight distances;
- road width and vehicle/pedestrian conflict;
- drainage and safe stopping condition;
- heritage/protection boundary and permitted media mode;
- same-viewpoint evidence sequence: `approach → front/read → pass/leave`.

### Human gate

Reuse the existing F02 age-group learning-test structure. Do not optimize for a predetermined sample number; first protect comparability and consent.

Record:

`Prototype → first noticed object → autonomous question → prompts → error/uncertainty → autonomous expression → voluntary next-node connection → local narrator correction → Keep/Reject/Revise`

Satisfaction and “interesting/not interesting” are insufficient passing criteria.
