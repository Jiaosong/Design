---

## 1｜项目是什么

「一脉广渡」是一项以文化研究与空间设计为主要维度的个人研究型设计提案。

这个项目关注的不是“先做一个视觉概念，再补故事”，而是：

> **文化线索、对象证据、空间关系、使用路径和地方解释权，如何真正进入设计判断。**

项目当前仍处于研究与提案并行阶段，因此仓库刻意保留：

- 已有事实；
- 可支持判断；
- 设计推断；
- 缺失证据；
- 尚未执行的现场／参与者验证。

它不是一个以效果图完成度作为唯一终点的案例。

---

## 2｜为什么这个项目适合观察 OLEANDER

C01 是一个典型的“研究与设计不能分家”的长期项目。

它要求系统同时处理：

- 文化资料与公开来源；
- 空间对象与路径关系；
- 方案转译；
- 原型；
- Reality Gate；
- Human Test 前置条件；
- 证据不对称；
- 设计表达与事实边界。

因此它更适合验证：

**Evidence → Interpretation → Design Decision → Prototype → Validation**

而不是单纯验证生成质量。

---

## 3｜核心问题

当前最重要的问题不是“能否再设计一套导览”，因为公开资料已经表明广渡此前存在导览设施、调研与多轮高校规划设计介入。

更准确的问题是：

> **能否在既有系统之上，形成可追溯的证据分层、对象比较、自主问题、文化解释权与后续责任链？**

这个问题直接影响项目是否只是“重复做已有内容”，还是形成新的设计价值。

---

## 4｜当前设计／验证链

```text
Public / Existing Evidence
→ Object Identity
→ Existing Baseline
→ A/B/C Translation
→ Prototype
→ Dry-run
→ Remote Preflight
→ Reality Gate
→ Human Test
→ Evidence Upgrade / Hold
```

当前状态没有因为“流程准备完成”而自动升级到真实验证。

---

## 5｜当前关键对象与决策

### A0｜现有导览基线
`PENDING CAPTURE`

仍需要真实采集／确认，不能把缺失基线当成已完成。

### A1｜受控讲解
`KEEP AS CONTROL`

作为对照条件保留。

### B｜证据阅读
`KEEP`

继续作为核心验证路径。

### C1｜单坊深读
`KEEP / LOW-RISK SINGLE-OBJECT PATH`

适用于单对象、低风险的深读路径。

### C2｜多坊比较
`KEEP AS LEAD EXTENSION / EVIDENCE ASYMMETRY MUST REMAIN VISIBLE`

保留多对象比较，但不允许为了版式“看起来完整”而伪造对称证据。

---

## 6｜三牌坊证据边界

R04 进一步锁定：

- P1 / P2 / P3 必须独立处理；
- 官方记录中的通用名称 `广渡节孝牌坊` 不能在缺少正式对象映射时自动分配给其中某一座；
- P1 / P2 / P3 的图像证据当前并不对称；
- 缺失照片不能通过生成、误配或替换来“补齐”。

这类约束体现了 OLEANDER 的一个核心原则：

> **视觉完整性不能高于事实完整性。**

---

## 7｜Human–AI 协作在这里如何分工

### AI 适合承担
- 公开资料整理；
- 对象关系梳理；
- 方案比较；
- 原型结构；
- 测试材料准备；
- 证据冲突提示；
- 文档、图示与执行支持。

### Human 保留
- 文化解释权相关判断；
- 对象身份确认；
- 关键设计取舍；
- 是否进入现场／参与者验证；
- 最终专业判断与晋级决定。

## 9｜当前验证状态

- R03 workflow：`BROWSER DRY-RUN PASS / SMALL ADULT PHOTO PILOT READY`
- Reality Gate 2：`NOT RUN`
- Human Test：`NOT RUN`
- Evidence Level：`E2`

重要区分：

> **Workflow integrity PASS ≠ Human Test PASS**

浏览器 dry-run 只证明流程可以运行，不代表真实参与者验证已经发生。

## 10｜当前开放问题

- 真实现场观察尚未闭合；
- A0 现有导览基线仍需 capture；
- P1 / P2 / P3 对象映射仍需更强证据；
- 多对象比较的 evidence asymmetry 仍需保持可见；
- Human Test 尚未执行；
- Reality Gate 2 尚未执行。

因此当前项目仍保持：

> **RESEARCH + PROPOSAL / EVIDENCE REVIEW**

而不是进入已验证或已实施状态。

---

## 11｜如果你从产品经理视角阅读

这个案例最值得看的不是视觉风格，而是：

- 如何重新定义问题；
- 如何避免重复已有解决方案；
- 如何处理证据不完整；
- 如何把设计假设变成测试对象；
- 如何区分“流程能运行”和“真实用户验证通过”；
- 如何把 AI 放在研究、比较与执行层，而不是替代关键判断。
