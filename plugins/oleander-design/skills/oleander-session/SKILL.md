# OLEANDER Session

Treat this plugin as a **session entry and routing aid**, never a new OLEANDER authority or replacement for `oleander-design-process`. Run the user's current instruction first. Read [execution.md](references/execution.md) for the exact start, continuation, stop and readback procedure.

## Start or resume

1. Determine `PROJECT_MODE` or `TRAINING_MODE` separately from `EXPLORE / CANDIDATE / AUTHORITY`. Read the current Notion architecture and Project Control Plane, the exact project or decision object, current source and constraints, and GitHub `main` implementation. Existing connected Notion/GitHub tools may supply the reads; do not treat a plugin snapshot or Reader projection as Current. Verify which connectors and native execution surface are available.
2. If continuing, resolve the existing task's exact `task_id`, logical object ID, latest valid Execution Receipt and native artifact readback. Match authority fingerprint and source revision. Resume from its highest verified checkpoint. If none exists, reconstruct the smallest valid frontier from the canonical project state and actual artifact; do not claim an old chat summary is a checkpoint.
3. Resolve the existing `oleander-design-process` Skill and minimum domain extension from GitHub `main` or a verified installed version. Use candidate branch only when the task explicitly evaluates that candidate. Resolve the required native output, minimum owner set, review lenses and applicable professional/evidence ceiling.
4. Start useful, reversible design work immediately. Ask the human only for an unresolved decision or source that truly governs the next irreversible step. Continue independent work across unblocked branches.

## Design loop

Frame the decision; let the system propose materially different causal mechanisms under one stated comparison world. Include current/baseline or no new intervention when relevant, deduplicate cosmetic variants, construct editable native alternatives, attack them, run actual readback and show the trade-offs. For interface work, run real states; for space, respect measured versus inferred geometry; for products, inspect assembly/use/service. AI images are supplementary presentations only. Text remains editable or vector in design assets.

At a consequential choice, give the human select / modify / mix / reject / reopen with reasons. Record only **actual** human feedback in the existing Design Intelligence Packet / Decision Record / applicable receipt, preserve all parent branches, then make and read back the affected second-round native artifact. One selection is not a permanent preference. Design KEEP and professional or statutory PASS remain with the existing owners.

For coupled objects invoke the existing Cross-Disciplinary Integration route and propagate a material change to every dependent native representation. Close only when applicable reviews, readbacks and the existing Execution Receipt's full-flow completion criteria are met. CI, a generated image, a polished board, a connector write response, or this plugin's installation never prove design quality or full closure.

## Recovery and handoff

On tool unavailability or ambiguous authority, preserve the last verified object, identify the smallest blocked claim/side effect, report the exact missing capability and next checkable action. Never create a parallel Current, new project state, replacement receipt or new Skill merely to proceed. For the next chat, report `task_id`, object ID, authority/source revision, last actual native artifact and readback, current owner and claim ceiling, highest valid checkpoint, blockers, and next allowed action—referencing the existing carriers rather than making a plugin-owned state store.
