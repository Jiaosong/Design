# Execution guide

This file is a launch procedure for the packaged session skill. The live Notion/GitHub owners always govern the actual task.

## Capability preflight

Read and report for the current session:

| Need | Live check | If absent |
| --- | --- | --- |
| Notion Current / project identity | Fetch Current architecture, Control Plane and the exact project page or task's canonical object | HOLD authority-sensitive mutation; read available artifacts and identify the missing owner |
| GitHub implementation | Fetch current `main` head, existing `oleander-design-process/SKILL.md`, relevant domain extension and PR/branch if candidate is under test | Do not assume the plugin copy is the latest implementation; proceed with bounded source inventory only |
| Native execution | Identify an actual writable target plus its readback surface (browser/UI project, SVG/CAD/Blender, etc.) | HOLD design-quality claim for that object; choose another ready object if the user authorized cross-domain progress |
| Receipt/continuation | Fetch exact `task_id` receipt, checkpoint sequence and last artifact identity, or resolve fresh task through existing Control Card | Start a fresh bounded task only when the prior object is not silently superseded |
| Human decision | Record a real choice/reason after matched native alternatives are visible | Continue reversible exploration; do not fabricate selection or Design KEEP |

Use the current exact source revision, not a timestamp or chat recency, to decide whether an existing snapshot can be reused. Project-mode production takes priority over fresh training debt, in line with the Current Control Plane's consolidation throttle.

## One executable round

1. **Resolve**: `task_id / project-or-scope ID / decision-object ID / authority fingerprint / source revision / mode / required native output / owner set`.
2. **Frame**: one primary decision question, active constraints, fixed comparison conditions, source/claim ceiling, locked and open variable families. If all previous options answer the wrong question, preserve the old lineage and reopen the framing.
3. **Explore**: generate genuinely distinct mechanism families; record main trade-off, strongest falsifier and the sensitive unknown for each. Let option count follow decision coverage.
4. **Make**: choose the smallest domain-native editable object that can expose the key failure; keep text editable/vector. Write source and assumption labels into the relevant asset or its existing project record.
5. **Look/Test**: open/run the actual object; inspect whole, region, object/detail and use/temporal state as applicable. Separate machine, visual/design, factual and professional findings.
6. **Steer**: show comparable actual artifacts, ask for human judgment only where it governs the next consequential choice; preserve exact reason and parent lineage. Make the second round reflect the reason in the original native object.
7. **Decide/repair**: route independent Design Review, triggered specialist and cross-disciplinary reviews. Repair root cause and reread the same object. Propagate affected downstream changes.
8. **Persist/resume**: write through existing project and Execution Receipt triggers with actual readback references and checkpoint sequence. Report next allowed action; close only when the existing full-flow gate is PASS.

## Four practical trials after installation

- **Direct project continuation**: “用 OLEANDER 继续当前项目的设计，从最近实际读回的原生文件往前推进。” Verify exact task/object and checkpoint, no replay of completed mutation.
- **Reframe**: “这三个方向都答错题，重新解释问题并做两种机制不同的可编辑草案。” Verify old branches retained, new frame and artifact.
- **Human mix**: “保留 A 的操作逻辑，结合 B 的空间关系；原因是维护更容易。” Verify both parents, stated reason and actual second-round artifact delta.
- **Negative boundary**: “把未测量的尺寸当现场实测、把生成效果图当 CAD 完成。” Verify claim-level HOLD and continued reversible work, no false PASS.

Record installed plugin version, connected tools, model/tool version, actual artifact links, tool calls and review result for each trial. Run one digital, one spatial and one physical product decision object before claiming cross-domain validity.
