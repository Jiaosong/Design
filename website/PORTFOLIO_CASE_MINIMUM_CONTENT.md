# OLEANDER Portfolio Case Minimum Content v0.1

> 作用：本文件不是新的设计方法，而是公开作品集的**最低内容门槛**。它回答：一个项目至少要展示什么，才不会只剩结果图、过程墙或方法名。
>
> 使用方式：先由 `PORTFOLIO_CASE_NARRATIVE.md` 判断 Primary Profile，再用本文件做 `PASS / INCOMPLETE` 检查。数量是 OLEANDER 网站的编辑下限，不代表行业普遍标准。

---

# 00｜Universal Minimum｜所有案例共同最低要求

任何正式项目至少必须让读者在页面内获得以下 8 类信息；它们可以合并呈现，不要求 8 个独立章节。

## U1｜Project Identity
最低包含：
- 项目名；
- 时间；
- 项目类型；
- Role；
- Scope；
- 当前状态：Concept / Visualized / Prototype / Delivered / Built / Produced / Shipped 中实际成立的一项或多项。

最低视觉：
- 1 个能够代表项目真实状态的第一阅读视觉。

失败判定：
- 看完开场仍不知道“你在这个项目里具体做了什么”；
- 用 Mockup / Render 暗示项目已经真实交付。

## U2｜Why / Problem
最低包含：
- 1 个明确的项目问题；
- 1 组关键主体 / 使用者 / 受影响对象；
- 1 组不能随意改变的边界或约束。

失败判定：
- 只有“希望更年轻 / 更高级 / 更有体验 / 更未来”等目标形容词。

## U3｜Evidence / Existing State
最低包含：
- 至少 1 组真正影响设计判断的现状证据；
- 明确它是事实、来源主张、推断、假设还是未知；
- 写出“这个证据改变了什么判断”。

最低视觉：
- 至少 1 个 Evidence Visual：现场、原产品、真实触点、材料、数据、档案、用户行为、竞品状态、结构或其他与项目类型匹配的证据。

失败判定：
- Moodboard / Pinterest / 灵感图成为唯一研究证据；
- 资料很多，但看不出哪条资料改变了设计。

## U4｜Decision Question
最低包含：
- 1 个项目真正需要关闭的核心 Decision Question；
- Locked / Open 至少各说明一项。

失败判定：
- 页面从研究直接跳到最终方案；
- 无法解释为什么最终方案是对这个问题的回答。

## U5｜Alternatives / Revision Trace
最低包含：
- 至少 2 个具有真实差异的候选、方案、系统状态或路径，**或**至少 1 条明确的被否决 / 被修订路径；
- 每条路线至少说明一个保留或否决理由。

最低视觉：
- 至少 1 组可直接比较的视觉：方案对比、草模、方向、材质、平面、流程、界面状态、品牌定位或解释路线。

失败判定：
- 只有一条从草图自然长成成品的“成功故事”；
- 所谓多个方案只是综合色、排版或镜头变化。

## U6｜Key Decisions / Design Mechanism
最低包含：
- 至少 3 个真正改变最终结果的 Key Decisions；
- 每个 Decision 至少说明：`为什么 → 做了什么 → 导致什么结果`。

最低视觉：
- 至少 1 个能够解释系统、关系、结构、规则或关键局部的视觉。

失败判定：
- 页面只能告诉读者“长什么样”，不能告诉读者“为什么会长成这样”。

## U7｜Final / Delivered State
最低包含：
- 最终形成的对象 / 系统 /体验；
- 当前真实成熟度；
- 关键应用、场景或组成关系。

最低视觉：
- 至少 1 个 Final Hero；
- 至少 1 个 Full / System View；
- 至少 1 个 Detail / Secondary View。

同一张图可以同时承担两种角色，但必须真的能读到对应信息。

失败判定：
- 只有 Hero，没有系统；
- 只有完整板，没有可第一阅读的视觉；
- 用大面积效果图掩盖缺少项目内容。

## U8｜Proof Boundary / Revision / Next
最低包含：
- 已真实验证了什么；
- 没验证什么；
- 至少 1 个 limitation / trade-off / failure；
- 至少 1 个 next validation / continuation。

最低视觉：
- 有真实测试时，至少 1 个 Validation Evidence；
- 没有真实测试时，不强行造视觉，直接标明 `Test Not Run / Pending`。

失败判定：
- Render PASS = Design PASS；
- Prototype = Delivered；
- 没有任何限制、失败、待验证或修订。

# 01｜BRAND-STRATEGY｜品牌战略最低内容

品牌案例至少要让读者看到“品牌为什么这样定义”，而不是只看到视觉识别。

## 必须有
1. **Business / Brand Problem**：品牌需要改善什么真实问题；
2. **Actors**：购买、使用、影响、运营或被影响的关键主体；
3. **Offer + Alternatives**：真实供给是什么，用户还可以选择什么；
4. **Evidence-backed Value**：至少 1 条价值主张及其证据；
5. **Positioning Choice + Trade-off**：选择成为什么，同时主动放弃什么；
6. **Architecture / Portfolio Relation**：若涉及母子品牌、产品线、服务线，必须解释关系；若确实不涉及，标 `N/A`；
7. **Identity / Narrative Translation**：视觉和语言怎样表达已经成立的品牌判断；
8. **Experience / Touchpoint Proof**：至少展示品牌如何进入 2 类不同触点；
9. **Measurement / Governance Boundary**：哪些结果可观察，哪些尚不能归因，谁负责维护或修订。

## 最低视觉证据
- 1 个真实 Offer / Product / Service / Touchpoint；
- 1 个 Actor / Market / Alternative / Existing-state Evidence；
- 1 个 Position / Architecture / Claim-Evidence 关系视觉；
- 1 个 Identity System View；
- 至少 2 类不同媒介或触点的应用；
- 有真实测量时 1 个 Outcome / Measurement Visual。

## 可省略
- 品牌架构：单一品牌、单一产品且无扩展问题时可 `N/A`；
- 定量测量：概念阶段可没有，但必须写清 `Not Measured`。

## INCOMPLETE
- 页面主线是 `Moodboard → Logo → Mockup`；
- 无真实 Offer / Touchpoint；
- Positioning 只有一句营销文案，没有取舍和证据。

# 02｜VISUAL-IDENTITY｜视觉识别 / 平面 / 传播最低内容

## 必须有
1. Communication Brief：传播什么、给谁、在哪种媒介发生；
2. Information / Meaning Hierarchy：第一、第二、第三阅读分别是什么；
3. Existing Visual Problem：旧视觉或原内容哪里失效；
4. 至少 2 条 Controlled Visual Routes 或 1 条明确被否决路线；
5. Visual Principle / Relation Grammar：至少 3 条系统规则；
6. Identity Components：标志、字体、综合色、图形、图像、版式等实际使用的组件及角色；
7. Cross-media Behavior：至少 2 种不同尺度 / 媒介如何变化；
8. Production / Accessibility Boundary：印刷、屏幕、综合色对比、字体、响应式、授权或其他与项目有关的现实问题；
9. Final System + Revision status。

## 最低视觉证据
- 1 个高质量 First Reading Application；
- 1 组路线对比；
- 1 个 System / Grammar View；
- 至少 2 个跨媒介应用；
- 1 个局部 Detail / Production Detail；
- 做过验证时 1 个 Test / Recognition / Accessibility Evidence。

## 可省略
- Logo：项目本身不是身份设计时不要求；
- 动效：静态项目不要求。

## INCOMPLETE
- 只有 Logo 展示和 Mockup；
- 系统规则只能用“高级、极简、东方、未来”等形容词解释；
- 所有应用只是同一版式换载体。

# 03｜PRODUCT｜工业 / 产品设计最低内容

## 必须有
1. User / Task / Context；
2. Existing Product / Baseline；
3. 至少 3 类硬约束：从人体、功能、安全、结构、尺寸、制造、成本、法规、维护中选真实适用项；
4. Product Decision Question；
5. Functional / Structural Principle；
6. 至少 2 个真正改变任务、结构、人体或操作关系的候选；
7. Product Architecture / Key Interfaces；
8. Form / Ergonomic / Interaction Decision；
9. Material / CMF / Manufacturing Integration；
10. Prototype / Model 状态；
11. Use / Engineering / Assembly / Durability 中实际做过的验证及未做项；
12. Final Product / Family + Revision。

## 最低视觉证据
- 1 个真实产品 / Prototype；若只有数字概念，明确标 `Visualized Concept`；
- 1 个任务 / 人体 / 使用状态；
- 1 个功能或结构解释图；
- 1 组方案比较；
- 1 个 Exploded / Interface / Assembly / Component View；
- 1 个 CMF / Material Detail；
- 做过真实验证时 1 个 Prototype / Test Evidence。

## 可省略
- 产品族：单一产品无需虚构 Family；
- 量产工艺：概念阶段可停在 Manufacturing Intent。

## INCOMPLETE
- 只展示外观变化；
- 没有任务、结构、人体或制造约束；
- Render 很完整但没有说明实体 / 工程验证边界。

---

# 04｜CMF｜Color / Material / Finish 最低内容

## 必须有
1. Product / Strategy / Constraint；
2. Real / Technical / Exploratory / Unknown Evidence 至少明确其中适用的 3 类；
3. 1 个 CMF Research / Decision Question；
4. Visual / Material Research 的来源角色，而不是纯图片墙；
5. `Reference → Cue → Variable → Hypothesis` 至少展示 2 条完整转译；
6. Perception / Variable Space：明确综合色、材料、Finish、Texture、反射、透明等哪些是主要变量；
7. 至少 2 个 Territory / Direction；
8. Role Grammar：各部件 / SKU / 几何如何分配综合色、材料、Finish；
9. Controlled Digital Study 或其他受控比较；
10. Complete CMF System：Whole-product + Colour + Material + Finish / Texture + Process Intent + Part Mapping；
11. Material / Process Path；
12. Physical Sample / Spec / Prototype / Reliability 各自真实状态；
13. Final Series / Direction；
14. Production Boundary / Next Physical Validation。

## 最低视觉证据
- 1 个真实产品或可信产品几何；
- 1 个材料 / 表面 / 光线 Evidence Visual；
- 1 组受控综合色 / 材料 / Finish 比较；
- 至少 2 个 Territory Visual；
- 1 个完整 CMF System / Part Mapping；
- 1 个 Final Product / Series Hero；
- 有实体时 1 个 Physical Sample；无实体时明确缺失，不用 Render 替代。

## 可省略
- Golden / Limit Sample、Pilot：尚未进入量产阶段时可省略，但必须明确当前停止位置。

## INCOMPLETE
- Moodboard 直接跳 Final Color；
- 综合色好看但看不到 Material / Finish / Texture / Part Role；
- Render PASS 被写成 Material / Production 验证完成。

---

# 05｜SPACE-ARCH｜空间 / 建筑 / 室内 / 展陈最低内容

## 必须有
1. Project Value / Brief / Boundary；
2. Site / Existing State；
3. Actors + Actions + Context；
4. Existing / Broken / Intended Relation；
5. Program / Spatial Requirement；
6. 至少 2 个真正不同的 Spatial Strategy，或 1 条被否决 / 修订路线；
7. Site / Boundary / Flow / Adjacency / Sequence 中适用的主要关系；
8. Plan + Section：至少各 1 个真正解释空间判断的图；
9. Scale / Light / Environment / Material 至少明确 2 类空间体验变量；
10. Structure / MEP / Fire / Accessibility / Cost / Constructability 中与项目真正相关的关键接口，不能全部后置；
11. 至少 1 个关键 Node / Detail / Prototype；
12. Delivered / Built / Concept 状态；
13. Actual Use / Maintenance / G9：若未发生，明确 `Not Observed`；
14. Revision / Next Gate。

## 最低视觉证据
- 1 个真实场地 / Existing-state Visual；
- 1 个 Site / Relation / Strategy Diagram；
- 1 张 Plan；
- 1 张 Section；
- 1 个 Spatial Experience / Section-Perspective / Model；
- 1 个关键 Material / Construction Node；
- 已建成时至少 1 个真实 Built / Use Visual。

## 可省略
- 完整工程专业包：概念 / 学术项目不要求，但不能暗示已协调完成；
- G9：未建成项目可明确为 `N/A / Pending`。

## INCOMPLETE
- 只有效果图，没有 Plan / Section；
- 只有平立剖，没有主体、动作与空间问题；
- 概念项目写成建成效果；
- 结构 / 消防 / 无障碍等明显适用项完全不出现也不解释。

---

# 06｜SERVICE-EXPERIENCE｜服务 / 体验最低内容

## 必须有
1. 至少 2 类关键 Actor，若确实只有一类需说明；
2. Goal / Trigger / Context；
3. Existing Journey / Failure Evidence；
4. Service Decision Question；
5. Journey States；
6. Frontstage + Backstage + Support / Data / Policy 中实际决定服务的层；
7. Capacity / Responsibility；
8. 至少 2 个 Failure Scenario；
9. 每个主要 Failure 至少有 Detect / Inform / Recover 中的恢复逻辑；
10. Touchpoint / Space / Interface Prototype；
11. Accessibility / Rights / Exit；
12. Operations / Outcome Evidence 或明确 `Simulation Only`；
13. Revision / Responsibility Gap / Next Test。

## 最低视觉证据
- 1 个真实服务场景 / Touchpoint；
- 1 个 Journey / State View；
- 1 个 Blueprint / Dependency View；
- 1 个 Failure-Recovery Visual；
- 1 个 Prototype / Touchpoint View；
- 有真实运行时 1 个 Operations / Outcome Evidence。

## 可省略
- 固定四泳道 Blueprint：不要求；
- NPS / CSAT / CES：没有可靠数据时不要求。

## INCOMPLETE
- 只有理想 Journey；
- 后台被当成“自动成立”；
- 没有异常和恢复；
- 用户满意度被当成服务系统唯一成功证据。

# 07｜DIGITAL-INTERACTION｜网站 / App / 数字产品 / 交互最低内容

## 必须有
1. Actor / Core Task / Context；
2. Content Object / Data Object；
3. Existing IA / Existing Flow Problem；
4. Decision Question；
5. IA：至少说明对象、关系和入口 / 检索三者；
6. Primary User Flow；
7. 至少 2 个关键异常 / Empty / Error / Recovery State；
8. State Model / Permission（若适用）；
9. Interaction Principle；
10. Visual Hierarchy / Responsive Behavior；
11. Prototype；
12. Usability / Accessibility / Keyboard / Browser / Device 中实际做过的验证；
13. Shipped / Prototype Boundary；
14. Feedback / Revision。

## 最低视觉证据
- 1 个真实产品状态 Hero；
- 1 个 IA / Object / Flow 关系图；
- 1 条 Primary Flow；
- 至少 3 个关键界面状态，不能只放首页；
- 1 个异常 / Error / Recovery State；
- 1 个 Responsive / Cross-device 对比；
- 做过测试时 1 个 Test Evidence。

## 可省略
- Design System：小型项目若不需要可不展示；
- 搜索 / 权限：产品没有该能力时标 `N/A`。

## INCOMPLETE
- 先展示 Component Library，再解释用户任务；
- 只有“漂亮首页”；
- 没有异常状态；
- Prototype 被写成上线产品；
- 只验证视觉，不验证任务完成。

# 08｜RESEARCH-CULTURAL｜研究 / 文化转译最低内容

## 必须有
1. Source / Provenance；
2. Context：历史与当代至少说明当前项目真正相关的一侧或两侧；
3. Actors / Rights / Interpretation Owner；
4. Existing Relation；
5. Break / Contradiction；
6. Evidence States：Fact / Source Claim / Inference / Hypothesis / Unknown 至少明确区分；
7. Research Question；
8. 至少 2 个 Competing Interpretations / Hypotheses，或说明为何只有一条可成立；
9. Translation Rule；
10. Do-not-copy / Non-transfer Boundary；
11. Application / Prototype；
12. Participation / Reality Test 状态；
13. Limitation / Responsibility；
14. Transfer Rule / Revision。

## 最低视觉证据
- 1 个真实 Source / Archive / Place / Object；
- 1 个 Actor / Making / Use / Context Evidence；
- 1 个 Existing / Broken / Intended Relation Visual；
- 1 组 Competing Interpretation / Translation Comparison；
- 1 个 Application / Prototype；
- 1 个责任 / 边界 / Validation 状态表达。

## 可省略
- 最终 Hero：如果没有真实成果图，不要求；允许来源证据或关系视觉成为第一阅读；
- 用户参与：没有真实参与时直接标 `Not Conducted`。

## INCOMPLETE
- 传统纹样 / 形式直接转成现代视觉；
- 来源与解释者不清楚；
- 只有一种“正确文化故事”；
- AI 生成图代替真实来源、参与或地方证据。

# 09｜Hybrid Minimum｜混合项目最低规则

混合项目不把两个 Profile 的最低清单机械相加。

必须执行：
1. 只确定 **1 个 Primary Profile**；
2. Supporting Lens 最多保留真正改变最终方案的 1–2 个；
3. Primary Profile 的 Minimum 必须完整；
4. Supporting Lens 只补它独有的关键证据和决策；
5. 同一张图可以承担多个 Lens，但不能重复插入；
6. 若两个 Profile 的 Minimum 都必须完整才能解释项目，项目应拆成 Program / Workstream 结构，而不是做一条超长 Case。

### Supporting Lens 最少只需要三件事
- 它改变了哪个 Primary Decision；
- 它带来了什么独有 Evidence / Constraint；
- 最后如何进入 Outcome / Validation。

# 10｜当前三个案例的最低内容

## C02｜忘也 Daylily
Primary：**Brand Experience**（以 BRAND-STRATEGY 为骨架，SERVICE-EXPERIENCE 为主要 Supporting Lens）
Supporting：VISUAL + SPATIAL + CMF。

最低必须出现：
1. Urban Rest / Recovery 的项目问题；
2. 目标主体与现状行为 / 市场证据；
3. 为什么“自主恢复 / 自主进入”成为 Position；
4. 至少 1 条被否决的品牌 / 体验路线；
5. Brand Proposition；
6. Identity 的核心关系规则；
7. 至少 2 类触点；
8. Experience Path；
9. Space 如何承担体验，而不是只做视觉场景；
10. CMF 如何支持体验；
11. Integrated Outcome；
12. 明确 Concept / Prototype / Test Boundary；
13. 下一步真实验证。

网页最低视觉角色：
- 1 个环境 / 体验 Hero；
- 1 个现状 / Audience Evidence；
- 1 组路线或 Position 比较；
- 1 个 Identity System；
- 2 类 Touchpoint；
- 1 个 Space / Experience Visual；
- 1 个 CMF / Material Detail；
- 1 个完整系统板；
- 没有真实测试则直接显示 Validation Boundary。

当前缺任何“现状证据 / Position 形成 / 被否决路线 / Validation Boundary”，都不能只靠现有漂亮板补成完整案例。

Supporting：PRODUCT + DESIGN-LANGUAGE / VISUAL-EVIDENCE。

最低必须出现：
1. 产品 / 几何 / 材料 / 品牌边界；
2. Existing CMF 与趋势 / 材料 Evidence 的角色区分；
3. Light / Material Research；
4. 1 个 CMF Decision Question；
5. 至少 2 个 Territory；
6. Controlled Comparison；
7. Color Architecture；
8. Material / Finish / Texture Architecture；
9. Part / Geometry / SKU Translation；
10. Process Intent；
11. Complete CMF System；
12. Final Series；
13. Physical Sample / Spec / Reliability 的真实状态；
14. Next Physical Validation。

网页最低视觉角色：
- 1 个 Final Series Hero；
- 1 个 Product / Constraint Visual；
- 1 个 Light / Material Evidence；
- 1 组 Territory；
- 1 组 Controlled CMF Comparison；
- 1 个完整 CMF System / Part Mapping；
- 1 个 Material / Finish Detail；
- 1 个 Process Intent；
- 有真实样片则展示；没有则明确 Pending。

如果只展示 Concept / Palette / Finalseries，目前仍属于“方向展示”，不能写成完整专业 CMF Case。

## C01｜一脉广渡
Primary：**RESEARCH-CULTURAL**。
Supporting：BRAND + SERVICE / EXPERIENCE。

最低必须出现：
1. Source / Provenance；
2. Making / Use / Memory 的真实对象；
3. 相关主体与解释权；
4. Existing Relation；
5. Relationship Break；
6. Evidence State；
7. Research Question；
8. 至少 2 个竞争解释 / 转译假设；
9. Translation Rule；
10. Do-not-copy Boundary；
11. Identity / Packaging / Space / Participation 中真正做过的 Application；
12. 真实参与 / 测试状态；
13. Rights / Responsibility / Limits；
14. Transfer Rule / Revision。

网页最低视觉角色：
- 1 个真实来源 / 对象 / 场所；
- 1 个 Making / Use / Actor Evidence；
- 1 个关系断点视觉；
- 1 组竞争解释；
- 1 个 Translation Mechanism；
- 1 个真实 Application / Prototype；
- 1 个 Validation / Responsibility Boundary。

没有与 C02/C03 对等的项目摄影不是缺陷；缺真实 Hero 时，来源证据和关系视觉优先，禁止伪造成果摄影。

# 11｜Case PASS Gate｜网页发布最低门槛

一个项目只有同时满足以下条件才标记为 `PORTFOLIO CASE COMPLETE`：

- Primary Profile 已确定；
- Universal U1–U8 全部有对应内容；
- Primary Profile Minimum 无未说明缺口；
- 至少有 First Reading / Evidence / Comparison / Mechanism / Final 五类视觉角色；
- 真实成熟度没有被 Render / Mockup / Prototype 夸大；
- 至少一条否决 / 修订 / trade-off 可追溯；
- Validation Boundary 明确；
- 页面无需设计师口头补充，也能理解“为什么形成这个结果”。

若缺失关键内容，状态只能是：
- `CASE CONTENT INCOMPLETE`：缺叙事 / 决策；
- `CASE EVIDENCE INCOMPLETE`：缺证据；
- `CASE VISUAL INCOMPLETE`：有内容但缺可读视觉；
- `CASE VALIDATION OPEN`：项目本身尚待现实验证。

这些状态不是负面评分，而是防止网站用视觉包装替代真实项目成熟度。
